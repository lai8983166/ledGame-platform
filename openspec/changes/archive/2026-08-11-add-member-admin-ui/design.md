## Context

`apps/member-admin` 当前是一个只有标题与说明文字的 Vue 3/Vite 占位页，没有既有页面结构、路由体系或业务组件。本 change 要在不接入服务端、支付、硬件和外部上传能力的前提下，建立可完整演示和后续接线的管理端 UI。

主要使用者是门店管理员。其高频任务是快速判断房间是否可用、查找会员并执行常用操作、核对当日记录；设置类操作频率较低。因此 UI 必须先呈现状态和操作结果，再按需展开细节，避免把所有功能平铺在同一页面。

## Goals / Non-Goals

**Goals:**

- 建立清晰且稳定的管理端信息架构，一级导航不超过六项。
- 让房间状态、关键统计和会员常用操作在少量点击内完成。
- 以统一的本地模拟状态覆盖列表、详情、表单、确认、筛选、开关和反馈等 UI 行为。
- 建立明亮液态玻璃拟态的设计语言，同时保证文字对比度、状态可辨识度和表格可读性。
- 为未来替换成真实 API、WebSocket、硬件事件和上传任务保留明确的数据边界。

**Non-Goals:**

- 不实现数据持久化、身份认证、权限管理或真实会员 CRUD。
- 不处理真实充值、支付安全或资金流水。
- 不连接 IC 手环、游戏设备、电视、邮箱或服务器。
- 不实现真实实时推送、离线同步、邮件发送、文件上传或素材管理。
- 不新增与需求无关的营销、排班、库存、门店或权限模块。

## Decisions

### 1. 使用六个一级入口组织全部功能

侧边导航固定为“总览、房间、会员、记录、排行、系统设置”。记录页内部使用“发卡记录、游玩记录、交易记录、会员数据、游戏数据”标签；系统设置内部使用“基础设置、功能开关、数据上传”分区。

这样可以让高频业务直接可达，同时将低频、同类内容收进二级层级。备选方案是为每类记录和数据上传建立一级入口，但会产生过长导航并削弱任务聚焦。

### 2. 使用单页壳层与按功能拆分的 Vue 组件

应用保留统一的侧边导航、顶部状态栏和内容画布，各页面拆成独立视图；抽取 `GlassCard`、状态徽标、数据表格、筛选栏、空状态、模态框、抽屉、Toast 等可复用展示组件。导航可由轻量前端状态或现有依赖允许时的路由实现，不为本次 UI 演示引入服务端路由。

备选方案是把所有内容堆叠在一个超长组件中，但会使状态耦合、响应式布局和后续接 API 都更难维护。

### 3. 明确区分持久展示数据与断电丢失的临时数据

前端模拟数据分为 `members`、`records`、`games`、`settings` 等业务展示集合，以及 `roomLiveState`、`scores`、`rankings`、`hardwareState` 等临时实时集合。临时数据区域显示“实时临时数据 · 断电不保存”提示，避免管理员误以为已留档。

所有编辑操作只更新当前页面内存或给出模拟成功反馈，刷新页面可重置。备选方案是写入 `localStorage`，但会模糊“仅 UI”和“断电不保存”的边界，因此本 change 不采用。

### 4. 用统一交互模式降低操作成本

- 列表顶部统一使用搜索、状态/时间筛选与主要操作按钮。
- 查看详情使用右侧抽屉，新增/编辑/充值使用聚焦模态框，删除使用危险确认框。
- 表单就地显示必填、格式和数值范围错误；成功或失败结果使用 Toast，并保持当前上下文。
- 房间卡片首先突出状态与剩余时间，展开后再显示玩家积分、排名、游戏阶段和硬件状态。
- 手环有效时长设置旁固定显示规则说明：“自助系统激活后可见；首次在游戏系统刷卡后开始计时，未开始游戏不生效”。

备选方案是将所有操作跳转到独立页面，但会增加返回和重新定位成本，不符合门店快速操作场景。

### 5. 采用克制的明亮液态玻璃视觉系统

背景使用低饱和蓝青至淡紫的柔和渐变与少量模糊色斑；内容层使用半透明白色、细描边、柔和内高光和轻阴影形成玻璃层次。强调色以蓝青为主，紫色仅用于排行和关键高光；成功、警告、危险状态保持语义色，不单独依靠颜色传达。

玻璃效果仅用于导航、卡片、弹层和工具栏，表格主体保持更高不透明度以保证密集信息可读。避免重霓虹、深色赛博风、过量装饰图形和无意义动画。

### 6. 响应式以桌面管理场景为主，窄屏可完成全部任务

在宽屏中使用固定侧栏、统计卡网格、房间卡网格和数据表；中等宽度收窄侧栏并减少网格列数；窄屏将导航折叠为抽屉，表格转为横向滚动或信息卡，表单与弹窗使用接近全屏布局。

交互控件保留清晰的悬停、聚焦、禁用和选中状态，正文及关键状态满足可读对比，尊重“减少动态效果”偏好。

### 7. 为未来真实集成保留替换边界

页面组件只消费定义清楚的视图模型和动作函数。未来可分别将房间临时状态替换为实时连接，将会员和记录替换为 API 查询，将上传测试替换为异步任务，而无需重做页面层级。

副屏排行在本次仅提供页面预览/展示模式和榜单周期切换；不尝试发现或配对真实电视设备。

## Risks / Trade-offs

- [模拟交互可能被误解为真实业务成功] → 在充值、上传、硬件及副屏区域使用“演示数据/仅 UI”提示，反馈文案明确为模拟结果。
- [玻璃拟态降低文字和表格对比度] → 玻璃只用于容器层，数据区域提高背景不透明度，并对正文、边框和焦点环设定最低对比。
- [单 change 覆盖页面较多，组件易膨胀] → 按功能视图和通用组件拆分，先建立壳层与 token，再逐页实现和验收。
- [“实时”数据没有真实数据源] → 使用可预测的本地样例和有限状态切换，不构造虚假的持续网络活动。
- [游戏数据字段信息密集] → 列表仅展示关键摘要，其余关卡、规则、素材路径和组件信息放入详情抽屉分组呈现。
