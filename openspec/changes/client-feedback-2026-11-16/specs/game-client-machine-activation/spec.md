# Spec Delta

## Purpose

让游戏端永久机器授权在同一 Windows 用户环境中跨重新打包、安装目录移动及多个独立游戏包持续有效；兼容旧授权文件的安全迁移，并保持可信签名、本机匹配和未激活业务门禁。

## ADDED Requirements

### Requirement: 本机有效授权跨发行包持久化

正式游戏端 SHALL 使用不依赖包目录的固定本机授权目录，同一 Windows 用户下的多个游戏包及新解压包 SHALL 复用有效机器授权。机器码 SHALL 继续由真实 Windows 机器身份派生；游戏数据库及配置 SHALL 仍按包独立，授权不得随数据库恢复或 ZIP 分发。

#### Scenario: 同机重新打包或新目录解压
- **WHEN** 本机已有有效游戏端授权，用户重新打包、移动目录或在新目录解压新包
- **THEN** 自动校验并继续启动，无需重新输入激活码，独立数据库和配置不合并

#### Scenario: 复制到其它机器
- **WHEN** 相同包和授权文件被复制到机器身份不同的电脑
- **THEN** 原授权不能激活该电脑，业务门禁仍生效

### Requirement: 旧授权仅在验证后迁移

固定目录尚无有效授权时，系统 SHALL 尝试已知旧目录中的授权，先验证可信签名、游戏产品及本机身份，再原子持久化到固定目录。有效固定授权 SHALL 优先；损坏、异机或不可信旧文件 SHALL 不覆盖有效授权。迁移保存失败 SHALL 明确报错且不误报激活成功，旧文件保持完整。

#### Scenario: 旧包授权自动迁移
- **WHEN** 旧包内有本机有效授权且固定目录尚未建立授权
- **THEN** 验证成功并持久化后继续启动，后续只需固定目录即可保持激活

#### Scenario: 无效或不可保存的旧授权
- **WHEN** 旧文件被篡改、机器不符，或固定目录不能写入
- **THEN** 不产生虚假激活状态，不删除旧文件，并保留明确失败原因

### Requirement: 自动化授权目录保持隔离

显式隔离用户目录的自动化启动 SHALL 使用隔离授权目录且不读取或改写正式本机授权。测试 SHALL 不增加免激活模式、不更换正式信任公钥、不携带签发私钥。

#### Scenario: 隔离保护验收
- **WHEN** 验收指定独立用户数据目录且该目录没有有效授权
- **THEN** 仍显示未激活并拒绝业务请求，不因开发机已有授权而绕过测试门禁
