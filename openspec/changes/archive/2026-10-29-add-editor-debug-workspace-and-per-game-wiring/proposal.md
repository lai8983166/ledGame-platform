# Proposal

## Why

编辑器启动测试仍会弹出 DebugPanel 和 Touch 两个窗口，设置、观察与模拟踩踏分散，无法在编辑上下文中方便暂停和重试。地砖布线由全局 SDK 文件控制，不能随当前游戏独立保存和切换，需要把调试入口与逐游戏布线整合进现有编辑器。

## What Changes

- Simple、Normal、Diffcult、Rank 编辑器的“启动游戏”统一进入主窗口内的专用调试页面，不再为该入口打开 DebugPanel/Touch 窗口；左上角退出后返回原编辑界面。
- 左侧选择直接启动/真实手环启动、人数和起始关卡，提供启动、暂停/继续、重新开始、结束，以及状态、得分、生命值、累计积分和全局剩余时间；Rank 展示各玩家颜色和分数。
- 右侧复用现有 DebugLedCanvas、RGB 帧通道和模拟踩踏输入，保持正方形地砖、按视口高度完整显示、真实玩法逻辑和可选 SDK 输出。
- 增加后端真实的调试暂停/继续能力，冻结玩法进度、游戏/关卡时钟和相关效果计时；重新开始走正常终止与新会话启动，不篡改旧会话。
- 每个游戏编辑器增加布线工具入口，复用现有绘制/通道/校验逻辑；游戏独立持久化配置，启动时应用到 RGB 输出和踩踏输入映射，不能只保存 UI 草稿。
- 保留旧全局 wiring.json 作为尚未明确保存游戏布线时的兼容回退；独立布线不覆盖全局文件、其他游戏或符号灯布局。新增配置随游戏导入导出。
- 不改正常顾客 Touch 流程、排队、积分规则、会员管理端功能或 SDK 协议；现有手环调试仍执行真实会员准入与结算，不虚构手环 ID。

## Capabilities

### New Capabilities

- `editor-debug-workspace`: 编辑器内单页调试入口、设置、状态观察、RGB 交互与返回编辑上下文。
- `game-debug-playback-control`: 调试会话的暂停、继续、重新开始、退出及异步生命周期安全。
- `per-game-floor-wiring`: 逐游戏布线编辑、持久化、旧数据兼容和实际运行时映射切换。

### Modified Capabilities

无。现有主规范中的会员准入/结算能力直接复用，不在本 Change 改写手环计费规则。

## Impact

- 游戏前端 `F:/project/ledGame`：App 主窗口切换、两类编辑器、调试页面、DebugLedCanvas、布线组件、Electron IPC、既有语言文案与自动化测试。
- 游戏后端 `F:/project/ledGame-backend`：调试控制/运行状态接口、GameEngine 与玩法计时、编辑文档和游戏布线 JSON、FloorGameHardware/ELC408 运行时准备、导入导出及测试。
- `F:/project/ledGame-platform` 存放 Change、验证文档和隔离联调测试；补正烤机模拟采集器对现有 16×36 待机帧的分类，不放宽运行帧校验。会员管理端和自助注册端产品代码不改。
- 不新增第二套玩法引擎、硬件插件框架、调试数据库、通用页面路由框架或新的独立桌面窗口。
