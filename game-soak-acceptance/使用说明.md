# 游戏端烤机工具

本工具只启动游戏端打包应用及它自带后端，不需要会员管理端、自助注册端或激活签发工具。测试使用游戏模式、触屏启动，脚本点击真实按钮，等待游戏自然结束后进入下一局。崩溃不会自动重启，避免掩盖故障。

## 现场推荐用法

1. 解压游戏端和本工具。测试期间不要同时手动运行待测游戏端。
2. 双击 `烤机测试.cmd`。
3. 输入游戏端 exe 路径。
   启动前请先关闭正在运行的游戏端，让向导能够安全复制本机当前游戏数据库；原数据库不会被修改。
4. 选择硬件模式：
   - `1`：无硬件模拟，只验证游戏流程和程序稳定性；
   - `2`：真实地砖。工具会自动读取游戏端 exe 同级的 `elc408\conf.json` 和 `elc408\wiring.json`，并从 wiring 配置推断地砖尺寸，不需要手工填写目录或宽高。
5. 工具读取游戏端中的真实游戏列表，所有游戏默认未选。输入编号切换选择，例如 `1,3`；可多次输入，完成后输入 `done`。至少选择一个游戏才能继续。
6. 选择测试档位：快速 5 分钟、标准 30 分钟或正式 18 小时。
7. 确认摘要后输入 `yes` 开始。工具会自动完成预检、创建隔离运行目录并在结束后打印报告路径。

列表中的无限时长、时长无法确定、地砖尺寸不匹配或配置无效的游戏会显示原因并禁止选择。工具使用真实游戏 ID，不根据游戏名称生成或替换 ID。

真实地砖模式要求游戏端目录保持以下结构：

```text
LED Game.exe
elc408\conf.json
elc408\wiring.json
```

工具会在本轮运行目录中复制并校验这两个文件，原始 `elc408` 文件不会被修改。

向导会优先发现本机当前游戏数据库（通常位于 `%APPDATA%\led-game\database\runtime\ledgame.mv.db`），因此你在游戏端编辑器中保存的游戏时长和游戏列表会被读取。找不到本机数据库时才使用打包包内的初始数据库；如果数据库仍被游戏端占用，向导会要求先关闭游戏端。

工具自带 Node 和自动化依赖，不需要安装开发环境。测试期间不要修改游戏配置、手动结束游戏或关闭窗口；真实踩踏可以参与游戏。按 Ctrl+C 提前结束时，本轮会保留现场并标记为“未完成”。

## 报告和数据

每次运行都会在工具目录的 `runs` 下创建新的运行目录，并保存 `plan.json`、`rounds.jsonl`、`samples.jsonl`、`result.json` 和 `测试报告.md`。报告会列出本轮已选择和未选择的游戏、程序可用性、内存趋势及 SDK 通信统计；真实硬件模式还会每 10 秒搜索一次控制器，并给出有效回复的平均响应延迟（只保留累计值和样本数，不保存逐次时间戳）。

本轮目录超过 512MB 或 10,000 项、输出盘空闲不足 100MB 时会停止并保留现场。模拟模式不能证明真实控制器通信或地砖响应通过；真实模式也不会伪造协议不支持的 ACK 或丢包率。

## 开发排错入口

向导不是唯一入口，开发人员仍可使用：

```text
soak.cmd inspect config.json
soak.cmd run config.json
soak.cmd list http://127.0.0.1:37680
soak.cmd preflight http://127.0.0.1:37680 config.json
```

这些命令需要手工准备 JSON，适合固定夹具和问题复现，不是现场首选流程。
