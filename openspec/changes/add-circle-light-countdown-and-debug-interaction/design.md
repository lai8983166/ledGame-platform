# Design

## Context

动机见 proposal。已有布局快照、虚拟外围输出、Simple 运行时与 sessionId 隔离的 debug command。旧源码见 `docs/旧版符号灯运行逻辑分析.md`；旧 UDP 输出会替换对应端口的颜色数据，方形符号灯不是普通 RGB 颜色。新 SDK 物理外围映射及圆灯输入尚未确认。

## Goals / Non-Goals

**Goals:** 通用玩法持有圆灯业务，后端为唯一计时与生命权威；调试页面按已保存布局显示并模拟点击。复用既有媒体提示、会话和状态通道。

**Non-Goals:** 不向通用游戏引擎添加外围硬件依赖，不引入新定时线程、输入框架、表或依赖；不改变普通地砖、Rank、会员积分与物理输出协议。

## Decisions

- 在 SimpleGameHandler 内持有独立、可测试的圆灯倒计时状态，每关读取已解析的配置。RuntimeLevel 增加可选配置并保留原构造重载；旧字段不启用时原行为不变。
- 时间推进复用 RUNNING 帧节奏和可暂停的 playbackNow，不用 setInterval 或墙钟后台扣生命。首次运行后满 1 秒再减数，避免旧版最小值 1 立即受伤的偶然行为。初始数值在配置区间分散后打乱；按蓝灯设最大值加 1，下一秒恢复蓝色最大值；超时黄色保持约两秒后恢复。只按启用的生命限制扣生命，不减游戏/会员积分；同时多个灯超时各处理一次。
- 结束关卡、退出或重启清空；换关/重试重新初始化。按压命令只允许当前 RUNNING 的调试会话，校验链路序号、范围、布局、玩法；按绿/黄灯不改变状态，不新增颜色接触抽象。
- 状态快照附带按墙位置、链路序号排列的灯状态、剩余数字和颜色，复用现有引擎状态推送。前端不能自行扣生命或重置倒计时。
- 编辑器基础信息增每关倒计时开关、最小/最大秒数，开启时严格校验 `1 <= min <= max <= 99`。布局启用决定调试灯位展示，玩法开关决定是否倒计时；新配置默认关闭，旧已配置倒计时继续生效。
- 调试外围展示用现有布局几何辅助，不修改 DebugLedCanvas 的地砖点击逻辑；方形灯只显示，圆灯为带可访问名称的按钮。按墙位置匹配权威序号，不能假定 rows 索引等于链路索引。无运行游戏时按保存布局显示黑色灯，运行采用冻结布局快照，不随编辑草稿变化。
- 物理输出仍经过已有虚拟外围 sink，保持与地砖字节流隔离。记录已找到的旧输出证据和缺失的输入/新 SDK 映射，不把模拟测试计为硬件验收。

## Risks / Trade-offs

- [启动/暂停或结算仍扣时] → 首次 RUNNING 开始计时，暂停时钟冻结，结束清空，补生命周期测试。
- [灯序与墙位置错配] → 使用冻结布局提供的 wall/index/sequenceIndex，测试逆向、不同起点和多墙。
- [生命业务影响普通地砖或积分] → 独立外围超时入口，仅扣启用的生命值，覆盖分数不变和原红地砖回归。
- [无设备无法保证真实通信] → 明确暂不接入，模拟测试只验业务/布局，不伪造硬件成功。

## Migration Plan

无数据库迁移。升级应用后已有关闭的外围配置不产生新的生命消耗；保存开启配置才启用。回滚只更换游戏程序，既有 JSON 字段保留。
