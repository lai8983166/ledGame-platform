## Context

现有 `game-soak-acceptance` 已经提供 `inspect`、`preflight` 和 `run` 三个底层入口，并通过 JSON 配置指定游戏 ID。它们适合开发排错，但现场操作者需要先读取列表、手工复制真实 ID，再编辑配置，容易选错或漏填。本 Change 只调整平台工具的操作入口，不改变现有烤机引擎和真实通信判定。

## Goals / Non-Goals

**Goals:**

- 提供一个向导式入口，把发现游戏、选择游戏、固定档位和运行串成一条流程。
- 从实际游戏目录读取真实游戏项；所有游戏默认未选，支持多选并在确认前校验。
- 保留底层命令以便开发人员定位问题，并让向导生成的配置和运行证据与现有 runner 完全兼容。
- 让便携工具无需 Node/pnpm/源码环境即可运行。

**Non-Goals:**

- 不修改游戏端数据库、游戏配置或游戏内容。
- 不修改游戏循环、自然结束、内存监测、SDK 通信指标或报告的硬件验收边界。
- 不把向导改造成常驻桌面应用，也不自动重启崩溃的游戏进程。

## Decisions

### 1. 使用便携命令行向导，不新增桌面应用

在现有 `soak.cmd` 旁增加交互式入口（可通过子命令或单独 `.cmd` 启动），复用当前 Node 运行时、Playwright 和 runner。这样不引入新的 Electron 构建链，也能保留双击启动和命令行自动化。相比单独做 Electron 向导，命令行更容易在测试机上携带、升级和审计。

### 2. 游戏列表使用真实目录读取，选择结果转成现有 `games` 配置

向导先使用现有只读 catalog 读取逻辑，显示真实 ID、名称、时长和约束；交互结束后只把已选项转换为 `games` 数组，再调用现有 `buildPlan`。不通过名称匹配或创建 ID，避免游戏改名后误选。

### 3. 默认全不选，使用显式确认

所有有效项和禁用项初始均为未选中。用户可以输入编号批量切换，再输入确认命令继续；空选择直接拒绝。默认不选虽然多一次点击，但能避免新增测试游戏、隐藏测试游戏或无限时长游戏被意外纳入长时间测试。

### 4. 固定档位由向导映射为现有配置

向导提供少量固定档位（快速、标准、正式 18 小时），将选择转换为 `durationHours`，并可单独选择 `simulated` 或 `real`。底层仍允许开发人员直接传 JSON 做特殊短测，但现场向导不暴露任意时长和隐含默认值。

### 5. 一次运行生成隔离目录和选择快照

向导自动生成 `runId`、输出目录和配置快照，并把 catalog 全量、已选项、未选项、档位和预检结果写入本轮证据。运行失败或中止时沿用现有保留现场策略，不覆盖旧结果。

## Risks / Trade-offs

- [游戏列表过长] → 使用编号分页或滚动显示，并显示当前选中数；底层计划仍保存完整选择结果。
- [游戏目录在运行前发生变化] → 预检继续使用内容指纹和现有计划校验，变化时拒绝启动。
- [操作者误选真实硬件模式] → 在确认页明确显示模式、地砖尺寸和配置目录，并要求再次确认；模拟结果继续标记为未验证。
- [现场仍需要底层排错] → 保留 `inspect`、`preflight`、`run` 和原始 JSON 入口，不把诊断能力删除。

## Migration Plan

1. 扩展便携工具入口和交互测试，不改变旧 JSON 配置格式。
2. 重新生成 `release/game-soak`，现场可直接使用新的向导入口。
3. 旧脚本和已有配置继续可用；如向导出现问题，可回退到旧命令执行。
