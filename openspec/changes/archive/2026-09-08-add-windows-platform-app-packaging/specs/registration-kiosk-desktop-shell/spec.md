## ADDED Requirements

### Requirement: 自助注册端采用正式双窗口生命周期
自助注册端 SHALL 由同一个 Electron 主进程管理运维启动窗口和顾客流程窗口，并在开发模式、自动化测试和打包模式使用相同的窗口创建、隐藏、恢复和关闭规则。

#### Scenario: 应用首次启动
- **WHEN** 自助注册端启动
- **THEN** 只显示面向店员的运维启动窗口
- **AND** 不自动把未验证的连接配置暴露给顾客流程

#### Scenario: 开发模式启动顾客窗口
- **WHEN** 开发人员通过正式开发命令启动 Electron 并在运维页确认有效连接
- **THEN** 主进程创建与发布模式同类型的独立顾客窗口
- **AND** 开发模式只将页面来源切换为 Vite 开发服务器，不替换窗口或 IPC 实现

### Requirement: 运维窗口管理运行时连接配置
运维窗口 SHALL 允许店员填写、校验、测试和保存会员管理端 host 与 port，并显示连接状态和稳定错误；交付运行不得依赖重新编译 `VITE_PLATFORM_BASE_URL`。

#### Scenario: 测试并保存成功连接
- **WHEN** 店员输入合法 host 与 port 并点击测试连接
- **THEN** Electron 主进程在有限超时内请求目标会员管理端健康接口
- **AND** 只有响应满足健康契约时才允许保存并启动顾客窗口

#### Scenario: 连接测试失败
- **WHEN** 目标不可达、超时、拒绝连接或返回非健康响应
- **THEN** 运维窗口保留可编辑配置并显示区分明确的失败状态
- **AND** 不创建顾客窗口、不清空上一次合法配置

#### Scenario: 应用重启读取配置
- **WHEN** 店员曾保存有效 host 与 port 后重新启动自助注册端
- **THEN** 运维窗口显示已保存配置
- **AND** 店员仍须确认连接或启用后续明确设计的自动启动策略，本 Change 不静默绕过连接检查

### Requirement: 顾客窗口不具备运维配置权限
顾客窗口 SHALL 以全屏 kiosk 形态运行，只能调用注册、查询、刷卡和必要的健康请求，不得读取、修改、测试或展示服务器 host、port 和本地配置文件路径。

#### Scenario: 顾客流程返回首页
- **WHEN** 顾客完成、取消或返回流程首页
- **THEN** 顾客窗口回到顾客待机页
- **AND** 不显示或切换到运维启动窗口

#### Scenario: 顾客页面尝试调用运维 IPC
- **WHEN** 顾客窗口请求保存配置、读取完整配置或启动其他窗口
- **THEN** preload 或主进程拒绝该调用
- **AND** 已保存连接配置保持不变

### Requirement: 启动和退出顾客模式受主进程控制
系统 SHALL 在连接测试成功后由运维窗口启动顾客窗口并隐藏运维窗口；普通关闭操作不得让顾客退出到 Windows 桌面，只有店员退出动作或整个应用退出才能关闭顾客模式。

#### Scenario: 启动顾客模式
- **WHEN** 店员在健康连接状态点击“启动自助注册”
- **THEN** 主进程创建或聚焦唯一顾客窗口并进入全屏 kiosk
- **AND** 运维窗口被隐藏而不是销毁

#### Scenario: 店员退出顾客模式
- **WHEN** 店员执行约定的受保护退出动作
- **THEN** 主进程关闭顾客窗口并恢复运维窗口
- **AND** 顾客业务页面不能直接伪造该退出动作

#### Scenario: 普通窗口关闭请求
- **WHEN** 顾客窗口收到 Alt+F4、页面关闭或非授权关闭请求
- **THEN** 主进程保持顾客模式或要求店员退出动作
- **AND** 不直接暴露 Windows 桌面或运维配置

### Requirement: 顾客窗口断线时安全降级并自动恢复
顾客窗口 SHALL 在会员管理端不可达时停止提交新的业务操作、显示不含 host 与 port 的顾客提示，并以有上限的间隔自动重试健康连接。

#### Scenario: 顾客流程期间断线
- **WHEN** 已启动的顾客窗口失去会员管理端连接
- **THEN** 页面显示“服务暂时不可用，请联系工作人员”等顾客文案并禁用注册、查询和绑定提交
- **AND** 页面不显示服务器 IP、端口、堆栈或配置入口

#### Scenario: 连接恢复
- **WHEN** 后台健康重试再次成功
- **THEN** 顾客窗口恢复待机或可安全重试的流程状态
- **AND** 无需退出顾客窗口或重新填写配置

### Requirement: 桌面 API 传输具有最小权限
Electron preload SHALL 按窗口类型暴露最小能力，业务 HTTP 请求 SHALL 由受控的相对 API 路径和已保存目标组成，禁止渲染进程请求任意本地文件、命令或任意网络 URL。

#### Scenario: 正常业务请求
- **WHEN** 顾客窗口调用允许的相对 `/api` 路径
- **THEN** 主进程使用当前已保存会员管理端地址发送请求并返回有限响应
- **AND** 请求不依赖浏览器 CORS 放宽或关闭 Electron `webSecurity`

#### Scenario: 请求任意 URL
- **WHEN** 渲染进程提交带协议、主机、目录穿越或不允许方法的请求
- **THEN** 主进程以稳定错误拒绝请求
- **AND** 不发送网络请求或读取本地资源
