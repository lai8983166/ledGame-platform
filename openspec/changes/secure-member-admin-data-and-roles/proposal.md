## Why

会员管理端当前以明文 SQLite 保存会员身份、手环关联、游玩记录和操作摘要，数据库或异盘备份被复制后可直接读取；现有账号只有出厂管理员与操作员两级，部分限制主要依靠前端隐藏，无法表达店长与店员的实际职责边界。需要在不改变三端核心业务协议的前提下，为本地数据增加可恢复的加密保护，并由后端统一执行三级权限规则。

## What Changes

- 为会员个人信息、手环外部 UID、会员与手环关联、充值/游玩记录中的敏感标识及操作日志敏感详情增加版本化 AES-256-GCM 字段加密；手机号和手环 UID 使用带密钥的 HMAC-SHA-256 查询索引，继续支持唯一性与精确查询。
- 每台会员管理端首次启用时生成独立数据密钥，由 Windows DPAPI 保护后保存在数据库之外；密码哈希、数据库修订号和普通统计字段不做可逆加密。
- 对已有明文数据库执行可中断恢复的一次性迁移，迁移成功后不保留可被业务继续读取的明文副本；密钥缺失、密文被篡改或迁移未完成时明确进入维护状态，不静默创建空库。
- 让现有异盘数据库备份继续保存密文，并校验加密版本和密钥标识；同一 Windows 用户环境可直接恢复，跨机器恢复不在本次自动解密范围内。
- 业务 CSV 导出由会员管理端后端逐行解密后生成可读文件，仍与系统恢复备份严格区分；导出只允许出厂管理员和店长，并记录审计日志。
- **BREAKING**：账号角色由 `FACTORY_ADMIN / OPERATOR` 调整为 `FACTORY_ADMIN / STORE_MANAGER / CLERK`，已有 `OPERATOR` 账号迁移为 `CLERK`。
- 出厂管理员拥有全部权限，可创建、修改、重置密码和逻辑删除店长、店员账号；不能删除唯一的出厂管理员账号。
- 店长继承日常运营查看与非删除业务操作，可创建、修改、重置密码和逻辑删除店员账号，但不能管理店长/出厂管理员，也不能删除会员或执行数据库导入等出厂维护操作。删除店员账号是店长唯一允许的删除操作。
- 店员只可访问手环管理、会员管理中的非删除操作和系统功能开关；不能查看运营总览、房间、记录与数据、积分排行、账号管理、数据库备份/导入及其他系统配置。
- 将会员页中的“导出会员数据”按钮移除，仅在“记录与数据”页统一提供会员、充值交易和游玩记录导出；店员不可进入或调用导出。
- 所有角色限制同时作用于前端导航/按钮与后端接口，越权请求返回明确的 403 错误并写入有界审计信息。

## Capabilities

### New Capabilities

- `member-admin-local-data-protection`：会员管理端敏感字段加密、Windows 本机密钥保护、明文数据库迁移、加密备份兼容及授权后的明文业务导出。
- `member-admin-role-permissions`：出厂管理员、店长、店员三级角色及后端强制执行的页面、业务操作、账号管理和数据导出权限。

### Modified Capabilities

无。

## Impact

- `server`：SQLite schema/migration、数据访问与查询索引、DPAPI 密钥提供器、加解密服务、备份检查/导入、账号角色与逻辑删除、接口授权和审计、CSV 导出。
- `apps/member-admin`：三级角色类型与权限矩阵、导航和设置分区、账号管理交互、会员导出入口移动、维护错误提示。
- `packages/api-client`、`desktop/member-admin`：角色与导出契约、操作员请求头、文件保存和打包所需 Windows 密钥依赖。
- 自动化测试：明文迁移、密文不可读/防篡改、HMAC 查询、备份恢复、导出解密、三级权限矩阵、越权请求和打包版密钥持久化。
- 自助注册端和游戏端继续通过原有业务 API 获取已解密响应，不保存数据库密钥，也不新增权限界面。
