## Context

自助注册端是 Vue + Electron 应用，当前会员创建请求使用 JSON 传递 `avatarId`，头像库中的值是内置头像标识。会员管理端后端已经有字段级 AES-GCM、Windows DPAPI 密钥信封、SQLite 在线备份和原子导入能力，但这些保护只覆盖数据库字段，尚未定义头像二进制文件的生命周期。摄像头输入必须在用户主动操作后开始，并兼容开发版和打包版的 Electron 权限模型。

## Goals / Non-Goals

**Goals:**

- 让自助注册端在不绑定具体摄像头品牌的前提下发现并使用 Windows 本机媒体设备。
- 将拍照作为可取消的头像来源，与现有默认头像/头像库并列，不改变没有摄像头时的注册成功路径。
- 限制照片尺寸、格式和大小，避免大文件或不可解码内容进入中心服务。
- 让会员管理端集中保存加密头像，并在备份/导入时与数据库标识保持一致。
- 保持旧版注册请求只带 `avatarId` 时完全兼容，并为摄像头故障提供可诊断错误。

**Non-Goals:**

- 不支持通过 RTSP/HTTP 的 IP 摄像头发现或控制。
- 不做人脸识别、活体检测、年龄推断或其他生物特征分析。
- 不把照片作为 SQLite 大字段，也不把照片长期保存在自助注册端。
- 不改变会员手机号、手环绑定和激活的核心流程顺序。

## Decisions

### 1. 使用系统媒体设备能力，不适配具体型号

自助注册端使用 `enumerateDevices()` 发现摄像头，并在用户点击拍照后通过 `getUserMedia()` 打开选定设备。Windows 内置摄像头、UVC USB 摄像头和被系统暴露为视频输入的采集卡可共用这条路径；IP 摄像头需要完全不同的协议，明确排除以避免把网络设备误判为本机摄像头。

### 2. 拍照是可选覆盖，不改变注册状态机

拍照弹窗作为头像来源选择的一种，使用独立的预览草稿。只有“确认使用”才替换当前头像；重拍只更新草稿，取消则恢复原头像和原注册字段。无摄像头、权限拒绝、占用或断开均回到现有头像库路径。

### 3. 继续兼容现有 JSON 注册请求

在现有会员创建契约中增加可选的受限头像载荷（旧客户端不携带时行为不变），而不是强制改成 multipart。客户端先裁剪为正方形并压缩到固定上限；服务端再次验证 MIME、解码结果、像素尺寸和字节数。后端先把加密头像写入同一用户数据目录的临时文件，再在会员事务中写入 `avatar_id`，成功后原子移动到头像目录，失败时清理临时文件。

### 4. 文件加密复用现有数据密钥边界

头像文件使用现有 `DataKeyMaterial` 对应的数据密钥进行 AES-GCM 加密，每个文件使用随机 nonce、版本和认证标签；文件名只使用随机头像标识，不使用手机号或姓名。SQLite 的 `avatar_id` 仍走现有字段保护。读取通过会员管理端受控接口完成，不返回服务器绝对路径；找不到文件时回退到默认头像并记录可诊断但不含照片正文的错误。

### 5. 备份和导入采用配套清单与原子替换

数据库备份除了加密 SQLite 文件，还复制加密头像目录和头像文件清单/校验值。导入准备阶段先验证数据库、密钥信封、头像清单和每个文件的认证/校验，再将数据库与头像目录一起放入暂存区；切换失败时同时回滚两者，避免出现会员记录指向不存在头像或旧数据库指向新头像的混合状态。没有头像文件的历史数据库仍可导入并使用默认头像。

### 6. Electron 权限与错误映射

桌面主进程显式允许 registration-kiosk 窗口的 `media` 权限请求，并在开发版和打包版使用同一权限策略。渲染器将 `NotFoundError`、`NotAllowedError`、`NotReadableError`、`OverconstrainedError` 和断流事件映射为中文可操作提示；不把摄像头问题报告成会员管理端网络故障。

### 7. 测试只模拟设备边界，不依赖现场摄像头

单元测试覆盖设备枚举、载荷限制、回退和错误映射；Electron 测试使用可注入的媒体权限/设备夹具验证弹窗和状态机。至少保留无设备、单设备、多设备、拒绝权限、占用、拔出、重启以及头像备份恢复场景，真实硬件验收只需抽查一台标准 UVC 摄像头。

## Risks / Trade-offs

- [门店摄像头驱动或隐私设置导致设备不可用] → 明确提示检查 Windows 摄像头权限、设备连接和占用程序，并始终保留头像库回退。
- [照片文件泄漏或临时文件残留] → 客户端确认前只在内存保留，服务端限制大小并加密落盘，成功/失败/取消都清理暂存文件，日志不写照片正文。
- [头像文件与数据库备份不一致] → 备份记录文件清单和 SHA-256，导入前完整验证，数据库和头像目录使用同一暂存/回滚事务。
- [大量高分辨率照片造成磁盘或备份膨胀] → 强制正方形裁剪、像素和字节上限，拒绝超过限制的内容并在测试中覆盖边界。
- [旧客户端无法理解新字段] → 新载荷保持可选；只含原 `avatarId` 的请求继续走既有默认头像路径。
