# Design

## Context

未分配余额在 members.time_balance_seconds，GameAccessService 已提供事务化充值、分配和还卡。MemberHistory 为会员详情提供充值和游玩弹窗。见 proposal.md。

## Goals / Non-Goals

在现有账户方法、DOM 弹窗及权限上增加最小补偿能力。不做通用钱包、可编辑流水、独立账务页面或在用手环补时。

## Decisions

- schema 9 新建 member_time_adjustments 单表保存会员、唯一请求号、带符号秒数、前后余额、原因、操作时间及操作员快照；不复用充值流水，避免混淆销售。纳入现有自动备份版本触发器，全库备份自然包含记录。
- POST /api/members/{id}/time-adjustments 接收 ADD/DEDUCT、1～1440 整数分钟、1～500 字原因及请求号，沿用 MEMBER_MANAGE 权限。事务内条件增减账户，拒绝负余额；账务和记录要么同时成功，要么全部回滚。
- 相同请求内容重试返回原调整回执，修改参数复用请求号报冲突。调整不写充值、手环、游玩表，不改变收入。
- 会员列表“调整”与“充值”并列；弹窗显示会员、未分配余额、增加/扣减、分钟、原因和确认后的预计余额。网络结果未确认时锁定输入并复用原请求重试，取消不提交。仅对余额有影响，不堆说明段落。
- 会员 history 增加 adjustments 投影；详情新增“调整记录”按钮，弹窗列出增减、前后余额、原因、时间及操作员。无需为此扩展业务 CSV 格式或全局记录 Tab。

## Risks / Trade-offs

- 并发扣减/重试超扣 → 原子条件更新、唯一请求号及原事务串行写入策略，补并发测试。
- 调整本次手环而非账户 → 接口仅写会员未分配余额，测试已发卡 started_at、allocated_seconds 均保持不变。
- 调整记录写入失败而余额已变 → 同事务并用故障注入验证回滚。
- 记录遗漏于备份 → 将新表加入已有备份修订追踪名单，迁移重复执行及修订测试覆盖。

## Migration Plan

只新增表、索引和修订触发器，不迁移或重算账户余额。正式库由应用后续正常启动升级，测试使用临时库；回退须用升级前备份。仅重打会员管理端，另外两端不修改。
