# Design

## Context

动机见 proposal.md。`F:/project/ledGame/src/views/SimpleGameEditorView.vue` 同时用于 Simple、Normal、Diffcult。现有帧序列、对象面板和右侧操作栏分散；对象面板还承担精灵筛选、预览和对象列表切换，不能随按钮整体移除。

对象以 `{id,x,y,color,points}` 保存，绝对点位为 `(x+dx,y+dy)`；`points` 可以为负数，旧元组对象与全景场外点位仍需兼容。现有占用索引按实际点位累计，运行时通过既有颜色优先级选取可见对象。RGB 编辑已具有事务式历史、缓存更新、撤销/重做；批量复制、特效导入等也会修改矩阵，不能只限制鼠标单击。

游戏仓库的 `simple-editor-object-edit-modes`、`simple-frame-and-level-editing-safety`、`simple-editor-edit-history` 主规范是回归背景。本 Change 明确替代其中“同点位任何颜色都不能单击新增”“对象删除确认”“手动基准点”“合并采用首个对象基准点”和相关工具栏的对应行为，其余安全和历史约束保持。

## Goals / Non-Goals

**Goals:** 通过现有编辑器、图标组件和历史入口完成界面收敛、同色叠层约束、中心基准点；让失败编辑无副作用，旧数据可打开和修复，RGB 区域不因按钮切换而移动。

**Non-Goals:** 不新增后端端点、数据迁移、通用命令框架、硬件抽象、图标库；不改 Rank、正常游戏启动、SDK 帧、积分或实时叠色规则。隐藏按钮不删除对应业务函数，也不改变外部游戏文件结构。

## Decisions

### 1. 工具栏只迁移呈现，不重写业务命令

将模式切换、四色/精灵画笔及保留的对象操作，与原右侧保存、调试、预览、导出操作合并到帧序列下方的单行工具栏；复用原事件处理、禁用条件、忙碌状态和返回编辑上下文。对象/精灵面板继续位于原位置，互斥切换与默认精灵预览保持。

隐藏以下入口但保留处理函数：复制当前帧到前一帧、末尾添加帧、手动基准点、层级调整、改色、选中对象复制到前/后/全帧。隐藏实现使用当前编辑器局部模板条件或注释，不建立全局功能开关，也不能通过快捷键继续触发已隐藏的手动基准点/层级/改色操作。保留插入后一帧、复制当前帧到后一帧/全帧、四色批量复制、旋转、合并、删除、撤销/重做等已有所需操作。

删除右侧静态矩阵尺寸、缩放、当前画笔、运行摘要等说明信息；错误、校验失败、保存状态及 GIF 导出进度放到紧凑反馈区域，不被一起删除。工具栏不挤占对象面板，也不增加右侧操作列。窄屏优先工具栏局部横向滚动，不让模式切换导致换行或 RGB 高度抖动；矩阵仍为正方形单元格。

替代方案：只改右侧按钮图标，仍保留多处操作区。拒绝，因为未解决用户要求的操作集中和信息冗余。

### 2. 图标和状态样式分开

复用 `EditorActionIcon.vue`，为保留的业务动作补齐 SVG 图标；复制同色到全帧使用四个 `currentColor` 实心方块。图标保留 `title`、可访问名称和足够点击面积。“复制重复次数”独立为文字按钮，输入值和作用于当前关卡全部帧的逻辑不变。

仅移除对象工具按钮 hover 的前景、背景、边框颜色变化；保留明确的选中拟物效果、禁用和 `focus-visible` 提示。颜色键和索引仍为 0–3，现有语言文本中的粉色对应改为紫色，不改 RGB 值或旧数据。不要用全局 CSS 取消其他页面 hover。

### 3. 按实际占用静默跳过同色叠层

用 `(绝对 x,绝对 y,color)` 统计每帧每种颜色的实际占用次数，包含同一对象重复点位。新数据约束为次数不超过 1；不同颜色可各占一层，优先级仍调用原选择规则，绝不能通过封顶角标伪装合法。

尽量复用/扩展现有对象及占用辅助函数，在现有 RGB 编辑提交边界先处理候选矩阵、再提交历史与缓存，不建立编辑事务框架。普通绘制、框选绘制、精灵、移动、旋转、合并、复制、手动矩阵输入/导入和特效应用均必须经过等效约束。不同颜色已占用的点位允许新增当前颜色；普通/框选绘制自动跳过已有同色的点位，其他未重复点位正常绘制。同色重复属于正常无变化操作，不弹窗、不显示拒绝文案、不设置错误状态。

精灵、移动、旋转及批量复制等整对象操作不裁剪形状；如果候选数据会新增同色层，整次操作静默保持原状。多个对象或多个目标帧的单次操作全部预检，不能留下部分提交。完全无变化时不增加对象、不创建空对象、不改变选中状态、不更新历史；新增后一帧也不能先创建再因复制未生效遗留空帧。更新同一 ID 是替换，不得把原对象和候选对象同时计入。新导入/特效内容内部存在同色叠层时同样静默保持当前文档；语法错误、越界等真正无效输入仍按原规则提示，不能与同色重复混为一谈。

旧文档读取不清理叠层、不截断 points、不自动落盘。在旧冲突帧上编辑，既有冲突键的次数不得增加，也不得在其他键引入新冲突；允许删除、合并或调整逐步减少旧冲突。已有冲突不受无关设置修改、保存或预览阻断；撤销/重做允许准确恢复历史旧状态，不当作新增编辑再次限制。外部新导入内容按新编辑校验，不套用旧文件兼容例外。

替代方案：同色重复时弹错误、覆盖旧对象或裁掉精灵的一部分。不采用：重复绘制不是错误，整对象操作也不应损坏既有形状。仅改变角标、仅限制点击均无法约束复制等路径。

实施细节：复用同步的 `runRgbEdit`，在原有修改回调结束后检查全部目标矩阵，再提交历史。若任一目标不合法，在 Vue 绘制前同步还原矩阵和选择、重置缓存，不产生可见的部分提交或历史记录；不额外搭建候选命令框架。会创建帧的整帧复制与特效应用则先检查候选结果，避免遗留新帧。

### 4. 中心基准点重算保持实际图形

以去重后的绝对占用点包围盒取整数中心：`cx=floor((minX+maxX)/2)`、`cy=floor((minY+maxY)/2)`。偶数尺寸选左/上侧格点，包括负坐标必须用向下取整。中点可落在空洞，不为让基准点成为占用点而增加 `(0,0)`。

重基准仅替换 x/y 与 points 的相对表示，保留绝对点位、ID、颜色及附加字段。新建、精灵创建、合并、形状修改和旋转后重算；平移时中心随图形平移。旋转采用自动中心，维持整数格点与现有 90 度方向约定。

旧对象进入编辑器后在内存中规范为中心表示，保留原绝对点位且作为加载基线，不伪造一次用户编辑或立即保存；用户明确保存后才持久化中心表示。无对象的帧保持空帧，无实际点位的无效对象沿用现有合法化规则，不凭空生成用于求中心的点。

替代方案：用第一个点或平均重心。拒绝，前者不是中心，后者可能因点密度产生难以解释的偏移及非整数位置。

### 5. 删除对象立即执行，但保留历史和其他确认

按钮和 Delete 键统一调用现有 RGB 删除事务，不弹确认；删除后撤销一次可完整恢复。删除帧、删除关卡、批量覆盖帧继续使用现有确认，避免扩大到其他破坏性动作。

### 6. 追加：按手势起点分流，画笔放回对象面板

本节取代第 1 节关于模式切换与画笔位置的安排；其他保留操作仍在帧下工具栏。删除新增/选择移动开关与 Q 模式切换快捷键，不新增隐藏模式。点击已有对象始终选择，空白单击按当前单色或精灵绘制；矩阵组件在按下时锁定本次手势，起点有对象则移动，否则仅当前单色画笔允许框选，跨越其他对象不改手势。精灵状态空白拖动（含拖走再返回）不产生放置，取消拖动不新增历史。多选合并和其他弹窗保护仍优先。

四色画笔在对象编辑区中始终可见（不随对象列表切换消失），与精灵卡片互斥。精灵卡片选中即启用放置；选中已有对象不改变画笔。空输入按固定名称顺序展示安全块、得分块、Double、三个常见陷阱及 1–10、13、14、15、20，共 20 项；只显示库中实际存在的条目，不造精灵、不记录使用历史。非空合法宽高按尺寸筛选，非法或未完成输入不回退常用列表；列表变化导致选中项不可见时回到当前单色画笔，避免不可见精灵继续绘制。

预览单位格为 12px 正方形、间隙 1px，预览图宽高由格数决定。卡片按图形大小排布，过大图形在预览列表内部滚动；对象面板外框和 RGB 可用高度不随列表内容变化。仅改编辑器预览组件，不影响精灵库/特效预览或游戏运行时。

## Risks / Trade-offs

- [旧同色冲突仍可能显示大于四层] → 明确兼容旧数据，不假装其已修复；验证新编辑不能增添冲突，删除/合并能修复。
- [自动中心改变旧自定义基准的后续旋转结果] → 属于本次明确要求；加载时绝对图形不变，测偶数、负坐标、空洞、精灵和全景场外对象。
- [移动或旋转目标已有同色] → 整次静默保持原状，不弹错误、不裁图、不留缓存或半次历史；绘制仅跳过重复点位，非重复点位正常新增。
- [一次批量操作涉及大量点位] → 用 Map 线性统计，重用现有目标帧快照；避免逐格逐对象两层扫描和额外实时监听。
- [取消 hover 后选中不清楚或统一行过宽] → 保留拟物选中和键盘焦点；实际组件测试 1366×768、1920×1080、2560×1440，并检查矩阵稳定和工具栏可达。
- [只靠源码字符串测试误判 UI] → 更新确实过时的断言，同时补真实组件点击、hover 样式、确认调用计数、矩阵数据和撤销测试。

## Migration Plan

先补行为测试，再分阶段完成几何/冲突约束和 UI；不自动迁移数据库。回归游戏读取、保存重开、预览、调试页面返回、帧复制、特效和精灵路径后，在原 release 位置重打游戏端 `win-unpacked` 与 ZIP。回退恢复本 Change 的前端逻辑/样式并重打包，保存数据仍采用原结构，不能靠删数据库回退。
