## Context

现有工具已经将中心启动、代理执行和最终核账拆为 `center`、`agent`、`verify` 三个可靠命令，并把 B/C 的计划与结果保存在各自本地目录。当前问题位于三台机器之间的人工编排层，不是负载模型或 SQLite 核账能力不足；见 `proposal.md`。

便携工具运行在 Windows 局域网中，不依赖共享盘或第三方服务。测试业务端口默认是 18090，B/C 的业务请求必须继续直达会员管理端，以免协调层改变并发特征。

## Goals / Non-Goals

**Goals:**

- 把常规操作压缩为 A 机选择档位、B/C 各运行一次加入命令、A 机查看报告。
- 复用现有中心启动、代理运行和核账实现，确保结果口径不变。
- 在网络短暂中断时保住本地证据，并让非业务传输可以安全恢复。
- 让操作者在 A 机直接看到“缺 B/缺 C、运行中、可能离线、已完成、核账结果”。

**Non-Goals:**

- 不做通用远程命令执行、软件分发、常驻 Windows 服务或图形化管理平台。
- 不代理或重试注册、充值、绑定、开局、结算等业务写请求。
- 不引入数据库表、共享目录、连接令牌或互联网服务。
- 不移除原始高级命令和手工证据恢复路径。

## Decisions

### 1. A 机使用独立轻量 HTTP 控制器

控制器与隔离会员管理端同进程外运行，默认端口为测试业务端口加一（18091）。它只提供健康检查、当前批次读取、代理状态、固定证据上传和完成通知。相比 SMB 共享目录，HTTP 不要求三台机器配置 Windows 账户和文件共享；相比把协调接口加入会员管理端，本方案不污染生产业务 API，也不涉及数据库迁移。

控制器只接受当前 runId、固定 agentId（B/C）及白名单文件名。证据采用临时文件接收，边接收边计算 SHA-256，校验成功后原子改名；相同哈希的重复上传视为成功，不同内容禁止覆盖。请求体和每种证据均设置上限，避免错误文件耗尽磁盘。

### 2. 控制器组合现有三个核心实现而非复制业务逻辑

A 机入口调用现有中心启动函数，B/C 加入入口最终调用现有代理执行函数，证据齐全后调用现有核账函数。原命令保持可用。这样简化层只负责状态机和文件传输，固定档位、确定性身份、非重试写请求及验收标准仍只有一份实现。

### 3. B/C 保存最小本地配置，运行参数由 A 机下发

每台压力机只持久化控制器 URL 和 `B`/`C` 身份。runId、档位、平台地址及开始时刻每轮从 A 机取得，防止把上轮连接文件或错误档位带入新批次。首次可通过参数保存；无配置时命令提供交互式输入。

本地配置保存在便携工具的 `config/agent-local.json`，便于操作者查看和迁移。它不包含凭据。A 机授权仍由中心启动器在本机寻找，绝不向 B/C 发布或复制。

### 4. B/C 就绪屏障由当前控制器内存状态实现

控制器启动后只有一个活动批次。B/C 分别取得批次并报告 `READY`；两个身份齐全后，控制器发布一个约五秒后的共同开始时刻。代理在就绪期间轮询，开始后沿用现有本机单调时钟调度。无需数据库或通用任务队列，控制器重启则该轮协调失败，但本机证据仍可用旧流程核账。

### 5. 进度是可观测信息，不是业务成功依据

代理复用现有节流进度回调，将阶段和简短摘要发给 A 机。控制器记录最后联络并定期打印 B/C 状态；超过阈值只显示“可能离线，请检查程序、网络或防火墙”，不猜测物理根因。最终通过只来自既有核账器，不从进度消息推导。

### 6. 只有控制消息和证据传输可重试

加入轮询、状态上报及同内容证据上传可以有限重试，因为它们不修改业务数据库且上传具有内容哈希幂等性。现有代理发出的业务写请求继续最多一次。该边界在代码中通过独立的控制器客户端保持，控制器不暴露业务转发接口。

## Risks / Trade-offs

- [控制器端口被防火墙拦截] → 启动时显示 A 机 URL，并在 B/C 给出面向网络/防火墙的连接提示；原文件复制流程仍可用。
- [A 机控制器中途退出] → B/C 始终先写本地证据；控制器重启不自动接管旧轮，操作者使用原 `verify` 兜底，避免模糊恢复造成串批次。
- [两机时钟略有偏差] → 共同开始时刻只用于形成重叠，精确延迟仍以各代理单调时钟计算；局域网机器应保持 Windows 自动校时。
- [长档位证据较大] → 使用流式接收、文件大小上限和哈希校验；不把逐请求结果包装为大 JSON 状态消息。
- [控制器无身份令牌] → 功能只绑定局域网，且严格限制 B/C、当前 runId、文件白名单和目录；本 Change 按既定低成本局域网威胁模型不增加令牌。

## Migration Plan

1. 便携构建加入新的 A 机和 B/C 入口及示例配置，不改变既有配置文件和命令。
2. 操作者可继续用旧流程验证新版本；新入口失败时回滚为旧命令，无数据迁移。
3. 新入口通过本机自动化、双代理集成测试和一次三机 quick 实操后，中文说明将其列为推荐流程，旧流程列为故障兜底。
