# Spec Delta

## Purpose

约束共用编辑器中真实 RGB 点位的同色重复占用，使每种颜色最多占一层而不同颜色仍遵守原叠色规则；重复颜色静默跳过，不以错误打断绘制，覆盖其他编辑来源并兼容现有包含重复层的游戏文档。

## ADDED Requirements

### Requirement: 每个点位每种颜色最多一层
编辑器 SHALL 按绝对坐标和颜色约束新编辑数据，同种颜色占用次数不超过 1，不同颜色最多各一层，且 SHALL 保留现有颜色覆盖优先级。普通/框选绘制 SHALL 静默跳过已有同色点位，其他点位正常新增，不显示拒绝或错误。限制 SHALL 包含对象内重复点位，并覆盖精灵、移动、旋转、合并、复制、导入及特效等矩阵修改，不得只封顶层数显示。

#### Scenario: 不同颜色与重复颜色
- **WHEN** 用户从空白处开始框选，在已有红色点位添加蓝色，然后再次框选添加红色
- **THEN** 蓝色允许添加并按原优先级显示，再次添加红色无变化、不增加层、不显示任何拒绝或错误提示

#### Scenario: 框选中只有部分点位重复
- **WHEN** 用户框选绘制红色，范围内部分点位已有红色、部分没有红色
- **THEN** 已有红色点位保持不变，其他点位正常新增红色，无拒绝或错误提示

#### Scenario: 完全重复绘制
- **WHEN** 普通或框选绘制的所有点位都已有当前颜色
- **THEN** 数据、选择和历史保持不变，不新增空对象或空历史记录，不显示拒绝或错误提示

#### Scenario: 精灵移动或形状编辑冲突
- **WHEN** 新增精灵、移动、旋转或修改形状导致任一点位有两层相同颜色
- **THEN** 整次编辑静默保持原状、不增加同色层、不显示拒绝或错误，不裁掉精灵点位、不覆盖其他对象

### Requirement: 批量修改全有或全无
一次影响多对象或多帧的整对象操作 SHALL 在提交前验证所有目标；任何目标会新增同色叠层时，SHALL 静默保持全部矩阵、帧结构、选中状态和历史不变，不显示拒绝或错误。同 ID 替换 SHALL 不误算为新增一层。

#### Scenario: 批量复制部分目标冲突
- **WHEN** 将本帧同色对象复制到全部帧，其中一个目标帧与不同 ID 的同色对象冲突
- **THEN** 所有目标帧均保持原状，撤销历史不增加，不显示拒绝或错误提示

#### Scenario: 覆盖同 ID 对象
- **WHEN** 复制操作更新目标帧中同 ID 对象，候选图形没有与其他对象冲突
- **THEN** 正常替换，不因为旧对象与新对象同时被计数而错误地跳过更新

#### Scenario: 新导入内容内部冲突
- **WHEN** 用户导入或应用的新矩阵内部存在同色重复点位
- **THEN** 整次操作静默保持原状，当前文档、历史与帧序列不变，不显示同色叠层错误；其他真正无效输入仍按原规则提示

### Requirement: 旧叠层数据无损兼容
旧游戏文件 SHALL 可读取，不自动删除点位或落盘清理；旧冲突帧的编辑 SHALL 不增加既有冲突次数或引入新冲突，并允许减少冲突。无关设置、保存和预览 SHALL 不因未被增加的旧冲突被阻断，撤销/重做 SHALL 准确恢复原历史状态。

#### Scenario: 旧文件打开与修复
- **WHEN** 打开含同点位三层红色的旧游戏，并删除其中一层
- **THEN** 打开时三层均保留，删除后允许变为两层，其他对象和颜色规则不变

#### Scenario: 无关编辑与历史恢复
- **WHEN** 用户修改旧冲突帧以外的数据、保存游戏，或撤销一次减少旧冲突的编辑
- **THEN** 无关合法编辑与保存成功，撤销恢复原历史，不自动清理旧点位
