## Why

自助注册端当前把首个头像作为视觉兜底，却没有把它记为已选值，导致顾客即使接受默认头像也必须额外进入头像库确认；头像库也没有按性别组织。刷手环仍依赖顾客聚焦输入框，而会员管理端积分榜继续读取演示数组，这些行为都与门店真实使用流程不一致。

## What Changes

- 让新注册会话始终持有一个可提交的默认头像；顾客不修改头像也能继续注册。
- 为内置头像增加男性、女性等适用范围元数据；选择男性或女性后只展示对应头像，并在当前头像不兼容时自动切换到该性别的默认头像。
- 把顾客可见的手环 UID 输入框替换为“开始刷手环”按钮和阻塞式等待弹层；仅在弹层打开时接收读卡器的数字加回车输入，成功后自动关闭，取消只退出等待且不得冒充成功。
- 新增真实日榜、月榜和年榜查询能力，依据 SQLite 中已正常结算的游戏积分进行聚合和排名。
- 会员管理端排行榜改为调用服务端接口，提供加载、错误、空榜、周期切换和手动刷新状态，并删除演示排名和伪造趋势。
- 为默认头像、性别筛选、刷卡等待状态、周期积分聚合与管理端榜单接入补充自动化测试。

## Capabilities

### New Capabilities

- `kiosk-registration-profile`: 约束自助注册资料中的默认头像、性别相关头像目录和无需重复确认的提交行为。
- `member-points-leaderboard`: 约束基于真实已结算游戏记录的日、月、年积分榜 API 及会员管理端展示行为。

### Modified Capabilities

- `wristband-core-flow-ui`: 将自助注册端刷手环步骤从可见输入框改为显式启动、可取消的读卡等待交互。

## Impact

- 自助注册端：`apps/registration-kiosk` 的注册会话、头像目录、头像选择界面、刷手环页面与键盘楔入读取逻辑。
- 会员管理端：`apps/member-admin` 的排行榜页面及演示数据依赖。
- 平台服务端：`server` 新增周期积分榜查询、日期边界与稳定排名逻辑。
- 共享客户端：`packages/api-client` 新增排行榜请求和响应类型。
- 验证：平台 SQLite 集成测试、自助注册端和管理端组件测试，以及受刷卡交互影响的核心流程验收脚本。
- 不涉及游戏端和游戏后端仓库，也不改变现有积分结算规则。
