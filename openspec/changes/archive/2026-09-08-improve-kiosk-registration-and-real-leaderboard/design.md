## Context

参见 `proposal.md`。目前注册表单通过计算属性把头像目录第一项显示成兜底图，但注册会话中的 `avatarId` 仍为空，因此校验要求顾客再打开头像库确认。头像目录没有性别元数据。读卡器是 USB 键盘楔入设备，会连续输入数字 UID 并自动发送回车；当前页面通过可见输入框接收它。排行榜页面直接引用 `apps/member-admin/src/data.ts` 中的日、月、年演示数组，而平台已有已结算游戏积分和可注入时钟，但没有周期榜单接口。

## Goals / Non-Goals

**Goals:**

- 让默认头像成为注册会话中的真实有效值，并让男性、女性头像选择一致且可测试。
- 把读卡器接收限制在显式、可取消的扫描会话中，避免页面焦点决定刷卡能否成功。
- 由平台服务端统一定义周期边界、积分聚合和名次，管理端只展示权威结果。
- 延续核心流程“先写失败测试、再实现、最后运行完整验证”的方式。

**Non-Goals:**

- 不接入拍照、摄像头或上传自定义头像。
- 不改变会员性别字段的现有取值，也不根据头像推断性别。
- 不提供手工输入手环 UID 的顾客入口；硬件故障诊断仍属于运维或调试能力。
- 不实现排行榜实时推送、自动轮询、跨门店榜单、历史名次趋势或真实电视连接。
- 不修改游戏端计分、结算和上报规则。

## Decisions

### 1. 头像目录增加适用范围和显式默认值

每个内置头像增加 `audience` 元数据，取值为 `male`、`female` 或 `neutral`，并为男性、女性和中性场景各指定一个稳定默认头像 ID。新注册会话初始化为中性默认头像，因此界面展示值和提交值始终一致。

选择男性或女性时，若当前头像不在对应目录中，则立刻切换到对应默认头像；若兼容则保留。选择“不透露”时展示完整头像目录并允许保留任意头像。这样既满足“默认头像无需再选”，又不会在顾客改变性别后保留明显不兼容的选择。

备选方案是继续允许空 `avatarId` 并在提交时补首个头像，但这会让校验、预览和请求数据继续使用不同状态，因此不采用。

### 2. 刷手环采用局部扫描状态机和窗口级键盘捕获

刷手环步骤使用 `idle -> waiting -> submitting -> success` 状态，并允许 `waiting/submitting` 进入失败后回到可重试的 `waiting`。只有 `waiting` 状态注册或启用窗口级键盘监听：数字追加到临时缓冲，回车结束一帧并触发现有“查询手环后绑定”的服务调用。成功后关闭弹层，失败则清空缓冲并在弹层内展示错误。

取消操作关闭弹层、移除监听并清空缓冲，不改变会员、手环或成功状态。离开页面和返回首页也执行相同清理，避免下一位顾客继承未完成输入。提交请求期间防止重复提交；取消是否允许中断网络请求由实现决定，但迟到响应必须被扫描会话标识丢弃，不得把已取消会话推进到成功页。

备选方案是自动在整个刷卡页持续监听，仍可能把软键盘或物理键盘输入误认为手环；保留隐藏输入框则继续依赖焦点，因此均不采用。

### 3. 服务端提供权威周期榜单接口

共享客户端新增 `GET /api/leaderboard?period=day|month|year` 契约。响应包含 `period`、`periodStart`、`periodEnd`、`generatedAt` 和 `entries`；每条记录至少包含 `rank`、`memberId`、`memberName`、`avatarId`、`points` 与 `completedGames`。

服务端使用已有可注入 `Clock` 和一个明确配置的 `ZoneId` 计算半开区间 `[periodStart, periodEnd)`，从 SQLite 聚合区间内 `COMPLETED` 游戏。仅返回有效会员且至少有一局完成记录的成员。名次只由积分决定，采用 `1 + 积分严格更高的人数` 的竞赛排名；同分成员按稳定会员 ID 排序，完成局数只展示、不参与破同分。

备选方案是管理端下载会员和游戏记录后自行聚合，但会复制日期、状态和排名规则，也可能与 Player Info 的积分来源不一致，因此不采用。

### 4. 排行榜页面按请求状态渲染且不自动轮询

进入页面、切换周期和点击刷新时请求服务端。页面持有 `loading/error/data/lastUpdated` 状态；周期切换时使用请求序号或取消机制忽略迟到响应。前三名台座和后续列表都从同一响应派生，副屏预览复用同一数据。若少于三人，布局只展示存在的条目；空榜显示空状态。

原有 `trend` 没有真实历史数据来源，因此删除，不以零值或随机值替代。更新时间使用服务端 `generatedAt`。不自动轮询可以控制实现复杂度和门店网络负担，管理员需要时手动刷新。

### 5. 关键行为采用测试先行

先增加会失败的前端测试，覆盖默认头像、男女目录、性别切换、扫描弹层、取消、成功和非等待输入；再增加真实 SQLite 集成测试，覆盖周期边界、只统计完成记录、空榜与并列名次。管理端测试验证不再导入演示排行、周期请求、刷新、错误和空状态。最后更新受影响的核心验收脚本，使它通过点击按钮后发送 `2283055618` 加回车完成真实扫描交互。

## Risks / Trade-offs

- [读卡器输入可能与普通键盘输入相同] → 只在显式等待弹层内捕获，限制为数字加回车，并在取消、离页和请求结束时彻底清理监听与缓冲。
- [顾客取消时请求可能已经发出] → 为每次扫描分配会话标识并忽略已取消会话的迟到响应，防止误报成功。
- [历史时间戳和服务器时区不一致会影响周期边界] → 接口返回实际周期边界，测试固定 `Clock` 和 `ZoneId`，并沿用数据库时间戳的统一格式。
- [头像性别标注具有产品主观性] → 元数据集中在头像目录，后续可只调整分类和默认 ID，不改变流程代码或接口。
- [榜单人数很大时全量响应会增长] → 当前门店规模小，先返回完整榜单；接口响应结构保留未来增加分页的空间，但本 Change 不引入分页复杂度。

## Migration Plan

1. 先合入测试和共享类型，再实现服务端榜单接口、头像目录及两端 UI。
2. 不需要 SQLite 表结构迁移；现有会员和已结算游戏记录可直接生成榜单。
3. 发布后旧注册会话只存在于前端内存，重启自助注册端即可使用新的默认头像状态。
4. 若需回滚，可恢复旧页面和客户端代码并移除新增查询入口；新增只读接口和头像元数据不会破坏现有数据库或旧客户端。
