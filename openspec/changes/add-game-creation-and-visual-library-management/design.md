# Design

## Context

现有列表以 type=default/rank 识别编辑器；Simple 共用编辑器支持 simple、normal、diffcult。媒体库由 Electron 读取应用 media 目录，精灵 API 已支持增删改查。

## Goals / Non-Goals

目标：复用现有文档转换、校验、列表通知、编辑器及媒体协议；创建独立记录并提供可视化资源维护。
非目标：新增玩法引擎、游戏家族表、资源上传服务器、改造对象编辑区精灵预览、改动硬件或三端通信。

## Decisions

1. 草稿接口只接收两种受支持的大类，后端生成有效的默认编辑文档但不写入数据库。娱乐挑战使用 default/[1]，排位赛使用 rank 现有模式；不克隆用户游戏、不调用种子更新、不增加数据库字段或草稿表。类型由现有 type 推导。
2. 选择类型后通过现有 open-game 事件进入无 ID 的编辑器草稿，首次点击保存、校验成功才插入数据库并生成卡片；取得 ID 后继续使用现有更新接口。退出未保存草稿不产生数据，保存失败保留草稿供重试。草稿的全局配置、符号灯及布线弹窗仅修改本地草稿；首次保存前不允许启动调试。多维竞技禁用，创建不覆盖既有排序及记录。
3. 独立精灵库采用缩略图卡片，按真实颜色等比例绘制，选中后可编辑或删除。取消右侧固定大预览布局；不影响 Simple 编辑器的宽高搜索与画笔选择。
4. 上传使用主进程文件选择器和复制操作，目标为当前文件夹或媒体根目录。新建目录限定单一目录名；验证真实路径不得越出媒体根目录。同名文件自动加序号且独占复制，不覆盖文件；取消选择不写入。复用原生对话框焦点恢复机制。

## Risks / Trade-offs

- 新游戏默认文档不满足现有校验 → 通过创建后两类编辑器读取、保存、列表和启动文档验证测试覆盖，不带 demo 名称或媒体占位路径。
- 大精灵列表产生过多格子 DOM → 缩略图使用限尺寸画布而不是为每个网格生成 DOM。
- 上传源文件或目标目录不可用 → 展示明确错误，不显示虚假成功，不删除源文件；自动命名及路径校验测试覆盖冲突、越界和目录链接。
- 打包资源目录可能不可写 → 失败提示保留，不切换到无关用户目录；按现有媒体目录布局打包。

## Migration Plan

不迁移旧数据。新增游戏存入当前数据库，媒体复制至现有目录；发布更新游戏端及其内嵌后端。不重新打包其他端。
