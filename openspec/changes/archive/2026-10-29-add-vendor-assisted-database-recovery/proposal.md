## Why

当前备份中的数据密钥由原 Windows 用户环境的 DPAPI 保护；如果主硬盘和 Windows 一起损坏，只有备份盘时，新系统无法解封旧密钥，只能联系厂家手工处理。需要增加一条厂家协助但不传输会员明文数据的恢复路径，使新系统能够安全地重新封装旧数据密钥。

## What Changes

- 为后续生成的正式备份增加厂家恢复密钥信封，厂家只保管对应的恢复私钥，客户应用只内置公钥。
- 在新系统中增加“生成数据库恢复请求”的流程，生成临时公钥和备份身份信息，不导出数据库明文。
- 增加厂家离线恢复工具处理恢复请求：解开旧门店数据密钥并针对新系统临时公钥重新封装，输出恢复响应。
- 在会员管理端增加出厂账号可用的恢复响应导入流程，验证响应、备份元数据、SQLite 完整性和密文可解密性后，重新生成当前 Windows DPAPI 信封并导入数据库。
- 恢复过程继续使用现有维护状态、原子替换、回滚和导入后重新登录规则，不在启动检查窗口开放恢复入口。
- 明确旧版没有厂家恢复信封的备份只能在原 Windows 用户环境中恢复，不能宣称支持跨系统恢复。
- 为恢复请求、厂家响应、拒绝条件、断电/中断回滚和测试环境隔离补充自动化测试及中文使用说明。

## Capabilities

### New Capabilities

- `vendor-assisted-database-recovery`: 在不把会员明文数据库发送给厂家的前提下，由厂家使用离线恢复私钥协助新 Windows 系统重新导入加密备份。

## Impact

- 会员管理端后端：备份元数据、恢复请求/响应、密钥封装、候选校验和导入维护流程。
- 会员管理端 Electron 界面：出厂账号限定的恢复入口、文件选择、校验进度和明确错误提示。
- 厂家离线恢复工具：跨机器运行，私钥仅存在厂家维护环境，不进入客户安装包或 Git。
- 现有 SQLite 字段加密、异盘备份、DPAPI 信封、导入原子替换和账号权限逻辑需要保持兼容。
- 未来备份格式会增加恢复信封；已有仅含旧 DPAPI 信封的备份不自动获得跨 Windows 恢复能力。
