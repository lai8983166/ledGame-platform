# 会员账户、发卡与还卡

余额归会员，手环只是凭证。发卡后为 READY，不立即扣时；第一次游戏激活后开始沿用持续计时，还卡结算剩余秒数并暂停。再次发卡可用其他空闲手环，不必再充值。正在游戏中的会员须先结束游戏再还卡。

## 柜台操作

- 运营管理首页 → 发卡：输入手机号，已有会员直接选择；新会员填写姓名。下一步刷手环（数字后回车），填写充值分钟数、确认。已有余额可填写 0。
- 运营管理首页 → 还卡：刷手环、确认。保留余额，解除绑定，手环回到库存。
- 取消不加时、不还卡。新会员资料若已保存，不因取消发卡而删除。
- 查询框回车重新读取会员列表；点击会员可编辑资料、查看充值与游戏记录。

## 新接口

以下两接口需要现有 `X-Operator-Id`，适用出厂账号、店长和店员。

| 请求 | JSON 字段 | 行为 |
| --- | --- | --- |
| `POST /api/wristbands/issue` | `uid`、`memberId`、`durationMinutes`（0～1440 整数）、`requestId` | 一个事务入账、发卡、记录充值；重复请求号及相同内容不会重复加时；不同内容冲突。 |
| `POST /api/wristbands/return` | `uid`、`bindingId`（刷卡查询返回） | 暂停账户、释放原绑定；重复/迟到请求不影响新持有人。 |

`GET /api/members` 增加 `remainingSeconds`、`consuming`、`wristbandUid`。`GET /api/player-info` 增加 `account: { remainingSeconds, consuming }`，即使已还卡仍能查询余额。

旧 charge/bind、游戏放行、游玩结算和旧游戏端兼容接口保留。旧 charge 的未绑定时长作为待入账数据，在 bind 时一次转入会员，不属于下一位持卡人。旧 READY/ACTIVE 余额在首次升级时迁移一次；历史 RETURNED/EXPIRED 不重新入账。

余额迁移后不能再用旧版本写同一数据库。需回退时使用升级前备份，不把新账户库交给旧版运行。
