# 会员账户、发卡与还卡

账户余额归会员，手环只是凭证。人工发卡从账户分配本次时间，立即开始连续计时；自助激活预置手环成功也立即计时。首次游戏刷卡不再重置计时；选游戏、排队和两局之间继续计时。还卡按服务端时间结算，未用完的秒数退回账户并释放手环。到期只耗尽本次额度，不影响账户未分配余额。正在游戏中的会员须先结束游戏再还卡。

## 柜台操作

- 会员列表 → 余额旁“充值”：填写充值分钟数，可选手填收款金额，不刷卡、不按分钟单价自动计算。充值不自动延长在用卡。
- 会员列表 → 新增会员：姓名、手机号、可选初始充值与收款。资料及初始充值原子保存，头像默认可用。
- 会员列表 → 行内“发卡”：直接带入会员，刷手环（数字后回车），填写本次分配分钟数、确认。首页发卡入口仍保留。
- 运营管理首页 → 还卡：刷手环、确认。按服务端当时实际剩余退回账户，解除绑定，手环回到库存。
- 充值、发卡、还卡分别确认。取消不充值、不分配、不退回。会员或充值若已经独立保存，不因取消之后的发卡而撤销。
- 查询框回车重新读取会员列表；点击会员可编辑资料、查看充值与游戏记录。

## 新接口

以下两接口需要现有 `X-Operator-Id`，适用出厂账号、店长和店员。

| 请求 | JSON 字段 | 行为 |
| --- | --- | --- |
| `POST /api/members/{id}/recharge` | `durationMinutes`（1～1440）、`amountCents`（可省略或 null）、`requestId` | 无需手环，给会员账户入账；保存操作员、手填收款及请求号，重试不重复充值。 |
| `POST /api/members` | 原资料字段，加 `initialDurationMinutes`（0～1440）、`amountCents`、`requestId` | 管理端可同时初始充值；初始充值需要操作员身份。自助端原不充值建档接口保持。 |
| `POST /api/wristbands/issue` | `uid`、`memberId`、`durationMinutes`（1～1440 整数）、`requestId` | 只分配而不充值；额度不得超过账户余额，立即 ACTIVE，重复请求不再次分配或重置计时。 |
| `POST /api/wristbands/return` | `uid`、`bindingId`（刷卡查询返回） | 原子退回当前剩余秒数、结束绑定；返回 `returnedSeconds` 和 `accountRemainingSeconds`；重复/迟到请求不退款第二次或影响新持有人。 |

`GET /api/members` 的 `remainingSeconds` 和 Player Info 的 `account.remainingSeconds` 表示未分配账户余额；手环查询及游戏 access 的 `remainingSeconds` 表示本次用卡剩余，两者不混用。即使已还卡仍能查账户余额。

旧 charge/bind、游戏放行、游玩结算和旧游戏端兼容接口保留。未激活预置卡不计时；bind 成功先将预置额度充入会员账户并保存来源充值记录，再全额分配到本次用卡并立即计时，所有动作在同一事务中完成。不挪用会员原账户余额，不重复入账。独立会员充值并入充值历史、交易查询、CSV 和收入统计；分配与退回不计充值收入，今日发卡数按实际绑定记录统计。

## 手环预充值

- 独立“手环预充值”页 → 预充值 → 设置每只卡的分钟数 → 开始刷卡。每次读卡器输出数字及回车后保存一只，成功后继续等待下一只；“完成”退出，不撤销此前成功的卡。
- 默认列表显示待激活卡，可按完整卡号、状态查询和刷新。待激活卡可修改分钟数或确认取消；使用中的卡先还卡，不能预充值。取消仅撤销未领取额度，不影响会员账户。
- 顾客领取后，自助端查询/注册会员再刷卡激活；没有自助机可在管理端正常“发卡”流程中刷预充值卡，分钟数自动带入且不可更改，确认后领取激活。柜台看见的额度若已被别人修改/取消，须重新刷卡。
- 预置额度尚未属于某个会员，不计时，不自动按分钟单价记收款。激活时记录一条会员入账并全额分配，会员原未分配余额不变。例：账户 40 分钟 + 领取 60 分钟 → 账户仍 40、本次 60；20 分钟后还卡 → 账户约 80、卡为空闲，不自动恢复预置额度。
- 新预置和取消不进入交易/会员充值记录；领取后只显示一条有手环来源的会员充值记录，金额未收录显示“—”。旧 charge 的历史金额、单价、日期仍保留，总收入不重复、不改变。操作员准备、修改、取消记入操作审计；领取入账关联唯一原记录。

| 请求 | JSON / 参数 | 行为 |
| --- | --- | --- |
| `GET /api/wristband-precharges` | 可选 `uid`、`status=PENDING/CLAIMED/CANCELLED` | 原手环管理权限查询预置记录，返回 `id`、卡号、分钟、状态、版本、准备时间及操作员。 |
| `POST /api/wristband-precharges` | `uid`、`durationMinutes`（1～1440）、`requestId` | 幂等准备；同一卡不能重复预置。 |
| `POST /api/wristband-precharges/{id}/edit` | `version`、`durationMinutes` | 仅修改当前待领取记录，旧版本失败。 |
| `POST /api/wristband-precharges/{id}/cancel` | `version` | 确认取消当前待领取额度，不能取消后续重新发放的额度。 |

以上接口均要求有效 `X-Operator-Id`，使用原手环管理权限；出厂账号、店长、店员均可。柜台 `issue` 可额外传扫描得到的 `prechargeId`、`prechargeVersion`；预充值卡必须全额领取，普通卡分配不变。自助 `bind` 请求格式不变，已领取后重复请求仍提示“此手环已绑定”，不重置计时。

schema 8 只新增预充值状态、请求号、版本和会员入账来源索引，不修改已存在的账户余额和绑定。升级迁移可重复执行。

升级为 schema 7：现有已发卡共享账户的实际剩余一次迁至当前绑定，ACTIVE 按升级时的实际剩余继续，READY 从升级时开始；无卡会员保留余额。历史 RETURNED/EXPIRED 不加回。多个历史开放绑定按原额度分配剩余，总权益守恒；不再重复迁移。不直接改本机人工库，迁移在新应用启动时执行。

余额迁移后不能再用旧版本写同一数据库。需回退时使用升级前备份，不把新账户库交给旧版运行。
