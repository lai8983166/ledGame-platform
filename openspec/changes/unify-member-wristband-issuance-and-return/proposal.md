# Proposal

## Why

会员与手环办理分散，余额跟随手环绑定导致归还后无法保留会员权益。按最新确认，余额归会员，手环仅作为消费凭证；柜台只保留发卡、还卡两个主操作。

## What Changes

- 合并柜台入口到运营管理首页；发卡识别/登记会员、保存后刷实体手环、确认时为会员增加所填分钟数并绑定，已有余额可不充值直接发卡。
- 房间管理改名运营管理并作为登录后的首页；房间卡仅显示名称、IP、状态、游戏剩余时间，详情只保留排队、硬件和原权限允许的改名；运营总览删除房间概况。
- **BREAKING**：可用时长由会员账户保存，不再由绑定记录拥有。首次游戏激活沿用现有持续计时规则；还卡将消耗结算到当前、暂停账户、释放手环，保留剩余时长，再发卡继续使用。
- 还卡合并解绑、回收，不提供清余额等独立柜台动作。运行中的手环不得归还；重复/延迟请求不能扣两次或解绑后来使用者。
- 保留旧充值/绑定 API 的三端与旧游戏兼容：未绑定的旧充值仅作为待入账时长，在绑定时一次转入会员，不复制到每张新卡。
- 旧绑定的当前剩余时长一次迁入会员账户，保留身份、积分及历史；新接口使用原权限和审计机制。
- 不加小标题或说明段落，不修改本次之外的权限矩阵、备份/加密、排行、按次数消费或 RUNNING-only 计费。

## Capabilities

### New Capabilities
- `member-time-account`: 会员时长账户、旧余额迁移、跨还卡/发卡保留、事务及重试安全。

### Modified Capabilities
- `wristband-core-flow-ui`: 管理端发卡/还卡统一流程与会员余额展示。
- `game-access-entitlement`: 游戏放行仍用原接口，但额度来自会员账户并支持暂停/恢复。
- `player-info-query`: 查询会员账户余额，不依赖当前是否持有手环。

## Impact

修改 platform 仓库会员管理前端、SQLite 结构/迁移、访问权益及查询投影、接口/客户端类型和测试。必要时仅同步注册端余额投影；游戏端请求和响应核心字段保持，不改游戏仓库。测试使用隔离数据库；交付重打会员管理端/必要注册端，不打包当前使用中的并发/烤机/激活工具，不自动提交已有未提交工作。
