# 厂家协助数据库恢复

本功能用于主硬盘和 Windows 用户环境同时损坏、只能使用异盘备份的场景。正式备份仍保留原来的 `data-key.dpapi`，并额外保存 `factory-key-envelope.json`。恢复信封只包含门店数据密钥的 RSA-OAEP 封装，不包含会员、交易、游玩记录或头像明文。

## 客户操作

1. 在会员管理端使用出厂账号登录，进入“数据库备份”，选择包含 `platform.db`、`metadata.json` 和 `factory-key-envelope.json` 的 `latest` 备份目录。
2. 点击“生成跨系统恢复请求”，把生成的 `recovery-request.json` 发给厂家。无需发送 `platform.db`、头像目录或 CSV。
3. 收到厂家返回的 `recovery-response.json` 后，在同一台新系统的会员管理端点击“导入厂家恢复响应”，依次选择原备份目录和响应文件。
4. 系统会校验响应密文、请求编号、实例身份、revision、`keyId`、摘要和有效期；校验通过后进入既有的维护导入流程。确认覆盖后程序停止服务、保留回滚副本、原子替换数据库与 DPAPI 信封，并重启复核。

请求和响应均为一次性材料，默认有效期 30 分钟。取消或校验失败不会改变当前数据库和正式备份。

## 厂家操作

厂家离线工具不需要客户数据库：

```text
node scripts/database-recovery-tool.mjs issue-response \
  --request recovery-request.json \
  --envelope latest/factory-key-envelope.json \
  --private-key <厂家受控目录>/database-recovery-vendor-private.pem \
  --output recovery-response.json
```

工具只读取请求和恢复信封，用厂家私钥解封门店数据密钥，再使用请求中的临时公钥重新封装最小响应；不会打开 SQLite、头像目录或 CSV，也不会把数据密钥写入日志。RSA-OAEP 本身提供密文完整性校验，因此不再额外生成重复的响应签名。厂家私钥不得进入客户安装包、测试目录、源码或 Git。

如果使用发布目录 `release/database-recovery-tool`，目录内已带 Windows Node 运行时，可在该目录打开命令行并执行同样的参数：

```text
database-recovery-tool.cmd issue-response --request recovery-request.json --envelope latest/factory-key-envelope.json --private-key <厂家受控目录>/database-recovery-vendor-private.pem --output recovery-response.json
```

首次建立密钥对（仅在厂家受控环境执行）：

```text
node scripts/database-recovery-tool.mjs generate-keys \
  --public-output server/src/main/resources/database-recovery-public.pem \
  --private-output F:/project/database-recovery-vendor-private.pem
```

公钥随应用发布，私钥保存在厂家受控目录并单独备份。更换密钥后必须同步更新 `recoveryKeyId` 和客户发布包中的公钥。

## 限制

- 只有已登录的出厂账号可生成请求或导入响应；店长、店员、自助注册端和游戏端没有入口。
- 旧备份只有 DPAPI 信封时，仍可在原 Windows 用户环境导入；不能生成跨系统请求，需先在原环境成功备份一次。
- 恢复过程中若有游戏、排队或其他营业流程运行，系统拒绝操作；中断时下次启动按导入状态回滚，不使用半套文件。
