## Context

`apps/registration-kiosk` 当前是 Vue 3/Vite 的占位页，没有流程状态、表单组件或触屏交互。用户提供的 7 张参考图定义了一条传统自助机流程：首页选择功能、输入手机号、填写注册信息、选择头像、刷手环、查看成功结果并返回首页。

主要使用场景是 16:9 横屏触控一体机，用户可能站立操作，输入依赖屏幕软键盘。页面需要比普通 Web 表单更大的触控目标、更明确的步骤反馈，并在软键盘出现时保持当前字段和主要操作可见。本 change 只建立可完整演示的前端 UI，不连接真实会员、相机或读卡器。

## Goals / Non-Goals

**Goals:**

- 将 7 张参考图对应的激活流程实现为一条清晰、可返回、可重置的触屏 UI 流程。
- 为手机号、姓名和日期等输入提供适合触控的屏幕键盘与明确的焦点状态。
- 建立头像来源选择和内置头像库的完整交互，并将选择结果回填资料页。
- 用蓝青色科技感视觉语言还原自助机氛围，同时提升原参考界面的层次、对比度和可读性。
- 将硬件与业务集成限制在可替换的模拟动作边界，便于后续接入真实服务。

**Non-Goals:**

- 不查询手机号对应的真实会员，也不保存注册资料。
- 不调用摄像头、不拍摄照片、不请求相机权限。
- 不监听或写入真实 IC 手环，不接入读卡器 SDK、串口或 WebUSB。
- 不实现 `Player Info Query` 的后续查询流程。
- 不增加登录、管理员入口、营销内容、支付或其他非激活流程。

## Decisions

### 1. 使用有限状态机表达页面与弹层

主流程使用 `home`、`phone`、`register`、`swipe`、`success` 五个页面状态；头像来源和内置头像库作为注册页上方的 modal 状态，软键盘作为当前输入字段关联的 overlay 状态。页面跳转只由明确的 `Back`、`Next Step`、确认、模拟刷卡和 `Return Home` 动作触发。

这种结构能防止多组布尔状态组合出不存在的页面，并让返回和重置行为可预测。备选方案是引入完整路由，但该流程不需要 URL 深链，且路由会增加 kiosk 会话恢复复杂度。

### 2. 将流程数据集中保存在单个前端会话模型

会话模型包含 `phone`、`name`、`birthday`、`gender`、`avatarId` 和模拟手环状态。离开某一步再返回时保留当前输入；点击 `Return Home` 时将模型、错误、键盘和弹层全部恢复为初始值。不得写入 `localStorage` 或发送网络请求。

这样既可演示完整流程，也能明确“刷新或返回首页即重置”的 UI-only 边界。未来接入服务端时可将手机号确认、注册提交和手环激活替换为独立 action。

### 3. 软键盘按字段类型切换布局

手机号和生日使用数字键盘；姓名使用字母键盘。键盘以屏幕底部面板出现，提供输入键、退格、清空、空格（字母布局）、关闭和完成操作。当前字段保持高亮，页面内容在键盘打开时上移或压缩，不能被面板遮挡。

同时保留物理键盘输入能力，便于开发与无障碍测试。备选方案是完全依赖系统触屏键盘，但浏览器 kiosk 环境的系统键盘行为不可控，无法稳定还原参考图。

### 4. 注册表单使用明确的触屏分组与就地校验

注册页按 Avatar、Name、Phone Number、Birthday、Gender 排列。手机号从上一步带入并允许修改；生日使用年/月/日三个可聚焦数字字段；性别使用大尺寸单选项。`Next Step` 仅在必填内容合法时进入刷卡页，错误直接出现在对应分组附近，并将焦点移回首个错误字段。

备选方案是分成多个更小页面，但参考图和用户要求都期望资料在一个界面完成，因此保持单页表单。

### 5. 头像选择采用两层短流程

点击 Avatar 旁的编辑按钮后显示来源面板：`Set from Library` 进入全屏/大尺寸头像网格，`Take Photo` 显示“Camera is not connected in UI demo”反馈并保持在资料页。头像库包含多种外观的本地预置头像，选中项显示清晰边框和勾选标识；`Confirm Avatar` 回填，`Cancel` 不改变原选择。

预置头像使用仓库内本地 SVG 或等效的代码原生素材，不依赖远程图片，保证 kiosk 离线展示稳定。

### 6. 刷手环页面使用显式模拟边界

刷卡页的主视觉是手环感应区域、环形脉冲动画和 `Waiting for wristband…` 状态，顶部或侧边展示玩家名称与头像。由于不接硬件，页面提供清楚标记为 `Demo · Simulate Successful Swipe` 的测试操作；触发后短暂显示 `Wristband detected`，再进入成功页。

不采用自动定时成功，因为自动跳转会让用户误以为读卡器已经工作，也不利于测试等待状态。

### 7. 成功页完成闭环并展示规定时长

成功页展示 `Activation Successful`、成功图形、玩家摘要和 `60 min` 有效时长。`Return Home` 是唯一主操作，触发后清空会话并回到首页，确保下一位用户看不到上一位用户的信息。

### 8. 视觉与布局以横屏触控为核心

采用深海军蓝至蓝紫渐变背景、青色能量光、细网格纹理、半透明科技面板和少量扫描/脉冲动画。主按钮、卡片和键盘按键的最小触控尺寸不低于 48 CSS 像素，核心操作更大；正文使用高对比浅色，非关键信息降低亮度而非缩小到不可读。

在 16:9 大屏中保持内容居中且不无限拉伸；较窄横屏减少间距与列数；竖屏或极窄屏显示旋转设备提示或转换为可完成任务的单列布局。动画尊重 `prefers-reduced-motion`。

## Risks / Trade-offs

- [软键盘占据大量垂直空间] → 根据键盘状态压缩标题和面板间距，滚动或上移当前字段，持续显示完成/下一步操作。
- [参考图较模糊且视觉元素年代感强] → 保留蓝青科技氛围和页面结构，不逐像素复刻噪点、复杂斜角或低对比文字。
- [模拟刷卡可能被误认为真实硬件] → 将测试操作标记为 `Demo`，等待页和成功页均显示“UI simulation”提示。
- [内置头像数量过多影响首屏与资源体积] → 首版使用约 18–24 个轻量本地头像，网格可滚动但主要操作固定可见。
- [返回首页时残留上一位用户资料] → 通过单一 `resetSession` 动作同时重置模型、校验、软键盘、弹层与步骤状态。
