# 数据库异盘备份真实双硬盘验收清单

本文只保留必须依赖真实硬件、无法由普通自动化测试可信替代的人工验收。其余数据库一致性、版本追赶、导入权限、失败回滚、历史清理和环境隔离由自动化测试负责，不再要求人工重复操作。

## 验收准备

- 使用装有两块独立物理硬盘的 Windows 测试机；不能用同一硬盘的两个分区代替。
- 使用打包后的会员管理端以及名称、手机号明显属于测试用途的数据。
- 禁止拿唯一一份真实营业数据库做破坏性试验。
- 设置 `LEDGAME_DATABASE_BACKUP_ENVIRONMENT=TEST`，并将 `LEDGAME_DATABASE_BACKUP_ROOT` 指向第二块物理盘上的独立测试目录，例如 `E:\LEDGameBackupTest\member-admin\20260903-验收`。
- 保存应用版本、测试时间、主数据库路径和本次测试备份根目录。

## 必须人工验收

### 1. 真实异盘证明

1. 启动会员管理端，完成一次测试会员注册或手环充值，等待备份成功。
2. 执行：

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts/verify-database-backup-hardware.ps1 `
     -DatabasePath "<platform.db 的绝对路径>" `
     -BackupRoot "<本次测试备份根目录>"
   ```

3. 保存脚本完整输出。

通过标准：

- 源库和备份库的 Disk Number 不同。
- 目标盘是本地、固定、可写的物理磁盘。
- 元数据环境为 `TEST`。
- latest 通过 SQLite 完整性、SHA-256 和隔离复制校验。

### 2. 物理拔盘与重新接入

1. 确认当前备份成功后，物理断开目标硬盘。
2. 在目标盘离线期间提交一笔测试充值。
3. 确认充值仍然成功，会员管理端持续显示备份不可用，并提示检查硬盘连接或目标盘。
4. 重新接入同一块硬盘，不手动选择备份目录。
5. 等待系统自动恢复备份，再查询主库与 latest。

通过标准：

- 拔盘不阻断已经成功的营业事务，也不会导致应用无响应或退出。
- 故障期间不会静默显示为“已保护”。
- 重新接入后自动识别原物理盘，latest 最终追平主库 revision，并包含离线期间提交的数据。

### 3. 真实盘符变化

1. 正常关闭会员管理端。
2. 在 Windows“磁盘管理”中修改目标硬盘盘符。
3. 重新启动会员管理端并提交一笔测试数据。
4. 再次运行异盘证明脚本。

通过标准：

- 系统按物理身份找到原目标盘，不要求重新选择目录。
- 不能误选源数据库所在物理盘的其他分区。
- 新盘符下的 latest 能追平主库，并通过完整性和哈希校验。

### 4. 真实突然断电

1. 确认已有一份有效 latest。
2. 提交一笔测试充值，在界面确认业务提交成功后立即切断测试机电源，不执行正常关机。
3. 恢复供电并重新启动会员管理端。
4. 检查刚才的业务数据、启动检查结果和最终 latest。

通过标准：

- 已经返回成功的业务数据仍存在于主库。
- 若断电前尚未完成备份，重启后能够识别主库领先并自动追赶。
- 主库和 latest 均通过 SQLite 完整性检查，最终 revision 一致。
- 如果硬件或文件系统确实造成损坏，程序必须明确阻断并提示，不能用损坏文件覆盖上一份有效 latest。

## 可以自动化但尚未覆盖

当前没有已知且有必要补充的自动化缺口。以后发现新的可重复软件场景时，应先加入自动化测试，不增加人工清单。

## 已补齐的高层自动化验收

- 最终打包产物首次启动：实际观察独立检查窗口，确认无导入入口，并验证首次 TEST 备份和管理界面状态。
- 最终打包产物强制终止：提交业务后用 Windows 结束 Electron/Java 进程树，重新启动并验证数据存在、revision 追平。
- 空间不足和不可写目标：用磁盘拓扑及文件系统故障注入验证错误码、中文建议、营业可用和旧 latest 保护。
- 重装空库导入：使用两套临时 `userData` 完整验证维护登录、候选显示、取消、确认导入和重新登录。
- 导入进程中断矩阵：在回滚副本已保存、主库已发布、等待启动复验三个节点强制结束真实 Node 子进程并验证恢复。
- 候选账号异常矩阵：覆盖无出厂账号、出厂账号停用、多个启用账号，以及 API、IPC 和界面权限边界。
- 最终打包产物退出和单实例：验证托管 Java 退出、端口释放、立即重开和重复启动不产生第二个后端。

上述打包版验收由 `pnpm test:desktop:member:packaged` 重新构建 `win-unpacked` 后执行；快速桌面测试由 `pnpm test:desktop` 执行，服务端测试包含在 `pnpm test:server` 中。

## 已由自动化测试覆盖，不需要人工重复

- 首次备份、提交后有界追赶和连续写入不会无限推迟备份。
- 正常关闭 flush、仅备份已提交事务。
- latest 的 SQLite 完整性、SHA-256、元数据和旧 latest 保护。
- 同一物理盘其他分区排除、目标盘物理身份保存和模拟盘符变化。
- 目标掉线降级及重新发现后的自动恢复逻辑。
- 主库损坏阻断、主库/备份 revision 和数据库身份冲突判断。
- TEST/PRODUCTION 隔离、环境不符文件隔离和“保留当前主库”。
- 营业中拒绝导入、候选库校验、导入 revision 提升和原子替换回滚。
- 每日历史快照、保留期清理以及 latest 不被历史清理删除。
- 出厂账号权限与备份管理接口只允许本机访问。

## 人工验收结论

以上 4 个“必须人工验收”场景全部通过，并保存脚本输出及关键截图后，才能确认真实双硬盘环境验收通过。自动化缺口应作为后续测试任务处理，不增加日常人工回归负担。
