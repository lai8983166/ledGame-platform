# 游戏编辑器特效功能实现指南

## 1. 功能定位

编辑器“特效”是前端的帧生成工具，不是后端运行时特效系统：

```text
填写参数 -> 预览移动动画 -> 点击确定 -> 生成普通 Frame
         -> 外层保存游戏 -> 写入 game.levels
```

保存后不再保留特效对象，后端只能看到普通 `frameList`。

## 2. 配置状态

```json
{
  "color": 2,
  "start": { "x": 0, "y": 0, "vx": 1, "vy": 1 },
  "end": { "x": 0, "y": 35, "vx": 1, "vy": 36 },
  "spirit": null,
  "width": 1,
  "height": 1,
  "cellSize": 10,
  "step": 1,
  "isMerge": true,
  "useSpirit": false
}
```

| 字段 | 作用 |
|---|---|
| `color` | 精灵类型：0 绿、1 蓝、2 红、3 紫 |
| `start.vx/vy`、`end.vx/vy` | 界面坐标，从 1 开始 |
| `start.x/y`、`end.x/y` | 内部坐标，等于界面坐标减 1 |
| `useSpirit` | 是否移动已有精灵 |
| `spirit` | 已有精灵；使用精灵模式必须选择 |
| `width/height` | 矩形模式的宽、高 |
| `step` | 每个生成帧的跳跃距离，UI 最小值 0.1 |
| `isMerge` | 写入当前帧序列的模式 |
| `cellSize` | 仅用于预览缩放，不保存到关卡 |

## 3. 面板控件

### 3.1 场地大小

只读显示当前场地尺寸，用于限制坐标、矩形和精灵的最大位置。

### 3.2 模式

#### 在当前帧之前插入

源码值为：

```text
isMerge = false
```

源码在当前帧索引处插入 `N-1` 个空帧。由于数组插入位置就是当前索引，这些空帧位于原当前帧之前；随后特效从当前索引开始写入 `N` 帧。

实际结果是：

```text
特效帧 0
特效帧 1
...
特效帧 N-1（原当前帧所在位置）
```

原当前帧被向后移动，但它所在位置会收到特效最后一帧，因此原内容不会完整保留。

如果新项目要求“严格在当前帧之前插入并保留原帧”，应插入 `N` 个新帧，并让原帧整体后移。

#### 在当前帧开始覆盖

源码值为：

```text
isMerge = true
```

实际行为：

1. 不预先插入帧；
2. 从当前帧开始写入特效；
3. 依次写入当前帧和后续帧；
4. 后续帧不足时追加新帧；
5. 通过 `pushSpirit()` 添加精灵。

因此“覆盖”实际是叠加，不会删除当前帧原有内容。若要真正覆盖，应先删除冲突内容再写入。

### 3.3 颜色

颜色表示编辑器精灵类型，不是符号灯协议颜色，也不是直接发送给硬件的 RGB。

```text
0 = 绿，1 = 蓝，2 = 红，3 = 紫
```

使用已有精灵时，选择列表只显示同颜色精灵。

### 3.4 使用精灵和大小

`useSpirit=false`：根据 `width × height` 生成实心矩形，再拆成多个 1×1 精灵。

`useSpirit=true`：选择已有精灵，保持原点阵形状整体移动；此时不使用 `width/height`。

### 3.5 起点和终点

界面坐标从 1 开始，内部计算使用零基坐标：

```text
(1,1) -> (0,0)
```

矩形模式的最大内部位置：

```text
maxX = siteWidth  - width
maxY = siteHeight - height
```

已有精灵模式把 `width/height` 换成所选精灵的宽高。

起点和终点相同会使轨迹距离为 0，旧代码会除零，必须在新实现中拦截。

### 3.6 跳跃距离

```text
step = 1   -> 通常每帧移动 1 格
step > 1   -> 跳过中间格，帧数减少
step < 1   -> 位置可能重复多帧，移动变慢
```

必须校验 `step > 0` 且为有限数，不能只依赖输入框的最小值。

## 4. 右侧预览

### 4.1 播放方式

预览使用独立 Canvas 定时器，源码约每 300ms 更新一次：

1. 清空画布；
2. 根据当前计数器计算位置；
3. 绘制矩形或精灵；
4. 计数器加 1；
5. 到达终点后从第 0 帧重新播放。

预览 300ms 只是编辑器预览速度，不代表游戏实际速度。游戏运行约每 25ms 取一个虚拟帧，实际停留时间还受 `repeatTimes` 影响。

### 4.2 参数变化后的重播

每次有效设置变化都应：

```text
停止旧预览定时器
重新把界面坐标转换为内部坐标
创建新的 Effect 对象
从第 0 个位置重新播放
```

需要监听：

```text
isMerge、color、useSpirit、spirit、width、height、
start.vx、start.vy、end.vx、end.vy、step
```

原前端显式监听了颜色、坐标、精灵、宽高和 `step`；`isMerge`、`useSpirit` 依赖对象监听，存在监听不完整风险。新实现应使用深度监听或统一的 `onConfigChange`。

关闭面板时必须停止预览定时器。

### 4.3 预览与生成共用算法

预览和最终写帧必须调用同一个轨迹计算器，否则会出现预览位置与点击确定后生成位置不一致。

## 5. 轨迹算法

设内部零基坐标为：

```text
dx = endX - startX
dy = endY - startY
D  = max(abs(dx) / step, abs(dy) / step)
```

第 `k` 个生成帧的位置：

```text
x = startX + floor(dx / D * k)
y = startY + floor(dy / D * k)
```

生成循环上限：

```text
limit = D + ceil(1 / step)
for k = 0; k < limit; k++
```

该算法是带 `floor` 的离散直线，没有缓动、旋转、透明度、缩放、粒子或声音。

## 6. 精灵和 UID

### 6.1 已有精灵

每帧修改同一个精灵的位置：

```text
spirit.setXY(x, y)
```

连续帧使用同一个 UID。

### 6.2 矩形

矩形会拆成多个 1×1 精灵：

1. 第一帧为每个小格生成 UID；
2. 后续帧按数组位置复用 UID；
3. 每帧把这些精灵加入对应 Frame。

## 7. 点击“确定”的写帧流程

“确定”按钮不调用后端接口，只修改当前编辑器内存：

```text
校验参数
计算 limit
根据 isMerge 决定是否插入空帧
for k = 0 .. limit-1:
    计算第 k 帧位置
    生成矩形或移动已有精灵
    push 到目标 Frame
刷新编辑器画布
关闭特效面板
```

新追加的帧使用当前关卡的 `frameDefaultRepeatTimes`。

“取消”或关闭按钮只关闭面板并停止预览，不写入当前关卡。

## 8. 数据库保存

特效参数本身不会写入数据库：

```text
不会保存 effectsConfig
不会保存 start/end/step
不会保存 isMerge/useSpirit
不会保存 effectDefinition
```

点击特效“确定”后，生成的内容已经变成普通帧。只有点击游戏编辑器外层保存按钮，才会调用：

```http
PUT /game/{id}
```

新建游戏使用：

```http
POST /game
```

前端把普通帧转换成：

```json
{
  "matrix": [
    [3, 5, "spriteUid", {"color": 2, "points": [[0, 0]]}]
  ],
  "repeatTimes": 1
}
```

然后将关卡列表 JSON 字符串化写入请求的 `levels` 字段，后端最终保存到：

```text
game.levels
```

准确说法是：

```text
点击确定：写入编辑器内存
点击外层保存：普通帧写入数据库
重新打开：只能恢复普通帧，不能恢复特效参数
```

## 9. 推荐实现结构

```text
EffectConfig
  参数、坐标转换和校验

EffectPreview
  停止旧播放、从头播放新轨迹

EffectGenerator
  把配置展开为 Frame[]，处理 UID 和边界
```

统一参数变化入口：

```text
onConfigChange(config)
  -> validate
  -> stopPreview
  -> new EffectPreview(config)
  -> playFromStart
```

点击确定：

```text
validate
  -> EffectGenerator.generate
  -> 按模式插入/合并到当前关卡
  -> 等待外层保存接口
```

## 10. 必须修正的问题

1. 起点等于终点时禁止除零，或生成单帧静止效果。
2. `step` 必须大于 0 且为有限数。
3. `useSpirit=true` 时必须选择精灵。
4. 所有配置字段变化都要重新播放预览。
5. “在当前帧之前插入”应保留原当前帧，不要让特效终点污染它。
6. 明确“覆盖”是叠加还是替换，不能用 `pushSpirit()` 冒充真正覆盖。
7. 如需再次编辑轨迹，额外保存 `effectDefinition`，不能只保存 `frameList`。
8. 预览应尽量使用与运行时一致的 `repeatTimes × tickMs` 时间模型。
