## Why

会员管理端当前的房间卡片主要是静态信息，无法确认某个房间是否对应一台实际运行中的游戏桌面端，也无法及时反映游戏开始、排队和结束。现在需要建立以游戏桌面端 IP 为房间身份的长连接，让会员管理端能够可靠显示房间在线状态，并接收关键运行事件。

## What Changes

- 增加游戏桌面端主动连接会员管理端的 WebSocket 房间连接。
- 使用连接来源 IP 作为房间身份，并限制同一 IP 的有效连接数量。
- 支持连接建立、断开、重连和初始状态快照同步。
- 游戏开始、排队变化、游戏结束时，通过长连接推送房间事件。
- 会员管理端房间卡片改为显示真实连接状态、最近运行状态、当前游戏和排队数量。
- 增加事件序号或幂等标识，避免重连和重复发送导致状态回退。
- 第一阶段不包含积分同步、完整游戏记录推送、远程控制和设备自动发现。

## Capabilities

### New Capabilities

- `room-connection-management`: 管理游戏桌面端基于 IP 的长连接、在线状态、初始快照和关键房间事件。

### Modified Capabilities

- 无

## Impact

- 会员管理端后端：新增房间连接会话、事件接收和在线状态管理接口。
- 会员管理端 UI：房间 Card 改为使用真实连接状态和事件数据。
- 游戏桌面端 backend：新增 WebSocket 客户端、重连处理和房间事件发送。
- 游戏桌面端运行流程：在开始游戏、排队变化和游戏结束节点发送事件。
- 局域网部署：游戏桌面端需要能够主动访问会员管理端地址；房间 IP 应使用静态地址或 DHCP 保留。
