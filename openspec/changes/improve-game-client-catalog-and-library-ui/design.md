## Context

动机和 12 项范围见 `proposal.md`。现有 `App.vue` 在“游戏”旁常驻一个 select，并把语言作为单独页面；副屏和配置已有下拉导航，可复用其交互模式。游戏首页/列表共用 `GameListView.vue`。

分类与游戏已分别有 `display_order`。游戏已有 `PUT /games/display-order` 与 `game:reorder` IPC，分类尚无重排入口。`MediaPickerDialog.vue` 把现有媒体目录树 flatten 成平面列表；媒体库本身已经能展开目录。精灵已有 `color` 字段与列表返回值，但 `SpiritCreateReq` 不接收颜色、创建固定写 0，库预览和点阵编辑画布也没有按精灵颜色着色。

## Goals / Non-Goals

**Goals:** 复用现有组件、目录结果、排序字段和颜色编码，完成用户指定交互；保持刷新/重启后一致，异步失败不损坏顺序或草稿。

**Non-Goals:** 不建立通用插件、导航路由、拖拽、资源或主题框架；不重构玩法/SDK/会员业务；不改数据库结构、资源内容和色号语义；不升级多语种架构。精灵颜色选择仅扩展新增流程，既有点阵编辑不额外获得改色功能。

## Decisions

### 1. 主窗口导航只改变入口展示，不切换窗口职责

游戏按钮文案始终为 `nav.games`；用与配置/副屏一致的应用内下拉菜单承载首页、游戏列表，不把当前子选项拼在按钮上。选择选项时更新既有 `activeView` / `gameSection`，启动默认值保持 games/home。“进入游戏”直接移动到副屏入口之后，继续调用 `enterGameFlow()`，不修改 Touch/DebugPanel 打开方式。

语言使用主窗口独立 modal 状态，复用 `LanguageSelectionPanel` 和 `setApplicationLocale()`，不修改 `activeView`，不卸载当前页面。选择成功关闭；点击当前已选语言也关闭（不重复写入）；取消/Escape 不更改语言，持久化失败留在弹窗并显示错误。保持原有国旗、支持语种和语言同步机制。关闭后恢复触发按钮焦点，现有未保存编辑状态、选中游戏/分类、滚动位置不被重置。无需“先记住页面再跳回来”的路由或缓存机制。

### 2. 卡片外观与拖动柄采用局部改动

分类卡片整体采用约 2:1 横向比例，封面在上、名称在下，不再左右并排，也不额外展示进入提示；不能只给封面改比例而留下高大的外框。保留编辑按钮，右上角专用于拖动柄，两个操作不能重叠。名称区域为编辑按钮预留右侧空间，长名称允许换行。

游戏列表采用铺满可用内容宽度的响应式网格、适当增大的卡片最小宽度和间距，取消导致两边大量留白的固定上限；分类网格与游戏网格不继续共用把二者变成竖卡的规则。沿用现有赛博霓虹设计，不改封面源图。目标验收包括 1366×768、1920×1080、2560×1440，不能产生横向页面滚动或按钮挤压。

拖动柄默认不可见，仅悬停卡片右上角或键盘聚焦柄时显现。只在柄上启用原生 drag/drop；卡片正文仍负责打开游戏/分类，不把整个卡片设为拖动源。拖动期间保持柄和落点反馈，结束不冒泡成打开/编辑；放到列表外或原位置不保存。不引入拖拽依赖；只在排序计算确有复用时扩展已有 `catalogOrdering.js`，不封装“通用排序管理器”。

### 3. 落下后保存，持久化失败回滚

在落下时形成新 ID 顺序，调用保存并阻止重复提交；成功使用权威返回或重新读取的顺序，失败恢复拖动前顺序并展示原因。刷新、重新启动仍读取后端顺序，不用 localStorage 作为排序权威。

游戏排序继续走 `/games/display-order`。当前接口将未传 ID 附加在末尾，因此在分类/筛选/儿童模式等只展示部分游戏时，前端必须把可见 ID 的重排合并到完整目录的原槽位，再提交完整 ID 顺序，保持非当前展示游戏的相对顺序和位置不变。普通全列表直接提交全顺序，不改游戏可见性和分类归属。

分类补充 `PUT /game-categories/display-order`，请求 `{ categoryIds: [...] }`，返回按顺序排列的分类；通过现有 backendRequest 方式加一组固定 IPC/preload 方法。要求为当前所有分类 ID 的排列，重复、空值、未知或遗漏 ID 拒绝且不写部分结果，事务更新既有 `display_order`。并发新增导致集合变化时刷新再重试即可，不新增版本表、锁服务或事件总线。

### 4. 封面选择复用真实媒体目录树

`window.mediaLibrary.list()` 已返回目录 children 和文件相对路径。选择器保留树，按 accept 过滤文件并保留包含匹配后代的目录，展开/收起显示缩进。目录只能展开，不能作为封面确认；相同文件名用相对路径区分。保留现有当前值、预览、双击确认、取消、焦点和异步预览防串图机制。

共用选择器可让音频选择也获得目录层级，但不改变音频类型过滤或返回格式。继续保存现有媒体根目录下的相对路径，不扫描任意磁盘、不新增后端资源接口。

### 5. 图片清除入口和媒体预览范围明确隔离

逐项盘点 `GameInfoEditDialog`、`GameCategoryEditDialog`、`ApplicationSettingsView`、`GameGlobalConfigDialog`、`RankGameEditorView` 等入口，移除图片/GIF、应用图标、背景和待机画面的清除按钮；待机画面是图片/视频共用的视觉资源槽，同一清除按钮统一移除。仍可首次选择和替换，取消不能保存空值，现有空配置使用默认显示的行为保留。

不删除兼容 IPC/API、不批量清空旧资源，也不移除音频字段的清除、地砖画布清空、日志清除、密码输入清空。针对混合媒体表单按字段类型控制，不能简单删所有含 clear 的按钮。

媒体树的展开箭头与文件夹图标分离，用现有图标风格的本地 SVG/代码图形表示文件夹，避免把三角形本身当文件夹图标。媒体库图片预览最大缩放系数规定为 `0.5 * min(容器可用宽度 / 图片原宽, 容器可用高度 / 图片原高)`，保持比例居中；系数是线性尺寸的一半，不是面积减半或图片压缩。GIF 同属 image。只作用于媒体库图片预览，不影响视频/音频、封面卡片、封面选择器、编辑器预览、Touch 和副屏。

### 6. 精灵颜色沿用既有 0..3 编码

新增弹窗增加互斥颜色选择：0 绿色、1 蓝色、2 红色、3 紫色。默认继续为 0，不新增自定义 RGB。`SpiritCreateReq` 加可选 color 并验证范围，未提供时兼容旧调用为 0；`SpiritService` 保存所选值。已有 `Spirit` / 简化列表返回 color，无需迁移。

新增画布、既有精灵点阵编辑画布和库预览按实际 color 着色，尺寸、点位和编辑保存格式不变。既有精灵颜色不能因为一次点位保存被默认值覆盖；未知历史色号使用可辨识回退展示，不自动改数据。移除非基础精灵的“自定义” badge，仍保留 `basic` 与基础精灵标识。选用既有四色调色值；不建立独立颜色策略、转换器或精灵类型系统。

## Risks / Trade-offs

- [拖动触发卡片点击，或 hover 浮起造成落点抖动] → 区分拖动源和卡片动作，拖动中冻结影响布局的位移，测试取消及落下。
- [部分目录排序把其他分类/隐藏游戏推到末尾] → 合并完整顺序再提交，覆盖带隐藏项的排序测试。
- [去掉图片清除按钮误删音频或清空数据] → 按字段类型列入口清单，断言取消和保存前后旧值不变。
- [共用选择器改树影响音频选择/同名文件] → 使用完整相对路径作为 ID，回归图片和音频过滤、异步预览与确认。
- [语言 modal 导致编辑器失焦或丢草稿] → 不切换页面，不使用原生 alert/confirm，验证输入在关闭后能继续编辑。
- [精灵历史色号有异常] → 显示回退但不重写；0..3 创建校验独立于点位校验。

## Migration Plan

1. 先补纯排序、接口和组件/交互测试，再实施前后端局部修改。
2. 无数据库迁移，旧分类/游戏 display_order 和精灵 color 保留；新增颜色参数对旧调用兼容。
3. 完成游戏前后端测试、构建、本地化检查及窗口尺寸验收，再执行游戏端现有 portable 打包，更新 `release/win-unpacked` 与 ZIP。
4. 回滚只需还原游戏端应用版本，新增分类排序接口可以保留；不回滚或删除客户业务数据库、资源和已保存顺序。会员管理端、自助注册端无需重新打包。
