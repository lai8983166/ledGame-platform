## Context

自助注册端位于 `apps/registration-kiosk`，通过共享 `packages/api-client` 访问会员管理端 Spring Boot API。当前 Player Info 客户端只接受手机号，服务端 `/api/player-info` 也只按手机号查询；结果 DTO 已包含积分、排名、手环和近期游玩记录，但查询页面只提供手机号入口。自助端的顾客流程由 `App.vue` 维护，现有连接状态监听可以在断线时清理会话，但没有流程级倒计时或用户可配置的倒计时设置。

## Goals / Non-Goals

**Goals:**

- 在不改变注册、绑定和只读查询语义的前提下增加手环 UID 查询。
- 让 Player Info 页面明确展示服务端返回的积分排名和近期游玩记录，并保持查询只读。
- 为注册/绑定和 Player Info 顾客流程增加统一的倒计时、超时清理和首页恢复。
- 提供易于店员使用的设置弹窗，并将合法配置保存在自助端本地。
- 用明确的网络连接提示替换重复的离线文案。

**Non-Goals:**

- 不新增第三方登录、权限账号或远程配置中心。
- 不让自助注册端直接访问 SQLite；所有会员信息继续通过会员管理端 API 获取。
- 不在本次变更中重做会员管理端排行榜或游玩记录业务计算。
- 不把倒计时作为服务器会话超时；倒计时只负责终端 UI 流程回收。

## Decisions

### 1. Player Info 使用一个互斥查询契约

扩展共享 API 客户端和服务端 Player Info 契约，使请求必须在 `phone` 与 `wristbandUid` 中二选一。保留手机号参数的兼容调用，新增手环 UID 参数；服务端先解析唯一身份，再复用同一套会员、积分、排名、余额和近期游玩记录投影，避免为两种入口复制业务查询。

手环查询只接受当前仍绑定到有效会员的手环，并且只读，不触发激活、开始计时、重新绑定或状态修复。未知、未绑定、已归还或格式不合法的 UID 返回稳定的未找到/校验错误，前端将其显示为可理解的查询失败。

备选方案是新增一个独立的 `/wristband-info` 接口，但这会造成响应字段和错误处理分叉，因此不采用。

### 2. 前端以查询方式切换代替复制结果页面

Player Info 输入页增加“手机号/手环”方式选择和对应输入框，`playerInfoFlow` 接收一个统一的查询对象。成功后继续使用同一结果页，结果页增加明确的积分排名和近期游玩记录区域；返回首页或超时时清空查询对象和响应，避免个人信息残留。

### 3. 倒计时采用一个受屏幕驱动的流程计时器

在自助端增加小型的流程计时状态：根据当前屏幕映射到 `activation`、`wristband`、`success`、`playerInfo` 等流程键，进入流程时按配置初始化剩余秒数，屏幕变化或返回首页时取消旧计时器。显示层只读剩余秒数，不直接操作业务状态；归零时调用现有的会话重置/读卡取消路径。

默认值采用适合触屏操作的安全值（激活流程 60 秒、刷环 45 秒、成功页 30 秒、信息查询 60 秒），范围限制为 10–600 秒。设置窗口允许分别修改这些值，所有值通过本地存储原子写入；非法值保持旧配置并显示字段错误。

备选方案是为每个按钮单独写 `setTimeout`，但会在异步请求、读卡弹窗和返回按钮之间产生竞态，因此不采用；计时器只在顶层流程状态上维护，并在所有离开路径统一清理。

### 4. 离线提示由连接状态统一生成

离线遮罩只保留一条明确的网络诊断文案：会员管理端网络连接出现问题，请检查网络连接。恢复连接后清除该错误；不再额外拼接“服务暂时不可用，请稍候”等泛化句子。API 请求失败仍可在当前步骤显示具体错误，但不能覆盖连接状态的根因提示。

### 5. 测试覆盖接口、状态机和用户可见文案

服务端增加手机号/UID互斥查询、未知 UID、已绑定 UID、只读不变更的集成测试；共享 API 客户端和 `playerInfoFlow` 增加两种输入的单元测试。自助端增加倒计时启动、重置、超时清理、设置持久化/校验和离线文案契约测试，并保留现有核心流程测试。

## Risks / Trade-offs

- [风险] 手环 UID 在数据库中可能存在多条历史绑定记录 → 查询只选择当前有效绑定，并对多条结果按最新有效绑定确定性处理。
- [风险] 顾客正在等待读卡或 API 响应时倒计时归零 → 超时动作增加会话版本校验，过期响应不得恢复已清理的页面状态。
- [风险] 本地设置损坏导致计时器异常 → 读取时做字段级校验，任何非法或损坏配置回退到默认值并重新保存。
- [风险] 展示个人游玩记录造成隐私残留 → 返回首页、超时、断线和应用卸载流程都调用同一清理函数，不保留查询结果到远程或 URL。

## Migration Plan

1. 先扩展服务端和共享 API 客户端，保持旧的手机号查询调用可用。
2. 更新自助端查询入口、结果展示、离线文案和倒计时设置；旧用户首次启动使用默认倒计时。
3. 运行服务端集成测试与自助端单元/构建测试后再打包自助注册端。
4. 如需回滚，回退自助端包即可；服务端新增的可选 UID 参数不影响旧版手机号客户端。
