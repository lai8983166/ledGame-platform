## Context

会员管理端目前已有 `deviceId`、`roomId` 和游戏访问记录字段，但房间管理仍然是静态信息，不能确认游戏桌面端是否在线，也没有统一的房间运行状态来源。游戏桌面端 backend 已经拥有游戏生命周期和排队状态，因此应由它主动向会员管理端建立连接并推送房间事件。

部署环境是同一门店局域网。会员管理端通常运行在固定 Windows 主机上，游戏桌面端主动连接会员管理端可以避免配置入站端口。房间身份按用户决定使用连接来源 IP，因此门店应为游戏桌面端使用静态 IP 或 DHCP 保留。

## Goals / Non-Goals

**Goals:**

- 通过 WebSocket 长连接准确判断房间在线和断线状态。
- 使用服务端观察到的来源 IP 作为房间身份。
- 支持连接建立后的完整状态快照，以及游戏开始、排队变化、游戏结束事件。
- 处理断线重连、重复连接、重复事件和乱序事件。
- 让会员管理端房间 Card 显示实时在线状态和最新房间运行状态。

**Non-Goals:**

- 不在本 Change 中同步积分或完整游戏记录。
- 不实现远程启动、停止、配置下发或设备自动发现。
- 不增加业务层定时心跳；WebSocket 仅使用协议级 ping/pong 或 TCP keepalive 检测传输存活。

## Decisions

### 1. 使用游戏 backend 主动建立 WebSocket

游戏桌面端的 Java backend 负责连接会员管理端，Electron 不维护第二套房间协议。这样游戏生命周期、排队状态和房间连接由同一个运行时负责，避免 Electron 转发状态时出现分叉。

备选方案：由 Electron 连接并转发 backend 状态。该方案会增加一层代理和重连状态，不采用。

### 2. 使用来源 IP 作为房间主键

会员管理端在 WebSocket 握手时读取实际来源 IP，并以规范化后的 IP 查找房间。客户端声明的 IP 只能用于诊断，不能覆盖服务端观察到的 IP。一个 IP 同时只保留一个有效连接，新连接建立后旧连接被关闭或标记失效。

### 3. 关键事件采用消息推送，连接状态单独管理

连接负责 `ONLINE/OFFLINE` 生命周期，业务消息只在关键节点发送：`ROOM_SNAPSHOT`、`GAME_STARTED`、`QUEUE_CHANGED`、`GAME_ENDED`。连接建立或重连后必须发送完整快照，使服务端不依赖丢失的历史事件恢复状态。

### 4. 使用连接会话和递增事件序号

每次连接分配 `connectionId`/epoch。事件携带设备本地递增序号和事件类型；服务端只接受当前连接会话中的新序号，重复事件按幂等处理，旧事件不能覆盖新状态。必要时使用事件 ID 作为数据库唯一键。

### 5. 房间在线状态与运行状态分开存储

房间 Card 的在线状态来自连接生命周期；当前游戏、游戏状态和排队人数来自最后一条有效房间事件。连接断开只将房间标记为 `OFFLINE`，不会自动生成游戏结束事件，也不会修改会员余额或游戏记录。

### 6. 连接认证和最小权限

房间连接使用每台游戏桌面端的设备凭证进行认证。认证成功后，服务端仍以来源 IP 确定房间，不允许凭任意 IP 字段冒充其他房间。连接协议仅允许房间注册、状态快照和关键事件上报。

## Risks / Trade-offs

- [IP 变化] DHCP 重新分配会让同一台设备显示为新房间 → 门店使用静态 IP 或 DHCP 保留，并在管理端提供 IP 冲突/未知 IP 提示。
- [网络黑洞] TCP 连接可能在异常断网后延迟触发断开 → 使用 WebSocket 协议 ping/pong 或 TCP keepalive；不引入业务心跳消息。
- [事件丢失] 断线期间的关键事件可能无法送达 → 重连后发送完整 `ROOM_SNAPSHOT`，客户端保留事件序号；第一版不要求补发完整历史。
- [重复连接] 同一 IP 启动多个游戏实例 → 以连接 epoch 进行 fencing，只接受最新连接。
- [进程崩溃] 游戏端崩溃不会发送 `GAME_ENDED` → 房间会立即显示 OFFLINE，但最后运行状态仍保留为诊断信息，不自动结算。

## Migration Plan

1. 会员管理端新增房间连接会话和最新状态存储，同时保留现有静态房间配置。
2. 先部署兼容旧游戏端的会员管理端；没有 WebSocket 的设备显示为未连接。
3. 发布带房间连接客户端的游戏 backend，启动时连接并发送 `ROOM_SNAPSHOT`。
4. 观察连接、重连和 IP 冲突日志后，再将房间 Card 切换为真实连接状态。
5. 回滚时关闭新连接客户端即可，已有会员、手环和游戏数据不受影响。

## Open Questions

- 房间连接是否需要由管理员在会员管理端预先登记 IP，还是允许首次连接自动创建待确认房间？
- 每个门店是否需要为不同房间配置独立设备 Token？
- 房间 Card 是否需要显示连接断开原因和最后一次事件详情？
