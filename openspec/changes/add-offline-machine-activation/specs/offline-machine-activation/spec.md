## Purpose

为局域网部署的会员管理端提供简单可操作的厂家离线永久机器授权，使客户首次启动时可以复制机器码申请激活、粘贴激活码后继续使用，并保证授权不随业务数据库备份或导入转移，未授权请求具有明确原因。

## ADDED Requirements

### Requirement: 厂家具备独立 Windows 图形签发工具
厂家 SHALL 能在支持的 Windows x64 电脑上直接运行便携 exe，无需另装 Node.js、Java 或会员管理端；工具 MUST 复用既有激活码格式且不内置私钥。

#### Scenario: 厂家选择密钥并签发
- **WHEN** 厂家选择有效私钥 txt/pem 并输入客户机器码，点击生成
- **THEN** 输出可验证的永久激活码并允许一键复制，只记住私钥路径，不持久化私钥内容

#### Scenario: 输入变动或私钥不可用
- **WHEN** 修改机器码、取消文件选择，或所选私钥无效/文件已丢失
- **THEN** 输入仍可用，失败显示中文原因，不将旧结果误当成新签发结果

### Requirement: 首次使用必须完成离线机器激活
会员管理端 SHALL 在缺少有效本机授权时停留在激活界面，提供机器码复制、激活码输入框、粘贴按钮、激活、重试及退出，MUST NOT 进入营业登录流程或自动视为已授权。

#### Scenario: 全新安装或旧安装没有授权
- **WHEN** 应用启动且不存在有效本机激活文件，无论数据库是否已有会员
- **THEN** 展示申请激活说明和机器码，不开放业务界面
- **AND** 等待客户联系厂家期间不报服务启动超时、不反复启动后端

#### Scenario: 本机身份读取失败
- **WHEN** 无法取得有效本机身份
- **THEN** 显示明确的机器码读取失败及重试提示
- **AND** 不生成随机机器码或接受空身份授权

### Requirement: 厂家签发永久且可验证的激活码
厂家工具 SHALL 根据机器码生成含产品、格式版本、授权编号及签发时间的数字签名激活码；客户端 MUST 使用预置信任公钥验证完整性和本机匹配，不需要访问互联网或定期续期。

#### Scenario: 有效激活码提交
- **WHEN** 客户输入或粘贴厂家签发且产品、格式和机器码均匹配的激活码并点击激活
- **THEN** 验签通过且程序自动保存授权成功后显示激活成功，自动继续启动
- **AND** 以后正常启动自动校验，无需再次申请，改变日期不使永久授权过期

#### Scenario: 激活码不可信或不适用
- **WHEN** 激活码被篡改、来自不可信密钥、机器不匹配、产品不符、格式不支持、包含非法字符或长度超限
- **THEN** 拒绝激活并分别提示可理解的失败原因
- **AND** 不覆盖原有效授权，不删除或修改业务数据库

#### Scenario: 尚未提交或保存失败
- **WHEN** 用户仅粘贴但未点击激活、清空输入或退出，或目标授权目录无法成功写入
- **THEN** 不显示激活成功；保存失败显示文件保存原因
- **AND** 原有授权保持不变，窗口仍能获得焦点并继续操作

#### Scenario: 复制粘贴方便且不自动激活
- **WHEN** 客户使用 Ctrl+V 或点击粘贴按钮输入含空格、制表符、换行的完整激活码
- **THEN** 清理上述空白后仍可校验原签名，不改变大小写或猜测其他字符
- **AND** 不自动提交，客户点击激活后才执行校验与保存，不提供客户文件导入入口

#### Scenario: 空输入或剪贴板不可用
- **WHEN** 激活码为空，或用户点击粘贴时剪贴板无文本／读取失败
- **THEN** 给出明确提示且不能误显示成功，保留手动输入和 Ctrl+V 能力
- **AND** 不后台读取剪贴板、不记录完整激活码或无关剪贴板内容

#### Scenario: 重复提交有效激活码
- **WHEN** 同一本机有效激活码重复提交
- **THEN** 安全返回已激活或激活成功，不重复触发备份检查

### Requirement: 授权独立于业务数据库生命周期
授权 SHALL 存储在持久化目录中的独立文件，不随 SQLite 备份／导入移动；同一 Windows 安装中的 IP、网卡、端口或应用安装位置变化 MUST NOT 改变机器码。

#### Scenario: 升级应用或恢复业务数据
- **WHEN** 同机升级、导入旧库、恢复测试库或更改网络及端口配置
- **THEN** 原有效授权仍有效，数据库没有激活状态字段需要同步

#### Scenario: 重装应用或复制到其他系统
- **WHEN** 同一 Windows 安装重装应用后重新输入原激活码
- **THEN** 能恢复激活而无需重新签发
- **AND** 机器身份不同的电脑不能使用该激活码，重装系统导致身份变化时提示联系厂家重新申请

### Requirement: 后端以授权作为统一业务前置条件
后端 SHALL 独立验证授权，在未激活时拒绝除启动诊断、授权操作及必要退出清理外的业务请求；业务 HTTP 请求 MUST 返回 503 和 `PLATFORM_NOT_ACTIVATED`，并附明确中文提示，不得误报为网络或防火墙故障。

#### Scenario: 其他客户端或直接请求访问未激活中心
- **WHEN** 未激活中心收到登录、会员查询／注册、手环充值／绑定、开局或结算请求
- **THEN** 请求被拒绝且业务数据不发生变更
- **AND** 直接调用后端不能绕过窗口限制，健康存活不代表业务就绪

#### Scenario: 房间连接在激活前建立
- **WHEN** 游戏端尝试建立或使用能够改变中心业务状态的房间连接
- **THEN** 未激活中心不处理业务消息，明确返回或记录未激活原因

#### Scenario: 远程机器尝试管理激活
- **WHEN** 非本机来源请求激活详情或提交激活码
- **THEN** 请求被拒绝；激活码提交仅供本机启动界面使用且不要求先登录

### Requirement: 激活与备份和账号权限顺序衔接
应用 SHALL 按激活、备份检查、现有登录／维护流程衔接；激活 MUST NOT 自动赋予出厂账号权限或替代备份检查。

#### Scenario: 激活成功后数据库需要维护
- **WHEN** 激活通过但后续备份检查要求出厂账号处理
- **THEN** 继续原维护登录流程，不绕过账号权限，不重复触发备份检查

#### Scenario: 等待激活时退出
- **WHEN** 用户关闭激活窗口或点击退出
- **THEN** 应用正常结束其自行启动的后端，不遗留占用端口的进程
- **AND** 下次启动仍可正常进入激活流程

### Requirement: 发布包与自动化测试不得引入通用绕过入口
客户发布物 SHALL 仅包含可信公钥，不包含签发私钥或通用激活码；自动化测试 MUST 使用隔离依赖或本机有效授权，不得通过测试模式、环境变量或前端状态使正式包跳过激活。

#### Scenario: 构建客户安装包或源码包
- **WHEN** 执行发布校验
- **THEN** 确认没有正式／测试签发私钥、测试信任配置和免激活开关进入客户产物
- **AND** 正式公钥缺失或错误时明确失败，不自动生成新密钥替代

#### Scenario: 打包版并发测试启动
- **WHEN** 测试启动器指定本机有效授权并使用隔离 userData
- **THEN** 仅复制授权到测试目录，不更改原授权、正式数据库或正式备份
- **AND** 没有有效授权时明确报告无法开始业务验收，离线计划预览仍无需激活或网络
