## Why

门店人员需要使用固定手机号反复验证会员管理端和自助注册端的注册入口，但当前无法让已有会员退出活动会员集合，只能不断制造新会员。手环充时目前也依赖常驻输入区域，未形成与真实键盘式读卡器一致的“主动开始刷环—确认 UID—输入分钟数—提交或取消”操作会话。

## What Changes

- 将会员管理端运营总览的总会员数、今日新增、今日发卡、今日收款和房间概况改为读取真实服务端数据；今日收款暂按每成功充值 1 分钟计 1 元。
- 删除运营总览中的设备健康卡片，不再展示无法由当前系统可靠采集的模拟硬件健康数据。
- 将手环管理页调整为更紧凑的响应式 Grid 工作台，把充值、清除余额、流程提示和回收操作组织为并排卡片，同时保留完整手环列表。

- 在会员管理端会员详情中增加带确认步骤的“删除会员”操作，以软删除方式让手机号能够重新注册，同时保留历史绑定、游戏和积分记录。
- 删除前拒绝仍有 `READY`/`ACTIVE` 手环或运行中游戏的会员，避免静默丢弃有效时长或正在进行的会话。
- 让已删除会员从活动会员列表、Player Info、排行榜、绑定和游戏准入中消失；使用相同手机号重新注册时生成新的会员 ID 和独立积分生命周期。
- 将会员管理端手环充时改为按钮触发的分阶段弹层：先等待键盘式读卡器输入数字 UID 和回车，成功识别可充时手环后再输入分钟数或选择快捷分钟数，最后显式确认充值。
- 充值弹层支持在刷环阶段和分钟输入阶段取消；取消只关闭并清理本次 UI 会话，不创建手环、不改变状态、不写入分钟数。
- 为会员删除/重复注册和充值弹层状态机补充服务端 SQLite 集成测试、前端状态测试及核心流程回归。

## Capabilities

### New Capabilities

- `operations-dashboard`: 定义真实运营统计、充值流水计价和真实房间概况的展示规则。

- `member-lifecycle-management`: 定义会员软删除、关联状态保护、活动数据隐藏、手机号重复注册和历史数据保留规则。

### Modified Capabilities

- `wristband-core-flow-ui`: 将管理端手环充时要求改为显式刷环会话、刷环成功后的分钟选择以及无副作用取消。

## Impact

- 会员数据状态和 SQLite schema/migration。
- 平台会员删除、会员查询、注册、排行榜、Player Info、手环绑定与游戏准入接口。
- 会员管理端会员详情抽屉、删除确认交互和列表刷新。
- 会员管理端手环办理页面的充值入口、键盘式读卡器捕获、弹层状态及分钟输入。
- 服务端集成测试、管理端单元测试和核心流程验收脚本。
