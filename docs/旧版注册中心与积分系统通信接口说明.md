# 注册中心与积分系统通信接口说明

## 1. 地址与协议

本项目作为 HTTP 客户端，向注册中心发送 JSON：

```text
POST http://{consoleIP}:16668/dev/gameCallback
Content-Type: application/json
```

`consoleIP` 来自本项目数据库 `dict` 表的 `name=globalConfig, k=consoleIP`。端口 `16668` 和路径 `/dev/gameCallback` 写在代码中。HTTP 客户端超时为 20 秒；启动前校验额外透传 `x-language` 请求头。代码没有为这些请求设置认证头。

注册中心的实现未包含在本项目源码中；以下是**本项目实际发送和解析**的协议，不能据此推断注册中心内部的存储规则。

## 2. 固定回调协议

所有消息使用同一个地址，以 `cmd` 区分：

| `cmd` | 含义 | 发送时机 | 请求体要点 |
| --- | --- | --- | --- |
| `1` | 心跳 | 应用启动约 3 秒后开始，每 20 秒一次 | `{"cmd":1}` |
| `5` | 启动前批量校验令牌 | 普通 `/game/start` 启动前，同步调用 | `json.icList`、`json.isAdmin` |
| `2` | 游戏开始 | 游戏实际启动时，异步发送 | `gameId`、`gameName`、`json.icList`、`json.isAdmin` |
| `3` | 游戏结束／上报积分 | 游戏停止或结束时，异步发送 | `gameId`、`json.points`、`json.icList`、`json.isAdmin` |

请求体示例（字段名和层级按源码）：

```json
{"cmd":5,"json":{"icList":["CARD_001","CARD_002"],"isAdmin":false}}
```

```json
{"cmd":2,"gameId":386,"gameName":"Ranking","json":{"icList":["CARD_001","CARD_002"],"isAdmin":false}}
```

```json
{"cmd":3,"gameId":386,"json":{"points":[{"ic":"CARD_001","points":120},{"ic":"CARD_002","points":95}],"icList":["CARD_001","CARD_002"],"isAdmin":false}}
```

`points[]` 是 `PointsWithUser`：`ic` 为玩家卡号／标识（字符串），`points` 为该玩家最终积分（Java `long`）。具体积分由当前玩法 Handler 的 `getPoints()` 计算；例如 Default 和 Rank 的计算方式不同。注册中心收到的是**最终积分**，源码没有向该 HTTP 接口逐次推送实时得分。

### 启用条件与响应

- 心跳：只要配置了 `consoleIP` 就尝试发送。
- `cmd=5`：要求本机授权 `hasTouch`、配置了 `consoleIP`，并且全局配置 `launchMethod=2`。`icList` 为空或任意卡号以 `mock` 开头时跳过远端校验，直接返回本地成功。
- `cmd=2`：要求本机授权 `hasTouch` 且有 `consoleIP`；代码**没有**检查 `launchMethod=2`。
- `cmd=3`：要求本机授权 `hasTouch`、有 `consoleIP`，且全局配置 `launchMethod=2`。

仅 `cmd=5` 会解析注册中心响应，读取 `code`、`msg` 和可选的 `data`，并把它转换为本项目的 `AjaxResult`。`/game/start` 只有在 `code=200` 时继续；如果 `data` 非空，则尝试将每个元素按数组处理，并从下标 `1` 解析 `Token`。`Token` 包括 `type`、`endTime`、`durationMinutes` 等字段，用于检查使用时长。注册中心完整响应结构需要以原服务为准。

`cmd=1` 忽略响应内容；`cmd=2/3` 仅记录响应日志。它们没有按业务码确认成功，也没有重试或补发机制。因此“请求已发送”不能等同于“积分已被对方入账”。

## 3. 相关的双向接口

| 方向 | 接口 | 用途 |
| --- | --- | --- |
| 本项目 → 注册中心 | `GET http://{ip}:16668/dev/ping` | 在 `/config/pingConsole?ip=...` 中测试指定 IP；要求响应 JSON 的 `data` 为 `pong` |
| 本项目 → 注册中心 | `GET/POST http://{consoleIP}:16668{path}` | 本项目 `/console/forward` 代理接口；由请求的 `method`、`path`、`params` 或 `data` 决定具体请求，透传 `x-language` |
| 其他应用 → 本项目 | `POST /game/start` | 普通启动入口；先执行上述 `cmd=5` 校验，再启动游戏 |
| 其他应用 → 本项目 | `POST /api/startGame` | 独立 API 启动入口；可传 `notifyURL`，**不调用** `cmd=5` 校验 |

`/api/startGame` 的 `notifyURL` 是另一条可选链路：游戏结束后，本项目向该 URL POST `{"id":游戏ID,"success":是否成功,"results":[{"id":玩家ID,"points":积分}]}`。它使用 `id/results` 字段，和注册中心 `cmd=3` 的 `ic/points` 格式不同；两者不要混用。

本项目 HTTP 服务的主机和端口取决于实际部署配置，不能从上述注册中心固定端口反推。副屏／看板的实时数据使用本项目 WebSocket，属于另一条通道。

## 4. 复刻时需留意

`cmd=5` 是阻断式启动校验；`cmd=2/3` 是异步通知。原代码对 `cmd=2/3` 不校验业务响应，也没有重试。若积分必须可靠入账，建议为结束积分消息增加唯一流水号、接收确认和失败补发；这属于改进建议，**不是现有协议字段**。
