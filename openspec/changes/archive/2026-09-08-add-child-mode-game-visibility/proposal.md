## Why

会员管理端“功能开关”目前只有不持久化的演示项，无法真正改变门店游戏端行为。门店需要一个默认关闭、可统一控制所有已连接游戏端的儿童模式，并让游戏端在断线重连后仍以会员管理端保存的设置为准。

## What Changes

- 清除会员管理端“功能开关”页现有演示开关和“演示设置”说明，只保留真实的儿童模式开关。
- 在会员管理端 SQLite 中持久化门店级儿童模式，默认关闭，并提供读取、修改接口。
- 复用现有会员管理端与游戏后端之间的房间 WebSocket：连接时下发当前设置，开关变化时向所有在线游戏端推送，游戏端断线后按现有机制自动重连并重新同步。
- 游戏后端保存当前会员平台功能设置，并在儿童模式开启时从可玩游戏列表中隐藏受限游戏；当前受限游戏暂定为测试专用的 `simple-demo`。
- 已打开游戏选择页收到设置变化后刷新列表；如果刚被隐藏的游戏尚未启动，则不得继续作为新局选择。
- 为默认值、持久化、即时推送、重连同步、隐藏与恢复可见性补充自动化测试。

## Capabilities

### New Capabilities

- `store-child-mode`: 定义门店儿童模式的持久化、管理端操作、跨端同步及游戏可见性策略。

### Modified Capabilities

无。

## Impact

- `F:\project\ledGame-platform`：SQLite schema、功能设置 API、房间 WebSocket 下行消息、共享 API 客户端及会员管理端系统设置 UI。
- `F:\project\ledGame-backend`：房间连接下行消息处理、平台功能设置内存投影及可玩游戏列表过滤。
- `F:\project\ledGame`：运行时设置归一化、游戏选择页实时刷新及前端契约测试。
- 房间 WebSocket 新增向下兼容的可选设置字段和设置变更消息；旧游戏端会忽略未知字段，不影响现有房间状态上报。
