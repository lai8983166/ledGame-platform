# 圆灯倒计时与调试

适用于新版 Simple、Normal、Diffcult 共用编辑器，不适用于 Rank。

## 怎么使用

1. 在游戏编辑器打开「符号灯布局」，启用布局、设置四面墙灯数和布线起点/方向，保存。全部灯数为 0 时没有外围灯。
2. 在基础信息中选中要修改的关卡，勾选「圆灯倒计时」，设置最小/最大秒数（整数，`1 ≤ 最小 ≤ 最大 ≤ 99`），保存游戏。每关独立，新配置默认关闭。
3. 点击编辑器的「启动游戏」进入单页调试。未启动时按保存布局显示黑色外围灯；点击「启动游戏」后，方形符号灯显示倒计时，圆灯显示对应颜色。方形灯只显示，点击配套圆灯模拟按压。

| 操作/状态 | 结果 |
| --- | --- |
| 蓝色圆灯 | 点击重置倒计时，短暂变绿，播放得分音效；不增加游戏得分或会员积分 |
| 未按灯直到归零 | 变黄，只在开启生命限制时扣生命，每次归零扣一次；播放受伤音效 |
| 黄色持续约两秒 | 恢复蓝色，从最大秒数开始下一轮 |
| 点击绿色/黄色 | 不额外重置或扣生命 |
| 暂停 | 数字和生命保持，不接受圆灯点击 |
| 重试/换关/重新开始 | 依据相应关卡重新初始化灯状态 |
| 结算/结束/退出 | 清空灯色，停止扣时和受伤 |

初值在最小/最大区间分散并打乱。首次进入实际 RUNNING 满一秒才减数，开场动画不扣圆灯时间；不照搬旧版「最小值 1 开场立即受伤」的零延迟定时器细节。

只保存布局、不开启某关倒计时，该关仍显示黑色外围灯，不产生生命消耗。保存布局不会提前保存其他未提交的关卡草稿；进入调试可选择保存草稿或使用已保存版本。

## 通信边界

本次完成的是玩法、调试显示/输入和既有虚拟外围输出。旧源码存在 `UDPResponseFactory.getRGB()`，把外围灯编码替换到控制器对应端口；`SquareLightUtils.calcRGB()` 使用特殊数值表达数字/符号。但尚未确认新 SDK 外围编码和真实圆灯输入映射，暂未启用物理外围收发，普通地砖报文不变。不应将模拟验收解释为真实符号灯硬件验收。

## 既有调试接口扩展

`POST /engine/game/debug/command`，沿用现有 Electron `sendDebugCommand`：

```json
{"command":"circleinput","sessionId":"当前调试会话", "circleIndex":0}
```

`circleIndex` 是后端冻结布局的链路序号，不是墙号或前端 rows 下标。必须为当前调试会话且引擎为 RUNNING；缺失/过期会话、暂停、生产模式、错误玩法及越界序号不会修改业务。合法的绿/黄灯点击是无操作，不报误伤或重复扣生命。

既有运行状态增加 `peripheralLights`：`enabled/order/selectedRow/lights`。每个灯位包含 `wall/index/sequenceIndex/alignX/alignY/phase/remaining`；前端只显示此状态，不自行计时或修改积分。活动游戏始终使用启动时冻结的位置。

```text
pnpm test
node scripts/test-editor-debug-ui.mjs
node scripts/test-simple-editor-toolbar-ui.mjs
node scripts/test-circle-light-packaged.mjs
```

最后一项使用真实打包端及后端、复制种子库至 `.build/circle-light-packaged` 的独立目录；不访问日常数据库，不要求外围设备或会员管理端。
