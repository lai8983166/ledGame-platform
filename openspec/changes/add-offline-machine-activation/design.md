## Context

会员管理端已经通过 Electron 启动 Java 后端、展示 startup 窗口，并根据 `/api/system/startup-status` 决定进入登录还是备份维护。`StartupGate` 当前仅表示备份状态，`StartupGateInterceptor` 允许健康检查、登录和退出备份。授权必须先于这些业务放行判断，不能只隐藏主窗口。

数据目录由 userData 决定，数据库为其 `data/platform.db`；数据库导入会替换主库并重启后端。并发测试通过 `LEDGAME_USER_DATA` 创建独立目录。主架构历史规格有尚未同步的 MySQL、设备令牌描述，本次不据此重新引入已移除的设施。

## Goals / Non-Goals

**Goals:** 用一段可复制粘贴的激活码、一个厂家工具和现有启动窗口完成首次激活；客户不操作授权文件；明确未激活原因；隔离授权和数据库生命周期；便于测试且不把私钥带给客户。

**Non-Goals:** 在线激活服务器、续期、远程吊销、设备名额、短信、反调试、强防破解、硬件加密狗、其他两端独立激活。离线永久授权无法阻止旧版程序被继续使用，也不保证抵御管理员修改程序或克隆整套系统。

## Decisions

1. **单一 Windows 安装身份，不做多硬件加权匹配。** 后端从 Windows `MachineGuid` 的固定 64 位注册表视图读取，规范化后以产品标识和算法版本为前缀做 SHA-256，显示为带版本前缀的机器码。IP、MAC、安装目录、SQLite 身份和随机生成 ID 不参与。原值不展示或写日志。身份读取失败明确报错并允许重试，不退回随机码或空值。此身份绑定当前 Windows 安装，不承诺换电脑／重装系统／系统镜像克隆时的物理硬件唯一性；同系统重装应用可复用原授权。相比磁盘／主板多源组合，减少普通硬件维护导致的误失效。

2. **签名，不把共享密钥放到客户端。** 使用平台内置 Ed25519 签名／验签，固定算法，不接受激活码指定算法或公钥。激活码格式为 `LGACT1.<payload-base64url>.<signature-base64url>`，签名覆盖原始 UTF-8 JSON payload 字节，避免 Node／Java JSON 重排问题。payload 包含 `formatVersion`、固定产品 ID、机器码、授权编号和签发时间，永久授权不含到期时间。严格解码和验签后检查格式、产品及机器匹配；不根据本机日期使授权失效。输入清理前和清理后均限制总长度（例如 16 KiB）；只移除空格、制表符和换行（含 CR/LF），不改大小写、不猜测错字或删除其他非法字符。采用可复制的长码，不承诺六位／八位短码，不引入在线查询服务。

3. **自动落盘，不要求客户管理文件。** 激活码通过校验后，程序自动将授权保存到 `<userData>/activation/license.json`，与 `data` 和数据库备份目录分开；保存原始签名字节而非重排后重新解释的 JSON。后端启动自行验签和读取机器码，激活状态仅在进程内缓存，不信任渲染层 `activated=true`。提交先完整校验再同目录临时文件原子替换，成功落盘才更新状态；错误码、尚未提交或写入失败不得覆盖原有效授权。同一有效码重复提交应安全成功，但不重复触发启动检查。不做授权自动异盘备份；客户保留厂家发送的激活码，同系统重装后可重新粘贴。

4. **激活检查 → 备份检查 → 登录。** 复用 startup 窗口，等待人工激活不计入现有 45 秒后端启动超时，也不启动重试拉起循环。Java 可以启动并完成必要初始化，但自动备份启动检查在授权有效后执行；授权和备份状态分开组合，不能被备份 READY 覆盖。有效激活码提交后仅启动一次后续检查；备份维护仍按原规则要求出厂账号登录，激活不授予任何操作账号权限。关闭激活窗口走现有正常退出流程，不遗留占端口 Java。

5. **后端门禁复用现有入口。** 增加小型授权服务，并在现有 HTTP 门禁的业务判断前校验授权。未激活时除健康检查、启动状态、授权查询／激活码提交和必要退出清理外，登录及所有业务读写拒绝，返回 HTTP 503、稳定的 `PLATFORM_NOT_ACTIVATED` 和中文消息；详细授权原因放入启动／激活状态。房间 WebSocket 握手和能写业务状态的消息入口也检查，不只拦 MVC 请求。`/api/health` 可以存活正常，但须暴露未就绪信息，不能将健康等同于可营业。其他两端仍靠现有错误与重连流程处理。

6. **本机输入，无需先登录。** 后端提供最小 `/api/system/activation` 查询与激活码提交入口，受 loopback 来源限制；Electron 通过现有本机请求桥接提交激活码字符串，不接收文件路径。界面提供输入框、粘贴按钮和明确的激活按钮，支持 Ctrl+V；只在用户点击粘贴时读取剪贴板，不后台监听或自动提交，读取失败／空内容时提示并保留手动输入能力。客户端和后端按相同规则清理空白，空码拒绝提交，失败保留输入并恢复焦点，重复点击期间防止并发提交。移除客户文件选择和导入入口，不使用原生 alert/confirm。激活不要求先登录，与数据库导入仅出厂账号可用的规则无关；不记录完整激活码或无关剪贴板内容。

7. **厂家工具独立交付。** 首版命令行工具提供生成密钥对和生成激活码两项操作；签发时输入机器码，输出可直接复制发送的一行激活码，不要求客户接收授权文件。私钥路径明确指定，密钥输出已存在则拒绝覆盖。正式密钥由厂家在仓库外保管并备份，不能每次构建重生成；客户构建只读取公钥。打包与源码导出通过明确排除规则和自动扫描验证，不依赖只改 `.gitignore`。工具代码可以审查，安全依赖私钥保密而非隐藏工具。

8. **测试使用相同机制，不增加可切换的免激活模式。** 单元／服务测试通过测试依赖注入使用临时密钥和机器身份，正式产物不可通过环境变量、查询参数或 JSON 开关换信任公钥／跳过验签。开发桌面版默认与打包版一致，申请一次本机开发授权即可使用。真实打包版自动验收在厂家已授权测试机器执行：启动器从显式输入路径复制该机有效授权到隔离 userData，该文件仅用于测试启动器预置程序内部授权，不是客户导入入口；原文件只读，不自动读取正式数据库或写入正式授权目录；没有授权时明确停止，而非无限等待。未激活和篡改场景使用无授权／无效文件隔离目录；正向发布版验收需要正式签发的测试机授权，不能由公开测试私钥激活正式产品。

## Risks / Trade-offs

### 追加：厂家图形工具

复用当前 Electron 与 electron-builder，新增独立 activation-signer 入口，输出 Windows x64 单文件 portable exe、win-unpacked 和 zip，不加入客户三端的默认打包任务。主进程动态导入现有 issueCode；私钥仅从厂家主动选择的文件读取，不返回渲染层、不复制进用户目录或发布包。设置只保存文件路径。图形工具不提供生成/替换正式密钥按钮，避免误换钥。更换机器码或签发失败清空旧结果；文件选择取消/失败后恢复输入焦点。测试使用临时密钥与隔离用户目录，实际运行打包 exe 验证内置运行时可用。支持 Windows 的范围与现有 Electron 相同，不宣称 macOS/Linux 可直接运行 exe。

- [MachineGuid 是系统安装身份而非不可复制的硬件身份] → 说明重装系统可能需重新申请、克隆系统可能共享身份；首版不建设复杂反克隆措施。
- [厂家私钥丢失或泄露] → 厂家离线备份，私钥与源码／交付目录隔离；泄露后的换钥属于后续受控升级，不承诺离线撤销已签授权。
- [客户首次升级新版被阻断] → 发新版前收集机器码并签发，说明旧数据不会因此删除；不自动把已有数据库视为授权证明。
- [长时间运行后外部删除文件] → 首版以启动和激活码提交时校验为准，不中断已经运行的游戏；下一次后端启动重新校验。
- [测试授权不足] → 未取得厂家测试机授权时报告正向打包验收未完成；不让测试通过标记掩盖发布门禁绕过。

## Migration Plan

1. 先完成临时密钥测试、厂家工具和授权校验，再接启动窗口及业务门禁。
2. 厂家在仓库外生成／保管正式密钥对，提供公钥用于正式打包，为验收机签发授权；这不是创建提案时生成生产密钥的授权。
3. 更新便携并发验收启动器及中文说明，验证导入数据库、升级、端口变化不影响同系统授权。
4. 客户上线前取得激活码；无数据库迁移。代码回滚可回到旧版，但旧版本身没有激活约束，不能声称回滚仍强制授权。
