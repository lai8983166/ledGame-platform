## Why

已有多点并发工具通过 API 验证中心数据库，不能证明游戏端打包应用在真实界面操作、游戏模式和长时间控制器通信中稳定。本次仅测试游戏桌面端及其自带后端，不启动会员管理端或自助注册端；以配置指定的游戏列表连续运行 18 小时，记录退出、卡死、内存趋势及可观测通信异常。

## What Changes

- 新增独立 `game-soak-acceptance` 测试模块，不把 UI 烤机流程混入 multipoint-concurrency；复用合适的进程管理、隔离目录和中文报告能力。
- 配置文件指定游戏端程序路径、目标游戏 ID 有序列表、人数、起始关卡、持续时间和硬件方式。严格按配置列表循环，不遍历未指定游戏；缺失、隐藏或不支持的游戏必须提前报错。
- Playwright 操作打包版真实界面，固定游戏模式 `game`、触屏启动 `touch`，依次点击待机、人数、游戏轮播、关卡、开始；等待自然结束，再点击“返回待机”。不得用 DebugPanel、直接开局 API、End Game 或跳关替代正常流程。
- 默认正式验收 18 小时，允许短时自测；每个目标游戏必须具有实际生效的有限全局时长，不修改用户游戏内容。无人踩踏也应自然结束，有人踩踏时按业务正常处理。
- 预留显式启用、默认关闭的模拟踩踏注入能力，复用规范化 DOWN/UP 输入通路；与真实输入分开记录，隔离按住/释放状态，不把模拟成功计为硬件成功。
- 区分无硬件开发验证与真实硬件验收；启动、就绪、证据和结论均记录实际方式，真实模式失败不自动切换模拟模式。
- 采集游戏端主进程、渲染进程及自有后端的身份/退出、窗口响应、每局生命周期、内存序列及通信计数；输出中文总结及可追溯证据，缺证据不得判通过。
- 以触屏独立游玩验证不依赖会员平台，不配置中心授权/数据库/备份，不测试会员积分和三端联动；平台离线不能误报为地砖控制器通信错误。

## Capabilities

### New Capabilities

- `packaged-game-soak-acceptance`：配置驱动的真实 UI 游戏循环、运行监测、受控模拟输入和分层验收结论。

### Modified Capabilities

无。会员积分、手环计时、游戏结束规则及既有并发验收标准不在本次变更。

## Impact

- `F:/project/ledGame-platform`：保留现有 Change 及独立测试工具的规划位置，复用测试基础能力；只承担测试主模块、便携命令行入口、隔离启动、监测和报告，不修改或启动会员管理端/自助注册端产品。
- `F:/project/ledGame`：现有游戏模式向导选择器核对/补齐、只读可观测性及独立测试启动配置；不改变正常结束后手动返回待机的产品交互。
- `F:/project/ledGame-backend`：复用生产形态测试就绪接口、规范化输入路径，补最小注入适配与真实通信可观测性。具体跨仓库改动需在对应仓库实施任务中落地，不借平台仓库范围修改其他仓库。
- 不增加云平台、数据库表、18 小时原始报文全量落盘或测试专用桌面 GUI；本次只是创建规划，不运行 18 小时测试。
