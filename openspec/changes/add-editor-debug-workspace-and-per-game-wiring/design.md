# Design

## Context

参见 proposal.md。现有 SimpleGameEditorView.startGame 与 RankGameEditorView.startTest 都以 SIMULATION 启动，随后调用 enterGameFlow 打开 DebugPanel/Touch；App 的调试窗口分支负责帧解码与状态监听，DemoView 使用 DebugLedCanvas。主窗口采用 activeView 切换，没有必要为了一个调试页面引入路由框架。

GameRuntimeService 已提供模拟输入和关卡结果等命令，GameEngine 有 RUNNING/STARTING/SETTLING 等状态，但没有用户暂停接口。GameContext 的 pauseTiming/resumeTiming 只用于现有关卡结算，不足以冻结 Stage、Rank 炸弹和媒体异步回调。暂停实现需要覆盖真实时钟和生命周期，不能只禁用前端点击。

Game.wiringData 已存在；Simple 编辑文档仅定义 cellSize/lines，Rank 编辑文档尚未暴露布线。ELC408 的输出映射、输入状态机及上游 TCP 帧尺寸来自全局 wiring.json。FloorGameHardware 是现有地砖玩法的硬件入口，逐游戏映射接入此处，不把硬件重新耦合进通用引擎。

现有主规范 game-access-entitlement 仍描述激活后持续计时，相关 RUNNING 扣时 Change 未完成；本次不得把“游戏暂停”宣称为“冻结购买余额”。现有平台规则及结算幂等约束保持不变。

## Goals / Non-Goals

**Goals:**

- 一个编辑器内调试页复用原玩法、帧、输入和会员准入，直接启动和多人真实手环启动在同页完成。
- 暂停后真正停止玩法推进，退出/重启可靠终止旧会话，返回时保留编辑器上下文。
- 每个游戏布线独立保存，并对该局实际 RGB 输出与踩踏坐标生效；旧游戏默认行为不变。
- 开发模式、打包模式行为一致，先补测试再实现。

**Non-Goals:**

- 不重写顾客 Touch 流程、引入第二套调试玩法、模拟手环 ID、增加投币调试启动或调试页排队功能。
- 不改变积分/计费策略、不增加会员管理端暂停计费 API、不修改自助注册端。
- 不逐游戏复制 conf.json 中的网卡/端口/型号，也不混用地砖布线与 pixelLightWiring 符号灯配置。
- 不立即删除所有旧 DebugPanel IPC；迁移编辑器入口后，仅清理确认无调用的代码，避免破坏既有脚本和烤机入口。

## Decisions

### 1. 主窗口内的调试工作区

新增共享调试视图，App 用现有视图切换挂载它。两类编辑器发出包含 gameId、当前关卡和返回编辑器类型的事件，统一处理；不新增 BrowserWindow。进入时是设置/待启动状态，选好直接/手环、人数与关卡后点击启动，避免打开页面就意外开始扣费。

未保存修改使用应用内确认，提供“保存并进入调试”“使用已保存版本”“取消”；保存失败留在编辑器。调试加载的游戏版本明确可见，不测试未落库的半成品。原编辑器保留实例或等价局部状态，退出回到原关卡/帧/滚动位置，不静默丢弃未保存草稿。不得使用 Electron 原生 confirm/alert 引入旧焦点问题。

页面左上为退出；左侧配置与数值，右侧 RGB。设置含启动方式、人数、起始关卡；关卡对用户从 1 起显示，提交仍转换成现有零基索引。运行/暂停后启动参数锁定。Rank 逐玩家显示颜色、得分，并对没有生命值等概念的玩法显示不适用；有限全局时间来自引擎实时状态，无限显示“无限”。游戏内得分与累计奖励积分分开展示。

复用 DebugLedCanvas 的帧渲染、正方形格子、ResizeObserver 与输入坐标算法。复用 onLedFrame/latestFrame、onEngineState 和 floorInput.js；初始化显示本游戏场地大小而不是固定 16×16，右侧完整适应可用高度，左侧单独滚动。提取必要的帧解码小函数，不创建通用可视化框架。

### 2. 一个真实引擎，两种准入方式

调试固定 SIMULATION，不从全局 entryMethod/mode 推导界面行为。直接启动不需要会员管理端；手环启动复用 preparation/create/update/select/confirm 与 MemberGameAccessCoordinator，使用真实 USB 键盘读卡数字＋回车，扫描监听只在主动刷卡状态生效，普通人数/关卡输入不被捕获。

多人刷卡继续遵守已选人数、手环/会员不重复、第一张成功后人数锁定、不足人数不能启动等现有规则。出错显示真实服务原因，不能伪造准入成功；取消准备释放该页的准入会话。SIMULATION 与 launchMethod=wristband 是两条独立维度，不能为了调试绕过会员结算。

复用现有无硬件模拟能力，配置可用且 SDK 已启动时仍能驱动真实地砖；无控制器/SDK 关闭不阻断 RGB 观察和模拟踩踏。如果应用存在其他运行/准备/排队任务，拒绝占用并提示处理原任务，不强行结束业务游戏或启动已有队列。页面只控制自己取得的准备/运行会话；复用 sessionId/runToken 做过期防护，不建立新的调试会话注册中心。

### 3. 后端调试暂停是生命周期操作

在现有调试命令中增加 pause/resume；只允许当前 SIMULATION 会话调用，重复命令幂等。运行状态显式包含 paused 和被暂停阶段，不能把暂停伪装成停止或成功结算。引擎锁下冻结玩法 tick 和输入处理，保留最后 RGB，不累计点击到恢复后再执行。

利用 GameContext、Stage 既有计时维护暂停偏移；核对 Simple 帧节奏/关卡时长与 Rank 刷新/炸弹存活/爆炸清除等时间来源，恢复后不得因墙钟跳跃瞬间扣命、过关或结束。不得引入通用时钟注入框架，仅补本次必要的活动时间取值与暂停边界。

STARTING 和 SETTLING 也接受暂停：媒体/地砖动画暂停，异步完成仅保留为待推进结果，恢复后再推进一次；暂停、退出、重启竞争均用现有会话与 runToken 防止旧回调推动新局。准备阶段尚未运行，不需要冻结玩法时钟。媒体播放控制只在现有媒体服务补必要能力，不改变正常游戏播放规则。正常 PRODUCTION 不接收模拟暂停命令。

手环购买余额仍按会员管理端当前策略变化，页面以返回的真实余额为准，不宣称暂停免扣费。这与待实施的 RUNNING 扣时需求分别处理，避免此 Change 顺带修改三端计费协议。

### 4. 重新开始与退出复用正常终止

重新开始先停止旧局，等待其正常清理/终止结算，创建新的准备会话，重新验证手环，再按本页设置启动；直接启动同理。新局分数、生命、奖励账本、时间、输入状态和媒体 owner 重置，旧局奖励不能被重加。如果会员平台暂不可用，沿用现有结算 outbox 的可靠性，不能前端重复上报补偿；重新准入失败则停留设置状态显示原因。

退出处理自己拥有的准备会话或游戏，等待清理成功后回编辑器；失败留在页面允许重试，不隐藏仍运行的游戏。自然结束留在调试页展示本局结果，可重新开始或退出。退出卸载帧/状态/读卡监听。副屏仍可观察同一引擎，但该入口不主动打开 Touch/DebugPanel；已有顾客界面不会因编辑器调试自动进入新流程。

### 5. 复用 wiringData，显式启用独立映射

复用 Game.wiringData JSON，不新建布线表或逐游戏文件目录。扩展编辑 DTO 支持 mode、maxPointsPerChannel、width/height 及布尔标记 runtimeEnabled；保留原 cellSize/lines。Rank 增加相同结构，保存/导入/导出不得丢失它。runtimeEnabled 仅在用户明确保存独立布线时设 true，缺省 false，防止旧种子/迁移数据中不完整 lines 被误认作实际配置。

复用 Elc408WiringPanel/Canvas 和纯函数，最小改为可传初值/尺寸、输出草稿/保存事件；全局工具继续有原下载/维护能力，游戏入口的保存只能写本游戏。场地尺寸来自编辑文档；宽高不能在布线工具中偷偷修改成另一套值。模式/通道/点位/每通道容量按现有协议校验，重复、越界、控制器通道非法需拒绝；未布线格子允许存在，输出按现有规则保持黑色，不能误映射。

首次打开优先已保存独立布线；没有则可复制尺寸兼容的全局配置作为本地草稿，若不兼容则给出该游戏尺寸的新草稿及明确提示，不能静默裁剪。取消不持久化；整体游戏保存时也校验布线与场地尺寸一致。新场地尺寸不兼容时提示用户调整/重绘，不截断旧点位。

### 6. 启动时在地砖玩法边界切换 SDK 映射

FloorGameHardware.prepare 从当前 gameId 取得启用的布线快照；没有 runtimeEnabled=true 时保持当前全局回退。在现有 Elc408RuntimeManager 中允许用校验后的内存布线重建 SDK、输入状态机和上游 TCP 帧尺寸，沿用全局 conf.json 的网卡、端口、型号、GRB 和搜索规则，不覆盖磁盘上的全局 wiring.json。

新映射校验通过、旧游戏输出 owner 已释放后才切换；输出映射与踩踏反向映射必须来自同一快照。关闭旧 SDK 和输入连接，避免旧搜索回复/踩踏事件进入新游戏，现有搜索结果不能被解释成“必须搜到配置数量的全部控制器”。启动失败恢复上一可用映射或保持明确不可用，不半切换。

SIMULATION 无设备时仍能运行；如果独立映射无法应用，真实硬件输出必须停用并显示原因，不能用另一游戏映射继续点亮。PRODUCTION 配置无效/硬件准备失败按现有失败规则拒绝启动。游戏结束恢复系统全局待机映射，编辑器修改布线仅影响下一次启动，不热改当前局。SDK 周期搜索、健康上报继续使用当前实例，丢弃旧实例结果。

## Risks / Trade-offs

- 暂停只停 scheduler 但异步媒体/炸弹时钟仍推进 → 分别测试 STARTING/RUNNING/SETTLING，长暂停后的恢复不得跳变。
- 旧 wiringData 包含示例单点 → runtimeEnabled 缺省关闭，不自动升级所有旧游戏为独立映射。
- 切换 SDK 时输出与输入短暂错位 → 同一经校验快照替换、旧连接清理、失败恢复和旧会话事件防护。
- 重新开始重复加积分或泄漏手环占用 → 复用正常终止/结算幂等、新准备身份和人数验证；多次点击禁重入。
- 手环调试改变真实会员数据 → 调试页明确显示真实会员身份与余额；自动化测试使用隔离平台数据库，不接用户库。
- 大页面或原生弹窗导致输入焦点回归 → 应用内弹窗、监听作用域、跨分辨率截图与键盘输入验收。

## Migration Plan

1. 先补隔离运行时、布线兼容和新页面测试，再修改产品代码。
2. 旧全局 conf/wiring 文件保持不变；wiringData 缺省继续全局，明确保存的游戏才启用独立映射。旧数据导入保留已有内容，不批量重写。
3. 编辑器入口迁移后保留需要的旧调试兼容入口和顾客 Touch/烤机能力；不以删除旧文件为验收目标。
4. 重新打包游戏端原 release/win-unpacked 与 ZIP，实际 EXE 用隔离数据冒烟，逐文件校验产物一致；不自动提交或归档。
