## A. 部署与基础设施

| ID | 问题 | 优先级 | 决策 | 备注/依据 |
|---|---|---|---|---|
| A1 | 部署形态 | 🔴 | **单门店独立部署** | 每家门店一套完整系统，门店之间不共享数据 |
| A2 | 应用架构形态 | 🟡 | **单体应用 + 包级模块** | 一个 Spring Boot 进程，内部按 package 切分；不微服务 |
| A3 | 中间件引入范围 | 🟡 | **仅 MySQL + Spring Boot 内置组件** | 不引入 Redis / MQ / K8s |
| A4 | 操作系统 | 🟢 | **Windows** | ⚠️ 影响：systemd 不可用 → 用 Windows Service 或 NSSM 做进程自愈；脚本走 PowerShell；定时任务用 Task Scheduler；路径用反斜杠 |
| A6 | 高可用等级 | 🔴 | **营业时段 RTO ≤ 10 分钟、RPO ≤ 24 小时**（≈99.5%） | 单实例 + 备份即可达标 |
| A7 | 数据库 | 🟡 | **MySQL 8.x** | — |
| A8 | 备份策略 | 🔴 | **每日全量 dump + binlog 增量；保留 30 天；每月一次恢复演练** | — |
| A9 | 备份存放位置 | 🔴 | **同机第二块盘** | ⚠️ 注：防误删/逻辑损坏有效；防硬盘物理损坏能力有限——靠每月演练兜底 |
| A10 | 旧系统数据迁移 | 🔴 | **无旧系统数据迁移** | 上线前无历史数据导入工作 |
