# Design

## Context

Touch 已有准备会话、多人手环准入、分类 CRUD、封面预览、轮播与 20 秒逐步超时；游戏模式原来只有 players/game/level/countdown。参考图用固定分类及示例数值，产品应显示真实数据。

## Goals / Non-Goals

Goals：拆分刷卡步骤并减少操作，按参考图实现可适配屏幕的展示；保持准备会话和真实手环结果为准。
Non-Goals：不新增准入 API、分类表、图像生成或另一套游戏启动链路。

## Decisions

- 增加 wristband 步骤，人数保存成功后才能转入；touch/coin 跳过。只在该步骤接受游戏模式刷卡，最后一位成功后自动进入游戏选择。复用原 runAction 错误恢复，避免失败/旧会话响应推动页面。
- 分类调用既有 listGameCategories，按 firstCatalog 过滤当前可见游戏。未分类游戏有实际兜底入口；无分类时可正常使用全列表。分类读取失败显示错误及重试，不用硬编码示例菜单。
- 轮播左/右及滑动保留，当前卡点击进入关卡，其他卡点击选中；原下一步可保留为确认所选游戏的快捷入口。分类切换在关卡页回游戏选择，不覆盖人数和已验证手环。
- CSS/SVG 内联科技边框实现参考图的中心刷卡提示、青色半透明面板、竖向分类和立体卡片；沿用真实背景与封面，刷卡页采用参考图的通用人物图标，姓名来自真实准入结果，不把整张截图做背景。
- 关卡 3 列，超多关卡只在关卡列表内滚动。显示全局游戏时间优先、生命遵守全局生命配置，Rank 继续第一关并显示实际持续时间。
- 新刷卡步骤加入原 20 秒倒计时；超时取消准备返回待机。重新选人数需取消原准备并创建新会话，避免已刷卡后改变人数或复用旧请求。

## Risks / Trade-offs

异步保存/扫码晚返回 → 以原 sessionId 与当前步骤检查流转。分类为空或缺少封面 → 兜底可见游戏和名称占位，不让顾客无游戏可选。不同分辨率 → 1366×768、1920×1080 与 1280×600 截图和滚动检查。原 UI 自动化定位变化 → 更新烤机点击以人数直接进入游戏为准。
