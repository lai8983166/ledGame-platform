## Why

现有会员管理端把充值金额和手环时长放在会员资料上，自助注册端也没有区分已有会员、未注册会员和未充时手环，无法准确表达门店真实的核心流程。当前需要先把两个 UI 收敛到一条可演示的最小闭环：店员给实体手环充入时长，顾客在柜台或自助端完成会员识别与手环激活，游戏时长在首次游戏刷卡后才开始计算。

## What Changes

- 在会员管理端增加以实体手环为中心的办理工作台，支持扫描/输入手环 UID、选择购买时长、完成模拟充时。
- 在会员管理端支持柜台激活：按手机号查询已有会员，或登记新会员，然后把已充时手环绑定到该会员。
- 在会员管理端增加手环状态列表，展示待激活、待开玩、计时中和已到期状态，并支持归还手环。
- 调整会员资料模型和页面，移除会员累计充值金额及会员自带手环时长，避免把本次手环时长错误归属到会员。
- 调整自助注册端手机号流程：已有会员直接确认身份，未注册手机号才进入资料登记。
- 调整自助刷环流程：只有已充时待激活的手环可以成功，其他状态给出明确反馈；成功页显示实际购买时长。
- 两端继续使用共享的前端模拟数据完成演示，不接入真实读卡器、支付、后端 API 或持久化。

## Capabilities

### New Capabilities

- `wristband-core-flow-ui`: 覆盖管理端手环充时、柜台激活、状态查询与归还，以及自助端会员识别和已充时手环激活的前端模拟闭环。

### Modified Capabilities

- 无。

## Impact

- 主要影响 `apps/member-admin` 的导航、类型、模拟数据和会员/手环办理页面。
- 主要影响 `apps/registration-kiosk` 的会话状态、手机号分支、刷环校验和激活结果页面。
- 可在 `packages/` 中增加仅供两个前端开发演示共享的浏览器存储状态模块；不改变服务器或 API 契约。
- 不新增运行时服务、数据库或硬件依赖。
