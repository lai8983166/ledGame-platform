# 玩法与地砖硬件解耦验收

## 修改边界

- 直接启动、准备确认、排队启动统一由选中的 factory 执行准备检查；检查仍早于会员 `startPlay`。
- `Stage` 和地砖 GIF 将帧交给当前 handler。Simple/Normal/Diffcult、Rank 和原地砖演示 handler 复用具体的 `FloorGameHardware`，原编码器、TCP 队列及 SDK 协议不变。
- 地砖坐标校验属于地砖 handler。未接入地砖的 handler 默认忽略 DOWN/UP/RESET，不输出地砖，也不初始化符号灯。
- 引擎通过 `openRuntime / closeRuntime` 管理本局资源；旧局输出和重复清理依据 context 身份被拒绝。
- `FloorStandbyRuntime` 承接 16×36 彩虹和旧待机 GIF；停机时使旧循环失效。Touch、副屏、游戏规则、数据库和配置格式没有修改。
- SDK 工具、60 秒异步搜索和房间硬件上报保持原链路。SDK 初始化失败只记录硬件加载错误，不再阻断整个应用；正式地砖游戏仍返回原就绪错误。
- 删除原 `handleSync` 的无效反射代码：其目标 `GameService.createSycPack` 在当前仓库不存在，原来没有实际发送作用。

未新增设备插件框架、硬件能力注册中心、设备绑定表或硬件选择界面。无地砖玩法只存在于测试夹具，不进入客户游戏列表。

## 软件测试

修改前：游戏后端 `mvn test`，600 项全部通过。

新增覆盖：

- 全局 ELC 启用但 SDK 关闭、配置不可用或没有控制器时，通过公共启动入口运行无地砖玩法，自然结束且不输出地砖/外围灯。
- 无地砖玩法忽略超出地砖场地的 DOWN/UP 和 RESET；异步硬件搜索等待/失败不暂停其帧循环。
- 四种现有玩法的 factory 正式模式检查、模拟模式跳过检查；handler 输出的字节、序号、尺寸与原编码器一致且只发送一次。
- 硬件检查失败不开始会员计时，不上报 GAME_STARTED；直接和队列入口回滚，交互准备可再次确认。
- GIF 使用当前 handler 输出，取消后释放循环。
- 布局冻结，旧局输出和清理不影响下一局；自然结束、手动中止、异常和部分启动失败清理资源。
- 无效 SDK 文件允许应用启动，但地砖启动仍返回 `ELC408_RUNTIME_LOAD_FAILED`，健康检查保留该原因。

## 三端全流程验收

初次旧脚本验收为 3 通过、7 失败、2 跳过；2026-09-28 已按用户要求修正。授权仅复制到隔离测试目录，没有改动正式数据库或绕过激活。

本轮只修改 `ledGame-platform/acceptance` 的脚本、测试及中文说明，没有修改两端的业务权限、积分规则或应用启动代码。

修正内容：

- 管理接口核对使用真实登录返回的操作员 ID，带 `X-Operator-Id`，不再把权限拒绝隐藏成房间查询超时。
- 单人场景明确选择 `simple`，预先配置并回读通关奖励 3，分别核对原始分 1 和会员积分 3；多人三种 Simple 玩法奖励 1，Rank 并列第一奖励 7，保留重复结算幂等检查。
- 店员可以充值、创建会员、清除余额和操作功能开关；不能查看运营数据、管理账号、访问备份或删除会员。页面和后端拒绝均有断言。
- 桌面启动原先缺少 JAR，现由测试自动构建；桌面备份使用独立 `TEST` 目录，两种平台启动方式均关闭与本套验收无关的固定端口旧协议监听。
- 正式界面通过轮播卡片选择游戏，调试界面通过列表选择游戏；后台重启等待启动检查完成，而不只等待健康接口。
- 每场景独立执行，不再因同文件前一场景失败而连带跳过。清理移入有独立时间预算的 Playwright fixture；诊断失败不阻断清理，Windows 短暂锁住 WAL/SHM 时有限重试。

验证结果：

- `pnpm test:acceptance:unit`：23 项全部通过，包括真实 Windows 文件锁释放后成功清理的回归测试。
- 全部验收脚本与支持文件的 TypeScript 检查通过。
- 全量复跑：12 个场景，10 通过、2 失败、0 跳过。两项失败分别是正式模式卡片定位和重启后的启动检查等待。
- 上述两项修正后定向复跑：正式模式 TCP 输入/自然结算与房间重连两项通过；其中正式模式曾在业务通过后遇到临时文件清理失败，补充删除重试和锁文件回归测试后再次完整通过。

因此，12 个不同场景已分批验证通过，任务 5.2 完成。这里没有声称最后额外进行了一次全量 12/12 单批通过。保留的原始中文报告分别是 `acceptance/artifacts/2026-09-28-全量复跑.md` 与 `acceptance/artifacts/2026-09-28-定向复跑.md`，最新定向报告仍在 `acceptance/artifacts/测试报告.md`。

## 尚需真实地砖确认

当前没有连接真实设备，以下不能以软件测试替代：

1. 正式模式发现控制器并启动；无控制器时仍拒绝启动。
2. 待机 → 准备 → 游戏 → 结束恢复过程中，真实地砖尺寸、颜色、动画及踩踏得失分正确。
3. 调试模式连接 SDK 时仍驱动真实地砖；断线重连后输入恢复。

符号灯目前仍只有可捕获的虚拟输出和默认空物理 sink，没有实物灯具验收，不声称已经接通真实符号灯。
