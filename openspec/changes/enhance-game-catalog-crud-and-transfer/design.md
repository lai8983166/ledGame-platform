# Design

## Context

- 分类保存在 `game_category`；游戏 `first_catalog` 是字符串形式的分类 ID，没有数据库外键。`GameCategoryService` 当前只有增改和排序。
- `Game` 实体包含关卡、布线、符号灯公共配置、媒体引用、积分及列表字段；两个编辑器的文档是投影，不等于完整表行。已有 `DELETE /game/{id}` 只是直接删行，缺少活动会话校验。
- `loadSupportedGames()` 每次读列表先调用 Simple/Rank 种子接口，既会补回已删除记录，也可能规范化已有 Rank 数据；仅在前端移除卡片不能实现可靠删除。
- 卡片当前整体点击进入编辑器，右下角打开信息编辑弹窗；调试页嵌在两种编辑器里，由编辑器取得文档。调试页自身已有硬件准备、会话控制、RGB/圆灯输入及退出清理。
- 规划集中在平台仓库，实际代码涉及 `ledGame` 与 `ledGame-backend`。本次规划不动现有未提交的会员管理端改动及后端开发日志；实施前核对跨仓库范围和各仓库约束。

## Goals / Non-Goals

**Goals:** 使用现有表、玩法映射/校验、文件对话框和调试组件完成维护操作；删除不会被普通读列表撤销，导入不会覆盖原记录，移动入口不改调试业务。

**Non-Goals:** 不导出整个数据库或媒体包，不新增玩法、分类同步、批量导入框架、回收站、软删除体系、通用命令平台；不修改会员平台、顾客 Touch 流程、硬件协议或计分计时规则。编辑器现有当前关卡导入导出独立保留。

## Decisions

### 1. 分类删除是一个事务

新增 `DELETE /game-categories/{id}`：校验分类存在，对 `game.first_catalog = String(id)` 的所有记录清空该列，再删除分类，任何失败整体回滚。更新仅涉及分类列，不用整行回写覆盖并发编辑。使用空字符串表达未分类，兼容现有下拉框和非 ALWAYS 字段策略。分类名不是关联键，不按名称删除，也不新增“未分类”数据库分类。

卡片删除使用应用内确认弹窗，提示所属游戏保留并变为未分类；成功后重新读取分类及游戏，失效的当前分类回到首页。可通过游戏列表继续访问未分类游戏。分类删除不会终止正在运行的游戏，因为不修改游戏内容或会话。

### 2. 导出是完整单行 JSON

主进程通过后端获取 `Game` 完整记录并保存为 UTF-8 `.game.json`，根节点为一个游戏对象，采用现有实体 JSON 字段命名；CLOB 字符串、空值和全部业务字段保留，不经编辑器转换再导出。导出位于列表中每张游戏卡片的操作层，不另外增加游戏选择器或多游戏合包。

导出包括资源引用但不解析/拷贝资源、精灵库、全局设置、日志或其他表。复用保存对话框、焦点恢复和临时文件原子替换，不添加二进制包协议或额外传输层。取消不写文件，失败不遗留看似有效的半份 JSON。

### 3. 导入按大类校验，原始记录入库

复用 `GameCreationDialog` 的类型选项与样式，支持明确的导入模式，选择后再打开 JSON 文件选择器。已核对当前 Simple/Normal/Diffcult 均使用 `default/[1]`，娱乐挑战导入保留该实际协议，排位赛允许已有 `rank/[1]`。不把选择当成修改 type 的指令；不兼容时拒绝并提示。

新增 `POST /games/import`，请求包含选择的大类及单条记录。使用受控的当前 `Game` 字段反序列化、JSON/字段类型及现有玩法校验；校验可借助编辑器映射，但最终保存原始记录，避免丢失编辑器未覆盖字段。所有新增在同一事务中完成，失败无写入。文件只支持当前约定的一条记录，拒绝数组、数据库文件、关卡文件、损坏或不支持的玩法数据，不做泛化旧格式转换。

导入清除来源主键，生成新 ID 和创建/更新时间；重新分配列表末尾顺序，不重排旧游戏；`firstCatalog` 清空，避免跨库 ID 撞号误分组。其余游戏业务字段保留，包括玩法、全局/关卡配置、资源引用、触屏显示、独立布线与奖励积分。存在同名时追加“（导入）／（导入2）…”等可区分后缀，并保持 Rank 展示名称一致，不要求原游戏先删除。

导入校验成功即落库并刷新卡片；它与“新建未保存草稿”不同，新建的首次保存机制不变。现有资源缺失诊断继续负责外部文件提醒，不为了导入而创建假资源或修改媒体引用。

### 4. 游戏删除复用接口并补齐使用中保护

将既有 `DELETE /game/{id}` 接入受控服务路径，验证目标存在、未被运行/暂停/准备/排队引用；与既有会话管理协调，避免检查与启动的竞态。前端禁止重复提交只是体验保护，不能代替后端检查。删除成功只删游戏行并刷新列表；不删媒体、独立精灵或任何历史记录，不触发会员扣时或结算。

不引入回收站、通用软删除及额外恢复表。使用应用内确认与明确失败提示；需要保留配置时可先导出。

### 5. 普通目录读取停止自动补种

`loadSupportedGames()` 改为只读取列表，去除日常目录路径的自动 seed 调用；核对游戏首页、Touch、调试选择等所有调用者。现有包内数据库及用户库继续作为数据来源，空库显示空态并允许新建/导入，不另加一次性初始化标记或删除墓碑。

开发/测试的显式种子接口可保留供主动使用，但不得被正常刷新/启动间接调用。对 Simple、Normal、Diffcult、Rank、自建游戏及“最后一条删空”覆盖刷新与重启验证。新建和导入不依赖游戏固定名称，也不把已有游戏按种子模板重写。

真实 EXE 验收还复现了 H2 延迟写盘问题：删空后立即关闭，重启可能恢复尚未落盘的旧行，额外等待 1.2 秒后不复现。游戏端启动 H2 的连接串设 `WRITE_DELAY=0`，让提交成功前完成日志刷新，开发默认文件库同步采用该设置；不靠测试休眠掩盖问题，不改会员管理端 SQLite。验收保持最后一次删除后立即关闭/重开。

### 6. 卡片操作层与现有配置能力

封面、名称和卡片设计保留，按用户参考图实现 Hover 遮罩、居中播放及底部编辑/导出/删除。右上角保留排序手柄，不使用无操作的装饰图标。`focus-within` 同样显示按钮，独立按钮具有名称，禁止嵌套按钮；点击停止冒泡，拖动不触发操作。

底部“编辑”直接进入 Simple 共用或 Rank 编辑器，不再打开 `GameInfoEditDialog`。核对并补齐编辑器中的名称、封面、分类、触屏显示设置，复用既有元数据保存能力，不能随旧按钮一起失去触屏显示开关。分类卡片保留原编辑/排序，并增加删除入口；不额外新增说明小标题。

### 7. 调试工作区提升为应用级页面

在 `App.vue` 增加明确的游戏调试路由状态，卡片播放按 ID 读取对应已保存编辑文档后直接挂载 `EditorDebugWorkspace`，不为了调试先挂载整套编辑器。复用该组件现有准备、SDK 搜索、直接/手环启动、暂停、重启、观察、模拟地砖/圆灯输入与 cleanup。

保存来源列表上下文，退出时返回游戏列表或所选分类；进入页默认第一关，可在页内选择。准备/运行/暂停期间离开及导航复用既有退出清理，失败不切页；语言等非导航弹窗不终止调试。编辑器启动按钮和仅为该入口存在的选择弹窗不再展示，相关旧测试更新为卡片入口；编辑器本身的保存、新建草稿及未保存保护保留。

## 追加界面完善（2026-10-16）

本轮仅修改 `F:/project/ledGame` 前端及相关测试，本仓库更新同一 Change，不修改游戏后端、表结构、会话、硬件或积分协议。

- 沿用现有样式：游戏卡片标题 18px → 16px、字重 400；按后续反馈将卡片从 430px 缩至约 215px，网格靠左排列、按可用宽度自动换行，间距 36px。取消四列限制和整体居中，封面保持上部独立 3:4 容器，名称单独在其下方，悬浮操作只覆盖封面。
- 封面比例反馈修正：加载图片后用其固有宽高比调整卡片宽度，保持原封面高约 284px；流式排列适应不同宽度，视口不足时按比例缩小。无图或加载失败采用 3:4/215px 占位。不裁切、不拉伸、不改资源文件，名称区仍独立。
- 导航 Tab 在普通、悬浮、选中状态均保持白字，不改变选中底色与边框。
- 利用现有 `role="dialog"` / `aria-modal="true"` 标记，局部覆盖弹窗主题变量及控件颜色。白底黑字不改页面整体深色风格、遮罩、彩色预览和业务错误提示；原生系统文件选择器仍由 Windows 绘制。不创建新弹窗框架。
- 分类内列表的唯一主标题为分类名称，保留返回按钮但去掉重复分类文字；提供新建游戏入口，沿用现有草稿首次保存机制，不额外改变分类保存规则。
- 符号灯关闭时仅以 `v-show` 隐藏左侧“灯光设置”行下面的具体配置；右侧矩阵预览和底部绘制/保存/取消始终可见，开关切换不缩小弹窗、不清空草稿，不改变保存与运行时逻辑。

## 编辑器保存与操作完善（2026-10-17）

- Simple 共用和 Rank 使用小型应用内保存反馈窗口，不用原生 alert；关闭后恢复可用输入焦点。必填检查发生在归一化/请求前，Simple 按现有必填星号检查，零积分及不限时/无限生命合法，数值限制仅启用时检查。Rank 保留自身后端配置校验，不套用 Simple 专用媒体必填规则。
- 全局配置仍只提交配置 patch，不提交未保存矩阵；新建游戏仅更新配置草稿，主保存才创建游戏。后端未确认 saved 时不得更新本地配置并宣称成功。
- 关卡按钮使用原生左键拖放，不增加拖放依赖；整个关卡对象移动，按对象身份保留当前编辑关卡，重置索引相关的 RGB 历史/缓存。Rank 仍为单关卡，不引入无意义排序。
- 矩阵根据当前格子占用直接更新 canvas 游标，不给每次悬停增加全量 Vue 渲染。类型只读展示娱乐挑战/排位赛，不改变存储 default/rank；旧 mode 字段保留但隐藏且不接受配置 patch 修改。音频输入宽度填充自身轨道，操作按钮保持紧邻。

## 保存忙碌反馈与编辑闪屏（2026-10-17）

- 点击保存同步设置 `editor-saving`，用 CSS 等待游标覆盖控件/矩阵自己的游标；让首个画面有机会绘制后才开始必填校验、序列化与接口操作。隐藏窗口的 rAF 可能停止，设置短超时兜底；成功、必填失败、接口失败均在 finally 清理。不改变保存的数据和接口，不添加保存队列或任务系统。
- 旧打包版隔离实验发现：删除对象和复制到后一帧各触发 3 次 `moveTop` 和 3 次窗口 `focus`。原因是普通编辑操作误用原生弹窗的 Windows 焦点修复边界，该边界本来有三次消息循环重试，作用于整窗而不是矩阵。移除上述普通操作的恢复，以及删除关卡/帧在既有确认边界之后的重复恢复。保留 `confirmWithRendererFocus` 和原生文件对话框的焦点恢复，不修改窗口绘制、RGB 协议或计分逻辑。
- 验收记录真实 EXE 修复前后窗口调用；普通操作要求零置顶/强制聚焦、矩阵面板边界不变，保存要求等待期间按钮禁用/游标 wait，结果弹窗后可继续输入。自动化证据不能代替所有显卡/系统的肉眼观察，不以此宣称所有环境绝不闪屏。

## 游戏级配置归位与帧工具（2026-10-17）

- Simple/Normal/Diffcult 根文档字段名称/描述/备注/场地宽高放入既有全局配置弹窗，仍以已保存文档为基底局部提交，不提交未保存帧草稿。尺寸更改时仅同步已启用布线的 width/height，不删除点位或裁剪帧；超范围由现有后端校验拒绝，失败不改本地文档。Rank 不新造共用编辑器全局配置体系。
- 真实 EXE 验证发现原备注输入未接 DTO/Assembler，界面保存后会丢失；补齐既有 `game.remark` 列的读取/写入，不新增列。旧请求未携带 remark 时保留现值，明确空字符串时可清空；Rank 的 displayName 映射不改。
- 游戏内布线隐藏宽高输入，独立布线工具仍可设尺寸；布线 API 失败和前端布线校验失败均使用现有保存反馈弹窗，失败不关闭配置且可重试。新建游戏只写草稿时显示原草稿说明，不冒充持久化。
- 特效增加 `after` 插入策略，前插入及旧核心 `merge` 兼容逻辑保留；界面旧 merge 映射为 after，不再提供合并选项。自动预览保留，去掉手动重绘按钮。确认后真实插入整帧而非仅改选项文本。
- 全部帧号单行显示，不限量抽样、不换行、不增加滚动条；按钮按 index / (count - 1) 定位，与进度条共用宽度和左右边距，首尾刻度对齐条两端。使用容器宽度和帧数自适应压缩字号，首尾文字中心对齐刻度并保留边缘留白避免裁切，所有帧可点击，拖动仍使用同一线性坐标。帧数极多时文字必然更小，不承诺无限帧数在有限屏宽中仍保持原字号。复制后一帧改为双纸页图标，复制全帧仅隐藏；当前关卡 JSON 保留覆盖确认与隔离导入语义，迁到工具栏。

## Risks / Trade-offs

## Rank 编辑器与多关卡追加（2026-10-18）

- Simple 首行保留返回入口并排列保存、全局配置、地砖布线、关卡增删及关卡列表；帧尺与其他对象工具仍独立，不复制按钮和状态。
- Rank 使用同一全局配置弹窗和 save/settings/wiring 图标；基础信息及共用媒体移到弹窗，只有一个名称输入，保存时同步旧 displayName 字段，不变更外部协议。按用户确认，关卡“玩法介绍”选择图片/动画并复用 startGif，“游戏说明”为 description 文字，“语音说明”复用原 gameplayIntro/voiceDesc 音频，“背景音乐”复用 backgroundVoice/bgVoice；不会把旧音频改成文字。关卡资料只保存在原 levels JSON，新增说明字段，不新增表。原炸弹预警/爆炸音效配置放入全局共用媒体，明确保存全局配置后同步各关，未指定全局值的旧数据继续保留各关旧引用。编辑器不再提供导入导出，目录的完整游戏导入导出保留。
- 沿用 game.levels JSON 数组，不新建表或子玩法插件框架；type=1 继续使用已有炸弹交互，界面名“炸弹3x3”，新关卡必须主动选类型。旧单关卡缺省名称为 Ranking，已自定义名称与旧参数不重置。范围界面 1-based、持久化 0-based 不变。
- 每玩家目标和炸弹数量使用 min,max 单输入，非法/逆序范围提示并阻止保存，切关保留未完成的范围输入。既有刷新周期仍位于子玩法末尾，不删除旧参数或默默改值。全局时长启用时按所有关卡总时长校验，未启用时每关仍有自身有限时长。
- 移除仅单关卡校验和运行时限制，复用引擎 Stage 顺序推进与按关卡积分账本；Rank 状态在切关重置当前关卡得分/接触/炸弹，保留整局累计得分。可从所选关卡开始，每关使用自身时长/媒体/积分。未知类型阻止保存，不隐藏后续关卡错误；显式 seed 不再截断关卡列表。既有共用会话、SDK 和会员通信不改协议。

## Risks / Trade-offs (continued)

### Rank 类型专属关卡音效修正（2026-10-18）

本节替代前述炸弹音效全局配置方案。预警/爆炸音效属于关卡 type=1 的选项，界面仅选择炸弹3x3 后显示，复用既有媒体选择和音频预览，仍保存到该关 option.bombWarningAudio/bombExplosionAudio。全局不再提供或覆盖此配置；历史全局字段反序列化时忽略、Rank 正常保存时清除，不覆盖既有独立关卡引用（此前全局保存已把资源写入关卡）。允许显式清空，新关卡从空值开始，不影响其他关卡、其他类型或运行时音效事件，不批量改写用户数据库。

帧号选中仅使用文字/刻度颜色和进度游标，不绘制按钮边框、背景框或阴影；键盘聚焦以帧号下划线提示，不改变布局和选择逻辑。

- 单行 JSON 不能让另一台机器自动拥有图片/音频/独立精灵 → 明确导出边界并保留现有缺失诊断；不把媒体缺失误报成导入已复制资源。
- 投影转换丢字段或写入原 ID 覆盖记录 → 原始行保存，测试逐字段往返；只允许指定的 ID/时间/排序/分类/重名处理差异。
- 默认游戏删除后复活 → 删除正常读取中的 seed，真实数据库删除后刷新/重启测试，而非仅测试 DOM 消失。
- 活动游戏被删除、调试残留监听 → 后端使用中校验及会话协调，端到端覆盖准备、运行、暂停、排队和反复进入/退出。
- 对话框后输入失焦、卡片按钮冒泡误触 → 复用现有焦点恢复方式，测试取消、确认、失败重试、键盘和拖动。
