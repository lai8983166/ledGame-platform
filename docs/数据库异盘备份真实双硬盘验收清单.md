# 数据库异盘备份真实双硬盘验收清单

## 准备

- 使用包含两块独立物理硬盘的 Windows 测试机；在“磁盘管理”确认不是同盘两个分区。
- 使用名称、手机号明显属于测试用途的会员数据。
- 记录会员管理端 `platform.db` 的实际路径和两块物理盘编号。
- 禁止拿唯一一份真实营业数据库做破坏性试验。
- 测试必须设置 `LEDGAME_DATABASE_BACKUP_ENVIRONMENT=TEST`，并将 `LEDGAME_DATABASE_BACKUP_ROOT` 指向另一块物理盘上的唯一目录，例如 `E:\LEDGameBackupTest\member-admin\20260902-店内验收`。不要把测试根目录设为正式目录 `LEDGameBackup\member-admin`。
- 启动前记录本次测试根目录；测试产物可以保留用于复核。正式程序只接受 `PRODUCTION` 元数据，不会读取这个测试目录。

## 必验场景

1. 首次启动：先出现独立检查窗口；检查窗口没有候选路径、文件选择或导入按钮。进入主界面后显示目标卷和首次成功时间。
2. 跨盘证明：运行 `scripts/verify-database-backup-hardware.ps1 -DatabasePath <测试库绝对路径> -BackupRoot <本次测试备份根目录>`，保存其输出，确认源、目标 Disk Number 不同、元数据环境为 `TEST`、哈希和隔离恢复通过。
3. 版本追赶：创建测试会员、充值并完成一局游戏；5 秒内应开始备份尝试，最终 latest revision 等于主库，备份库能查询到对应数据。
4. 立即关闭：提交一笔充值后立刻正常关闭；界面显示“正在保存并备份数据”。重启后 latest 包含该交易。
5. 强制终止：提交业务后在备份完成前通过任务管理器结束；重启后检查窗口识别主库领先并追赶，业务数据不得丢失。
6. 拔掉目标盘：营业写入仍成功，界面明确提示检查硬盘连接/目标盘；重新接入后无需选择目录即可自动恢复并追赶。
7. 盘符变化：关闭程序，改变目标卷盘符再启动；系统按物理身份重新发现，不能因为盘符变化改选同一源物理盘的其他分区。
8. 空间不足/只读：用隔离测试卷制造空间不足或只读状态；错误码和中文建议必须明确，旧 latest 保持可打开。
9. 重装空库：保留异盘备份，使用全新 userData 启动；不得用空库覆盖旧备份，应进入“需要维护”。登录出厂账号后才能看到候选并导入。
10. 旧历史导入：选择一个较旧 history；确认框准确显示 revision 和最后业务修改时间。取消时文件不变；再次确认后导入成功、要求重新登录，且新 revision 高于此前已观察版本。
11. 营业中拒绝：存在 RUNNING 游戏或排队时确认导入，必须提示先结束营业流程，三端现有流程不被中断。
12. 导入失败回滚：在测试环境分别模拟候选复制失败、哈希失败和替换后启动失败；均应恢复 pre-import，不能启动部分数据库。
13. 导入中强制终止：分别在保存回滚副本和替换后终止 Electron；下次启动应自动恢复旧库，或完成复验后使用完整新库。
14. 主库损坏：仅损坏测试副本。启动窗口应保持阻断，不得自动覆盖异盘 latest，也不得在未登录状态出现导入入口。
15. 历史保留：跨自然日验证每日快照；构造超过 30 天的测试快照后确认清理不删除 latest、保留期内快照或仅存有效历史副本。
16. 正式/测试隔离：保留测试目录，再以 `PRODUCTION` 启动正式程序；不得进入身份冲突维护状态，测试候选不得出现在正式候选列表。正式目录中如有人为放入旧 v1 或 `TEST` latest，应先进入 `quarantine\environment-mismatch-*` 再重建正式 latest。
17. 保留当前主库：制造同环境、异身份的测试冲突，使用出厂账号选择“保留当前数据库”；冲突文件应完整进入 quarantine，当前主库数据不变，随后生成新的 latest。
18. 候选账号校验：候选列表及确认框应显示出厂账号用户名和会员数量；无出厂账号、出厂账号被停用或存在多个已启用出厂账号的候选均不得导入。
19. 正常关闭与重开：关闭会员管理端主窗口后确认 Electron 及其托管 Java 后端均退出、原端口不再监听；随后应能立即重新打开。重复启动时只激活已有窗口，不得再拉起第二个后端。

## 通过标准

- 任一已提交业务要么出现在主库并最终进入有效 latest，要么有明确、持续可见且可重试的备份故障；不能静默丢失。
- latest 始终能通过 SQLite 完整性检查和元数据 SHA-256；失败候选绝不替换上一份有效 latest。
- 测试备份只写入测试根目录且元数据为 `TEST`；正式备份只写入正式根目录且元数据为 `PRODUCTION`，两者可以同时保留。
- 同一物理硬盘的其他分区绝不被认作异盘目标。
- 导入入口只在登录后的出厂账号界面出现；启动窗口、次级账号、未登录 API/IPC 均不能执行导入。
- 正常退出有界等待；目标盘故障不会让应用无限卡住，也不会回滚已经成功的营业事务。
- 验收记录至少保存：测试时间、应用版本、源/目标物理盘编号、测试数据库标识、关键截图、脚本输出、失败注入方式和最终结果。
