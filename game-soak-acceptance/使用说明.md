# 游戏端烤机工具

仅启动游戏端打包应用及它自带的后端，不需要会员管理端、自助注册端或激活签发工具。测试用游戏模式、触屏启动，脚本点击真实按钮，等待自然结束再返回待机。崩溃不会自动重启。

## 准备与启动

1. 解压游戏端和本工具。不要同时手动运行待测游戏端。
2. 复制 `config.example.json` 为 `config.json`，填写 `gameExecutable`（游戏 exe）、`outputRoot`（报告目录）。路径建议使用 `F:/xxx`。
3. 填写 `floor.width`、`floor.height`。真实地砖选择 `hardwareMode: "real"`，并填写 `floor.configDirectory`，指向已经实操验证过的 `conf.json`、`wiring.json` 所在目录。无硬件开发验证选择 `simulated`，不会自动降级。
4. 终端执行 `soak.cmd inspect config.json`，查看该打包游戏库的实际 ID、人数、关卡数和整局时长；此操作不开局。
5. 按所需顺序填写 `games`，例如每项格式为 `{ "gameId": 实际ID, "playerCount": 1, "startLevelIndex": 0 }`。不要原样复制占位文字。无限时长、错误 ID、非法人数或关卡会拒绝开测；不会自动修改游戏内容。
6. 执行 `soak.cmd run config.json`。默认 18 小时；可修改 `durationHours` 做短测，但要足够完整遍历一次所选列表。按 Ctrl+C 提前结束，报告记为“未完成”。

工具自带 Node 和自动化依赖，不需要安装开发环境。不要删除 `runtime` 或 `node_modules`。使用配套更新后的游戏包，旧版缺少证据接口时不能验收。测试期间不要操作游戏配置、手动结束游戏或关闭窗口；真实踩踏可以参与游戏。

## 数据与判定

每次创建新目录，复制游戏库和地砖配置后运行，不修改源文件。默认使用打包内置游戏库；需要自己的游戏时，关闭使用该库的应用，再通过 `gameDatabaseSource` 指定它的 `ledgame.mv.db`。不要复制正在写入的数据库。

测试结束查看本轮目录的 **测试报告.md**；原始依据在 `plan.json`、`rounds.jsonl`、`samples.jsonl`、`result.json`。预检后失败也保留报告。启动之前配置或目录本身不合法时，错误直接显示在终端。

本轮目录超过 512MB 或 10,000 项、输出盘空闲不足 100MB 时会停止并保留现场；不全程录屏，也不保存无限量报文。请不要用任务管理器强杀测试工具或直接关闭终端，否则可能来不及生成最终报告，应将这轮视为未完成。

- 软件：目标时间跑满、全部目标自然结束、没有异常退出或卡死。
- 内存：每 10 秒采样，预热 10 分钟后按窗口计算趋势。开测前填写 `limits.memoryLimitMB` 和 `memoryGrowthMBPerHour`；未填或样本太短只报告“未判定”，不要把短测当成无泄漏证明。
- 通信：依据 SDK 实际收发及解析计数。模拟模式永远不能验收真实硬件；真实模式无人踩踏导致没有回传时，输入链路仍为“未验证”。协议不能可靠判断的丢包率不会虚构。

## 可选模拟踩踏

默认 `simulatedInputEnabled: false`。明确设为 `true` 后，仅本机且当前 RUNNING 会话接受 DOWN/UP，不会自动生成踩踏。另开终端执行 `soak.cmd inject "本轮输出目录" DOWN 0 0`，随后执行同一路径的 `UP 0 0`，可模拟一次按下/释放。多个注入脚本不要争用顺序号；重复、过期或超过每秒 200 次的请求会被拒绝。

它走相同游戏输入规则，不直接改积分；模拟释放不会释放仍被真实踩住的格子。报告分别记录模拟事件和真实 SDK 通信。正式 18 小时真实地砖验收尚需现场执行。
