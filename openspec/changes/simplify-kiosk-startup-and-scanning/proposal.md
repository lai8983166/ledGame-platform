# Proposal

## Why

会议已明确自助端启动和刷卡不应反复点击前置按钮。当前仍需保存、测试再启动，以及进入流程后另点开始刷卡，需要按已确定的三点收敛。

## What Changes

- 店员页只需填写管理端地址（保留现有端口配置），点击启动即保存、检查连接、成功后打开顾客窗口；失败用直观 DOM 弹窗提示，可直接重试。重开记住设置。
- 已有会员确认或新会员登记成功后，直接显示刷卡等待；切换手环查询也直接等待刷卡，不打开软键盘或额外 UID 输入。
- 取消激活刷卡返回会员资料确认，取消查询刷卡回手机号查询；均不作为成功。等待倒计时、取消、离开和掉线使旧响应失效。
- 沿用当前数字+回车读取、请求序号、防重复、超时及两窗口权限边界；修正成功延迟回调在会话取消后仍可能切页的隐患。
- 补开发与打包桌面实操，覆盖失败启动、重试、记忆配置、自动等待、新老会员、取消/超时、断网恢复与重复刷卡；同步现有验收脚本。

## Capabilities

### New Capabilities
无。

### Modified Capabilities
- `wristband-core-flow-ui`: 自助端一步启动、自动进入激活刷卡等待及取消/超时保护。
- `player-info-query`: 切换手环查询直接接收读卡器输入，保持只读。

## Impact

仅自助前端和相关测试/中文说明，尽量复用现有桌面保存、健康检查与启动接口；不改管理端服务、数据模型、计时、余额、积分或其他页面刷已激活卡的分支。重新打包自助端原位置目录和 ZIP，不自动提交 Git。
