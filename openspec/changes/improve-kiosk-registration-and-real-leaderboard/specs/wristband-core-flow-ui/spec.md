## ADDED Requirements

### Requirement: 自助端显式进入刷手环等待状态
自助注册端 SHALL 在刷手环步骤提供明确的“开始刷手环”操作，并 SHALL 仅在顾客主动开始后显示可取消的等待提示和接收读卡器输入；顾客流程不得要求点击或编辑手环 UID 输入框。

#### Scenario: 进入刷手环页面
- **WHEN** 顾客完成会员查询或注册并进入刷手环页面
- **THEN** 页面展示开始刷手环按钮
- **AND** 系统尚未进入读卡等待状态
- **AND** 页面不提供需要顾客聚焦的手环 UID 输入框

#### Scenario: 开始等待真实读卡器输入
- **WHEN** 顾客点击开始刷手环按钮
- **THEN** 系统显示“请刷手环”等待提示和取消操作
- **AND** 系统开始接收读卡器输入的数字 UID 及其结束回车

#### Scenario: 成功读取并绑定手环
- **WHEN** 等待状态收到完整 UID 且平台成功校验并绑定该手环
- **THEN** 系统自动解除等待提示
- **AND** 系统显示绑定成功结果

#### Scenario: 取消刷手环
- **WHEN** 顾客在等待状态点击取消
- **THEN** 系统关闭等待提示并丢弃尚未完成的读卡输入
- **AND** 系统不发起绑定且不显示刷手环成功

#### Scenario: 非等待状态收到键盘输入
- **WHEN** 刷手环等待提示未打开且设备收到数字或回车键输入
- **THEN** 系统不得把这些输入解释为一次手环扫描或触发绑定

#### Scenario: 手环校验或绑定失败
- **WHEN** 完整 UID 的校验或绑定请求失败
- **THEN** 系统在等待提示中显示可理解的失败原因
- **AND** 系统清空本次扫描缓冲并允许重新刷手环或取消
