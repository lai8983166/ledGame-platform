## Context

会员管理端系统设置的功能开关来自前端静态数组，刷新即丢失。会员平台后端已经通过 `/ws/rooms` 接受各游戏后端的长连接、在握手时返回 `WELCOME`，游戏后端也已有断线自动重连逻辑；但当前链路只处理游戏端向平台上报房间状态，没有平台设置的下行契约。游戏端的编辑器列表和游戏模式选择页最终都读取本机游戏后端 `/games/playable`。

## Goals / Non-Goals

**Goals:**

- 建立可扩展但最小化的门店功能设置模型，SQLite 为唯一权威来源。
- 在不新建连接、不增加轮询的前提下支持连接初始化和在线变更同步。
- 将游戏隐藏规则放在游戏后端的可玩目录边界，避免两个前端列表各自维护不同策略。
- 让正在显示选择列表的游戏界面及时响应设置变化。

**Non-Goals:**

- 本次不实现不同房间使用不同儿童模式，也不提供按游戏勾选隐藏列表的配置界面。
- 本次不删除 `simple-demo` 数据、不阻止已有运行中的该游戏自然完成，也不修改游戏编辑数据。
- 本次不改变自助注册端，不新增第三方配置中心或消息中间件。

## Decisions

### 1. 会员平台保存单行儿童模式设置

新增单行 `store_feature_settings` 表，以固定主键保存 `child_mode`；缺失记录时读取为关闭，更新时使用 upsert 创建或覆盖。表内时间字段保留用于兼容已创建的数据库，但不再暴露到 API 或跨端协议。相比前端配置文件，SQLite 能随现有数据库备份恢复；相比通用字符串键值表，显式布尔列能获得类型约束并让后续迁移可审计。该表加入数据库 revision 跟踪，使修改会触发现有异盘备份机制。

平台提供 `GET /api/feature-settings` 与 `PUT /api/feature-settings/child-mode`。响应只包含当前实际消费的 `childMode`；前端收到成功响应后才更新状态，失败时保持原值。现有系统设置操作审计直接映射到真实 PUT，不再额外调用只记日志的演示接口。

### 2. 将下行设置扩展到现有房间 WebSocket

`WELCOME` 增加可选 `childMode`，保证后启动和重连游戏端总能拿到权威值。在线修改后，平台注册表向所有当前打开的房间 session 广播 `CHILD_MODE_CHANGED`，消息直接携带新的布尔值。当前只有一个真实开关，不引入通用设置快照或增量合并模型。

同步失败只影响对应离线连接，不回滚已经持久化的门店设置；游戏端的既有重连会在下一次 `WELCOME` 自动收敛。不改变游戏端上行事件序列与 ACK 语义。

### 3. 游戏后端维护只读内存投影并在目录边界过滤

游戏后端新增线程安全的儿童模式内存状态，进程启动默认 `childMode=false`。房间客户端解析 `WELCOME.childMode` 和 `CHILD_MODE_CHANGED.childMode` 后原子替换当前值。

`/games/playable` 在返回目录时根据投影过滤受限内部名称集合；当前集合只有 `simple-demo`。隐藏规则集中在后端，使编辑器列表、游戏模式选择页及其他未来消费者得到一致结果，不把策略散落到 Vue 模板。

### 4. 复用本机运行时 WebSocket让已打开页面刷新

通用游戏运行时快照只增加顶层 `childMode` 布尔值。游戏后端应用新的平台设置后触发一次现有 action `12` 运行时广播；游戏模式页面检测 `childMode` 变化后重新读取 `/games/playable`。如果当前仅在准备阶段选中了刚被隐藏的游戏，页面取消该准备选择或要求重新选择，不允许确认新局；已经 RUNNING 的游戏不被强制中止。

主编辑器列表不需要新增另一条连接：重新进入页面或手动刷新时会读到后端过滤结果。实时安全边界仍由后端目录与开始前校验负责，而不是依赖 UI 隐藏。

## Risks / Trade-offs

- [开关打开瞬间某游戏端离线] → SQLite 先保存，重连 `WELCOME` 总是携带当前值。
- [设置变化与用户确认开始处于竞态] → 游戏后端在准备确认/目录解析边界再次按当前策略拒绝受限游戏，UI 隐藏不是唯一防线。
- [旧游戏端忽略新消息] → 新字段和消息均不改变旧上行协议；旧端可能不执行隐藏策略，但房间通信不会中断，升级游戏端后生效。
- [会员平台暂不可达时默认关闭会展示测试游戏] → 这是用户明确要求的默认关闭语义；一旦连接成功即收敛到平台值。
- [未来受限游戏变化仍需改代码] → 本次只做好模式传播与策略集中点；未来可将受限集合迁移为数据库配置而不改变跨端 `childMode` 契约。

## Migration Plan

1. 先发布会员平台后端与会员管理端：旧游戏端忽略新下行字段，现有功能不受影响。
2. 发布游戏后端与游戏端：连接后消费当前设置并过滤目录。
3. 现场验证默认关闭、在线切换、多游戏端广播及断线重连。
4. 回滚游戏端时仅失去隐藏行为；回滚平台端时新版游戏端维持默认关闭，不影响其他游戏流程。数据库新表可保留，不需要破坏性回滚。
