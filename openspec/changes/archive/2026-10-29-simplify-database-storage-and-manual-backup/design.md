# Design

## Context

现有数据字段通过统一存储服务加密，照片为加密二进制，备份元数据与导入校验要求 v1 密钥。自动备份及 Electron 的维护门禁、替换、回滚链路已经存在。

## Goals / Non-Goals

目标：不改业务接口；已有数据无损转明文；自动备份继续工作；出厂账号可手动完整导出并受控导入。

非目标：不取消账号密码哈希、授权、审计或权限；不支持无旧密钥强行解密；不重做备份调度，不操作实际开发数据库。

## Decisions

1. 生产存储服务不再加密新值，旧解密器只用于历史数据兼容。查询索引改用不依赖密钥的稳定值，启动事务迁移所有相关列并保持业务版本、ID、账户余额和密码哈希。明文状态使用独立格式标记，不生成新 DPAPI 密钥。原密钥文件保留供旧备份使用。
2. 照片采用原文件名保存原始图片字节。旧照片逐个验证并原子替换；中断后仍能混合读取旧/新格式，避免跨文件与数据库事务造成不可恢复状态。
3. 自动快照使用明文标记，不携带新的密钥/恢复信封；旧格式按原密钥校验。相同实例、相同业务版本但存储格式变化也更新 latest；不同实例或较新备份仍不能自动覆盖。
4. 全量导出采用单一 ZIP，复用 SQLite 在线快照、元数据与照片清单校验；原生保存对话框选择位置。相比裸 DB，ZIP 不会遗漏拍照头像，也无需客户复制多个附件。不导出授权文件及厂家密钥。
5. ZIP 在隔离暂存目录解包，限制条目路径、大小与类型，复用候选校验、导入维护门禁及 Electron 回滚。也保留选择旧 DB 的兼容。出厂身份在后端和 IPC 校验，导入确认显示版本、修改时间、出厂账号并要求导入后重新登录。
6. 数据库页只显示自动备份实际保存路径和导出、导入两个按钮；移除版本列表和恢复操作。后台维护接口保留历史兼容，不在本次重写。
7. 自动备份资格统一用于启动、周期任务、实际发布及收尾；内存库、正式环境下的内存映射临时库不能发现备份盘或发布备份。周期重新发现目标后再次检查门禁，避免本轮刚发现冲突却继续发布。收尾仅在可营业状态执行；出厂账号明确保留主库后先进入检查态，再发布新备份。发布和导入门禁变更在同一协调器锁内串行，防止状态检查后发生导入切换。
8. 服务端 test profile 默认禁用自动备份并标记 TEST。专门验证备份的测试必须显式开启并指定隔离目录/模拟磁盘，不使用开发机正式目录。已有正式数据不在修复中删除、导入或重建。

## Risks / Trade-offs

- 旧密钥丢失 → 拒绝迁移/导入，不把密文当明文，不覆盖原数据。
- 导出期间照片被删除 → 快照所引用照片必须可用且校验通过，否则导出失败，不发布残缺 ZIP。
- 明文备份可直接读取 → 这是用户明确选择；账号密码仍只有哈希，文件保管责任不通过新加密功能转移。
- 历史备份冲突仍进入维护 → 保留原保护机制，不静默覆盖旧备份，可使用导入动作恢复正确数据。

## Migration Plan

先补隔离测试，再修改存储与迁移、备份与导入、桌面桥接及页面。校验失败不改变有效主库；替换失败恢复导入前副本。仅重新打包会员管理端的 win-unpacked 与 ZIP，测试和签发工具不重打包。
