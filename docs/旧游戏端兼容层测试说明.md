# 旧游戏端兼容层测试说明

## 准备

- 使用包含兼容层的新会员管理端，完成激活并登录；现有旧打包文件需重新打包。
- 旧游戏端将注册中心 IP（`consoleIP`）设为会员管理端 IP，使用手环启动模式（`launchMethod=2`），具备旧端 `hasTouch` 权限。允许访问管理端 TCP `16668`。
- 在新管理端准备两名测试会员，分别绑定已充值的真实手环，剩余时间大于 1 分钟。记录两人的测试前积分。

## 操作与预期

| 旧游戏端操作 | 新会员管理端的响应／检查结果 |
| --- | --- |
| 在设置中测试注册中心连接（`GET /dev/ping`） | 返回 `data=pong`，旧端提示连接成功。 |
| 保存注册中心 IP，启动旧端并等待心跳（`cmd=1`，启动约 3 秒后开始） | 房间管理出现以旧端来源 IP 识别的在线房间，可修改房间名。 |
| 刷两只已绑定、已充值的手环进行启动前校验（`cmd=5`） | 整批返回 `code=200`，待启用的绑定进入 `ACTIVE`；旧端可继续启动。管理端手环页手动刷新检查。 |
| 开始双人游戏（`cmd=2`） | 房间显示游戏名称及两名玩家；生成两条 `RUNNING` 游玩记录。 |
| 游戏结束，旧端上报每人的最终积分（`cmd=3`） | 房间退出游戏中状态；两条已有游玩记录改为 `LEGACY_SETTLED`，结束原因显示未知。会员积分增加值应等于旧端各自上报值，排行榜同步体现。 |
| 关闭旧游戏端，等待超过 60 秒 | 房间显示离线，已保存积分和游玩记录仍存在。重新打开旧端后，下一次心跳恢复在线。 |
| 一批手环中加入未绑定／已过期的手环后尝试启动 | `cmd=5` 返回非 200，旧端阻止启动；同批其他待启用手环也不能被部分激活。 |
| 游戏中重启管理端后，再由旧端结束并上报 | 已保存的会话仍可关联，积分只结算一次。 |
| 接口测试：重放相同的 `cmd=2`（本局运行中）／已接受的 `cmd=3` | 不重复创建游玩记录、不重复加积分；旧结算的完全相同重放不能结束新局。 |

会员／手环／记录页面按需手动刷新。多人验收必须逐人核对积分及记录，不能只看其中一名玩家。

## 验收注意

- 旧端不回传实时积分、排名、剩余游戏时间或控制器健康；房间不显示这些数值属于预期。
- 开始／结束通知是异步请求，旧端不会重试；旧端游戏正常运行不代表管理端已成功收到记录。
- 旧协议没有局 ID：同一房间、游戏、玩家再次上报完全相同的结算内容会被视为重复。测试连续两局时，让至少一人的积分不同；相同结果的跨局区分属于协议限制。
