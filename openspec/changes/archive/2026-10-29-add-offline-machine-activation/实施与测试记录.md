# 离线激活实施与测试记录

日期：2026-09-05。范围：ledGame-platform；未修改游戏前后端仓库，未生成正式密钥，未覆盖 release，未提交 Git。

## 已实现

机器码基于固定 64 位注册表视图的 Windows MachineGuid 摘要；厂家工具签发 Ed25519 激活码，Java 验签。授权保存到独立目录，经临时文件写入、刷盘和原子替换后才更新激活状态。遗留未提交临时文件不会被当作授权。

未激活时显示启动窗口中的激活界面，不启动备份检查，不开放业务 HTTP 或房间 WebSocket。激活后触发一次备份启动检查。原有出厂账号权限仍有效，激活不是登录。

客户只复制机器码、粘贴激活码，不导入授权文件。开发和打包桌面版使用相同校验，无跳过激活开关。业务验收脚本从显式本机授权文件复制到隔离目录；单元/服务集成测试仅在测试配置内使用临时密钥。

## 两端兼容检查

自助注册端共用 `packages/api-client/src/index.ts`，保留后端 `PLATFORM_NOT_ACTIVATED` 及中文原因；新增契约测试证明不会改写为网络错误。

游戏后端 `MemberPlatformClient.businessError()` 读取并透传后端业务 code/message，HTTP 授权失败有明确原因。`RoomConnectionClient.java` 的连接完成回调仅在失败后 `scheduleReconnect()`，不会读取握手失败响应体，因此房间连接状态无法区分“未激活”与其他连接失败。这是已确认的跨仓库提示缺口，不在本次 platform 实施中擅自修改。授权通过后已有重连机制继续尝试连接；实际三端授权后恢复需后续验收。
