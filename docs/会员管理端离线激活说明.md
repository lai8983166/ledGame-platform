# 会员管理端离线激活

## 客户怎么操作

1. 打开会员管理端，首次启动显示激活界面。
2. 点击“复制机器码”，把机器码发给厂家。
3. 收到厂家发来的激活码后，点击“粘贴激活码”（也可使用 Ctrl+V），再点击“激活”。
4. 成功后自动继续数据库备份检查，随后进入登录界面。激活码不是管理员登录密码。

无需联网、无需导入文件。等待厂家回复时可以退出；下次启动仍可继续激活。
提示错误时按界面原因处理：机器不匹配需重新发送本机机器码；格式错误请复制完整内容；签名或公钥异常请联系厂家。不要删除数据库来解决激活问题。

授权永久有效，不因当前日期变化而到期，也不能远程吊销。升级软件、更换端口、导入业务数据库不影响授权。同一 Windows 系统重新安装应用、授权文件丢失时，可重新输入原激活码；重装 Windows 或换电脑可能需要厂家重新签发。旧版升级到带激活功能的版本，也需要首次激活。

## 厂家如何签发

### 推荐：双击 Windows 签发工具

运行 `release/activation-signer/LEDGame-Activation-Signer-0.1.0-x64.exe`。这是单文件便携版，内置运行时，不需要安装 Node.js、Java 或会员管理端，也不需要联网。仅面向支持现有 Electron 运行时的 Windows x64，不是 macOS/Linux 应用。

1. 点击“选择私钥”，选择 `F:/project/ledgame-activation-private.txt`。换电脑时自行携带这份私钥，程序只记住路径，不复制私钥。
2. 粘贴客户提供的完整机器码，点击“生成激活码”。
3. 点击“复制激活码”，发给客户。

私钥丢失或移动后重新选择即可；不要重新生成厂家密钥。机器码改变会清空上次结果，避免误发旧码。取消文件选择不等于签发成功。工具不保存签发历史，激活码需自行发送/保管。

也可使用 `win-unpacked` 目录内的 exe，但必须保留整个目录，不能只拿其中的 exe。zip 是这一完整目录的压缩包。只有外层 `LEDGame-Activation-Signer-…exe` 是单文件便携版。单文件版运行时会自动解压到临时目录，需要磁盘空间和临时目录写入权限。

开发启动：`pnpm dev:activation-signer`。重新打包：`pnpm portable:activation-signer`。运行测试：`pnpm test:activation-signer`。均在 ledGame-platform 仓库根目录执行。打包仅更新 `release/activation-signer`，不重新打包客户三端。

测试目录版时，将 `LEDGAME_SIGNER_EXE` 设置为 win-unpacked 内 exe 的绝对路径，再运行同一测试命令。单文件便携版使用自解压启动壳，须将 `LEDGAME_SIGNER_PORTABLE_EXE` 设置为外层 exe 的绝对路径，然后运行 `pnpm exec playwright test desktop/tests/activation-signer.portable.spec.mjs --workers=1`。这些测试使用临时密钥和隔离用户目录，不读取正式私钥，不给真实客户签发授权。

### 命令行方式（保留）

在项目根目录运行，需要 Node.js。首次正式启用时，由厂家指定仓库外的安全目录生成一对密钥，例如：

```text
node scripts/activation-tool.mjs keygen D:/ManufacturerKeys/ledgame
```

妥善离线备份 `activation-private.pem`，不要交给客户、放入 Git 或放入打包目录。Windows 下还应限制该目录的访问权限。私钥丢失后无法用原密钥签发新码；不要在每次打包时重新生成。

仅将 `activation-public.pem` 复制到 `server/src/main/resources/activation-public.pem`，然后正常打包。应用只内置公钥。缺少正式公钥时，会员管理端打包准备会明确报错，不会自动生成正式密钥。

本项目已按厂家指定生成正式密钥：私钥为 `F:/project/ledgame-activation-private.txt`，对应公钥已放入上述资源目录，仓库外公钥另存于 `F:/project/activation-public.pem`。`.txt` 只是文件扩展名，内容仍是签发工具读取的 PEM 私钥。以后不要重复执行密钥生成命令来替换这对密钥。

签发电脑不绑定机器身份：把 `scripts/activation-tool.mjs` 和这份私钥复制到另一台安装了现代 Node.js（建议 22 或以上版本）的电脑，即可离线签发。工具无第三方依赖，无需安装会员管理端。生成的激活码绑定客户机器码，且只能被内置对应公钥的应用接受。

收到客户机器码后运行（把示例机器码替换为完整机器码）：

```text
node scripts/activation-tool.mjs issue F:/project/ledgame-activation-private.txt LGM1-完整机器码
```

将输出的完整 `LGACT1.…` 文本发给客户即可。机器码来自 Windows 系统身份的摘要，不使用 IP、端口或网卡地址。

## 授权文件与数据库

内部授权文件位于会员管理端用户数据目录下的 `activation/license.json`，不在 SQLite 中，不参与业务数据库备份和导入。客户界面不提供授权文件导入。

激活前后端可以完成必要的进程和数据库基础初始化，但不会运行异盘备份启动检查或开放业务接口。曾中断的数据库导入仍需先做文件恢复，以免 Java 打开不完整数据库；这不是授权或备份同步。

## 自动化测试

- `pnpm test:server`：临时密钥和隔离数据库，覆盖签名、门禁、授权存储以及原有业务回归。
- `pnpm test:activation`：签发工具和发布安全检查。
- `pnpm test:activation:desktop`：真实 Electron 未激活启动、粘贴/错误提示/焦点、退出和端口释放；使用隔离目录。
- `pnpm test:desktop`、`pnpm test:multipoint-concurrency`：桌面运行与并发工具回归。

需要进入业务的桌面和跨端验收必须先取得**当前测试机器的有效厂家授权**，并构建带对应正式公钥的后端。给测试进程设置 `LEDGAME_TEST_LICENSE_PATH` 为该机器已有 `activation/license.json` 的绝对路径；脚本只读原文件并复制到隔离目录，不复制业务数据库、不修改正常授权。该变量仅由测试脚本读取，正式应用没有跳过激活或替换信任公钥的开关。

打包版并发工具在 `config/center.json` 配置 `activationLicensePath`（相对路径按运行时工作目录解析）。中心机器和压力机器不是同一身份：此处需要中心机器的授权。未提供或提供无效授权时测试不能进入业务；离线生成计划仍无需激活。

正式打包版的正确激活、重启保持、备份导入不影响激活以及真实并发验收，需配置正式公钥和有效本机授权后再执行，不能用单元测试通过来代替。
