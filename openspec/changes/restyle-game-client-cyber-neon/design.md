## Context

游戏端使用 Vue 3、JavaScript、Vite 和 Electron，`src/style.css` 提供全局浅色样式，多数页面还有 scoped 样式。`App.vue` 根据窗口类型承载主窗口、Touch、DebugPanel 和副屏，因此全局覆盖容易影响多个窗口。参考项目的设计变量一致，但 Vue 库包含演示业务、占位封面和全局 reset，不适合直接覆盖现有源码。

## Goals / Non-Goals

**Goals:** 使用同一套设计变量实现统一视觉，保持实际控件的可用性、编辑器密度、多窗口布局与离线运行。

**Non-Goals:** 不重构业务状态、不改变导航结构或步骤、不迁移数据库、不替换资源、不重做待机动画，不增加主题切换、在线字体下载或新组件框架。

## Decisions

### 1. 样式适配优先，不整库替换

将参考设计中实际需要的变量整理为游戏端本地 CSS，保持深紫黑背景、青/品红强调、玻璃面板、边框、圆角和字体层级。在现有 DOM 和控件上使用变量及展示类，必要时只调整展示模板。现有 `<script>`、事件、props、v-model、DOM 定位标记和表单语义保持不变。

不选择整库复制：参考 `App.vue` 是演示入口，组件封装的事件/双向绑定可能与现有控件不同，且项目无需为此次样式改造迁移到 TypeScript。只有确有重复的纯展示样式才抽取公共样式，不建立额外主题管理层。

### 2. 按窗口和内容边界隔离

样式覆盖限定到明确的窗口根节点或面板，不复制参考库的全局 margin reset、固定全屏氛围层或宽泛的 `button/img/canvas` 覆盖。

| 区域 | 修改方式 | 必须保留 |
| --- | --- | --- |
| 主窗口、分类/游戏卡片 | 深色背景、霓虹导航、卡片框架、文字及悬停态 | 现有分类、排序、名称、品牌图标和实际封面 |
| 媒体/精灵/配置/帮助/SDK | 面板、工具栏、表单、列表与弹窗样式 | 搜索、防抖、权限、校验、资源路径及调用链 |
| Simple/Normal/Diffcult、Rank 编辑器 | 控件、选中态、侧栏、工具区和表单样式 | 四色画笔含义、精灵像素、坐标、正方形矩阵、选中和拖拽逻辑 |
| Touch、DebugPanel、副屏 | 非待机状态的外壳、信息面板、按钮及文字层级 | 待机组件/动画、倒计时、刷卡/触屏流程、背景资源、实时分数和矩阵内容 |

待机区域及其标题/文字动画不参与换肤。RGB、布线、精灵和媒体预览的像素、颜色、内容及宽高比不变；不使用全局滤镜、混合模式或主题色改变它们。副屏已配置背景的展示方式保持不变，面板只调整外观且确保内容可读。

### 3. 保留功能入口与交互状态

参考项目的导航项、浮动按钮和卡片布局仅作视觉参考，不新增参考项目里的功能或重新编排现有业务。保留当前菜单、图标按钮、快捷操作和对象/精灵区域切换。

为 hover、selected、focus-visible、disabled、loading 和 error 统一样式，但不靠尺寸、边框宽度变化导致布局跳动。危险按钮保留清楚的警示色，输入错误继续显示原校验文本。装饰层使用 `pointer-events: none`，不改变弹窗焦点恢复和点击热区。复杂编辑器优先保持密度，不强制套用示例卡片最小宽度。

### 4. 离线与性能

字体优先使用可离线取得的本地字体，缺少参考字体时使用系统中文/拉丁字体回退；不通过 CDN 加载。保留已有图片和动画原文件，不加入占位封面或改变品牌标题。有限使用 hover 光晕/transform；玻璃模糊不叠加到高频矩阵和实时分数区域。新装饰动画支持 reduced-motion，不修改现有待机动画行为。

### 5. 验收以样式和行为双轨进行

先记录现有页面/窗口关键状态，再修改样式。通过现有 Node 测试与生产构建验证回归；补充样式隔离、交互状态和资源保护的可自动化检查。真实视觉结果使用本地截图检查，不以“源代码包含某个颜色”替代视觉验收。

检查主窗口、四种玩法编辑器、弹窗、SDK 配置、Touch、DebugPanel 和副屏在 1280×720、1920×1080，以及当前支持的高 DPI 条件下的主要布局。尤其核对矩阵正方形、底行可见、工具模式切换无抖动、输入框可聚焦、弹窗不被遮挡和自定义背景可见。

## Risks / Trade-offs

- 全局及 scoped 样式混用导致局部浅色残留 → 按页面清单逐项适配，检查 select、弹窗和错误状态，不堆叠无范围的 `!important`。
- 全屏氛围层影响动画、媒体或点击 → 装饰限定在外壳，排除待机/矩阵/媒体区域，禁用装饰层指针事件。
- 控件换肤引发输入焦点或模式切换布局回归 → 保持原控件与事件，固定控件几何尺寸，复跑已有焦点和编辑器回归测试。
- 重复玻璃模糊和阴影影响实时窗口 → 实时区域采用低开销表面样式；不在帧/得分更新链路新增动画、定时器或计算。

## Migration Plan

先完成公共变量和主窗口，再逐页覆盖编辑器、弹窗及运行窗口，最后视觉/功能验证并重新打包游戏端 `win-unpacked` 和 ZIP。无需数据迁移，数据库和资源不变；回滚仅回退本 Change 的展示层改动，不回滚用户数据或其他功能修改。
