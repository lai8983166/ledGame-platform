# Proposal

## Why

会议明确要求礼品兑换只减少可用积分，不降低排名积分。目前只有游戏累计积分，缺少安全的扣减及追溯入口。

## What Changes

- 明确剩余积分与排名积分：排名积分仍来自已结算游戏，剩余积分为累计所得减去已扣减积分。
- 会员列表/详情分别展示两者，增加积分扣减弹窗及记录查询；正整数、必填原因、不能超扣，记录操作员和前后余额。
- 原积分字段保留累计排名含义，排行榜、副屏、游戏内得分与结算算法不变；自助端只读展示两种积分，会员 CSV 同步增加剩余积分。
- 事务和请求号保证并发/重试不重复扣减，补故障回滚及旧数据兼容测试；扣减不影响时长账户或收款。
- 不做礼品库存、积分人工增加/冲正、等级或新的通用钱包框架。

## Capabilities

### New Capabilities
- `member-points-redemption`: 剩余积分、可追溯人工扣减及会员记录查询。

### Modified Capabilities
- `player-info-query`: 查询响应和自助端明确展示剩余与排名积分，旧 total 字段保持原义。

## Impact

仅 platform 仓库后端、会员管理端、自助注册端、共享 API 类型、会员导出和测试。新增扣减记录表并纳入既有备份，旧游戏记录不重算。重打会员管理端及自助端原位置 win-unpacked/ZIP，不改日常数据库，不自动提交 Git。
