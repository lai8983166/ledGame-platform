# Design

## Context

参见 proposal.md。当前游戏端以 Vue 3 渲染多个 Electron 窗口；八个业务确认调用共用同步原生确认封装。公共恢复函数在主进程 IPC 返回后再次对当前活动元素失焦。普通编辑器模态检查仅位于 Alt+A/D 分支。文件选择已经绑定正确 owner，但返回时仍可能主动激活已离开的窗口。已完成浏览器复现：效果弹窗存在时 D 可切背后帧，Delete 可将背后选中对象数从1变0；组合输入标志下 Escape 仍取消精灵编辑。

规划在平台仓库，实际实现位于用户明确指定的相邻游戏端及必要的配套后端授权存储模块，沿用已有客户反馈 change 的组织方式。CLI 的 repo-local 路径用于规划产物；跨仓库实现依据本次明确授权。

## Goals / Non-Goals

**Goals:** 确认、模态键盘和窗口焦点以当前交互所有权为边界；延迟回调不能操作新页面或新输入；名称表单可持续进行中英文录入。保留取消不修改、确认一次修改和撤销历史粒度。

**Non-Goals:** 不升级 Electron 大版本，不改变游戏数据结构、授权保护、删除权限、输入法本身或硬件协议；不将单纯初始聚焦容器当作所有输入故障的根因。

## Decisions

1. 使用可随所属组件作用域释放的异步确认控制器与共用页面内确认组件。关闭、取消及卸载都结算为 false，重复触发不能叠加危险操作；取消按钮默认聚焦，Tab 留在顶层确认中，按键停止向底层传播。保留现有本地化消息，避免新建各页面独立的确认机制。排除继续依赖原生 confirm 加延时 focus 的方案，因为它保留了已复现的 Windows 焦点边界。
2. 所有确认调用迁移为 await，并在确认之后核对文档、关卡、帧或运行会话身份；改变目标、离开页面或取消后不得执行旧请求。特效确认期间保留草稿，确认只提交一个原有历史事务。
3. 普通编辑器全局快捷键入口统一检查可见模态及编辑状态，再进入各快捷键分支；文本、可编辑控件和组合输入继续让行。弹窗内自身的键盘行为由弹窗处理，不利用禁用全部键盘掩盖错误。
4. 共用组合输入判断，覆盖 isComposing 及兼容 keyCode 229；精灵、分类、媒体新文件夹和其他生产可达输入弹窗的 Escape 在组合输入时不关闭草稿。精灵名称以明确 input ref 聚焦，去掉容器与 autofocus 的竞争。
5. 公共 renderer 恢复不再无条件 blur 当前元素，不用迟到的 IPC 重新激活窗口。原生文件对话框关闭只在 owner 仍可见、未最小化且仍为当前窗口时恢复页面焦点；显式用户打开窗口保留激活能力。Touch 首次显式打开可激活，后续 ready/load 回调尊重用户已经转移的焦点，防止二次抢回。
6. 验证同时使用有意义的单测、真实 Vue 渲染键盘用例和 Windows Electron 输入事件；真实输入法兼容性与模拟组合事件结果分开记录。发行包继续启用已有五个 fuse 和 EXE/ASAR/JAR 校验链。

## Risks / Trade-offs

- [同步改异步产生旧目标写入] → 在确认后重新验证目标身份，作用域释放自动取消，并测试确认待决期间切换文档。
- [新确认与已有效果等弹窗堆叠] → 顶层确认消耗键盘事件，底层编辑快捷键统一禁止，按 Escape 只关闭最上层。
- [过度限制焦点破坏用户主动打开 Touch] → 显式打开与加载完成回调区分，分别测试应激活与不应抢回。
- [自动化填值掩盖真实焦点故障] → 以 click/键盘输入验证名称录入与删除后立即新增，不以 fill 或直接赋值证明 Windows 输入正常。
- [现有测试固定了两次 blur 等错误实现] → 改为验证可观察行为，同时保留取消、历史、导入导出及授权回归。

## Migration Plan

输入修复无需数据结构迁移。便携数据追加需求按下节处理目录迁移；执行全量前端测试、构建、隔离数据验收及目录/ZIP打包。change 保持活跃，完成任务及验收后提交并 push 相关仓库，不自动归档。

## 11月17日追加：便携包数据隔离

正式包在请求单实例锁、初始化设置及启动后端之前，将用户数据目录设为 `dirname(exe)/data`，Chromium 会话目录同步置于该根下。开发模式保留既有目录；显式 `LED_USER_DATA_DIR` 保留供隔离验收。现有数据库、备份、语言、配置、branding、日志和授权路径均由 userData 派生，因此随当前包隔离，机器授权仍独立验签且不进入数据库。使用 EXE 目录而非 cwd，避免快捷方式和命令行启动改变数据归属。不可写时显示明确原因并退出，不退回共享目录。

三类配置资源沿用经过格式、大小校验的复制安装流程，目标为 `data/branding`。设置持久化使用 `branding/<文件名>` 相对路径，向窗口和资源协议返回当前根下的绝对路径。旧配置的受管 branding 绝对路径只重定位到当前包对应文件，不能继续读取原包；新提交的越界路径拒绝。预览与保存仍分离，选择成功不自动保存其它表单草稿。

首次新包由随包种子初始化数据库，使用默认配置；不自动读取或改写旧 `%APPDATA%/led-game`。已有数据先关闭旧、新客户端和所属后端，再备份并将旧 database/settings/branding/activation 复制到目标包 `data`，只向未初始化的新目标迁移，不混合覆盖两个数据库。升级保留完整 `data`、`resources/media` 及 `elc408`；回退版本使用迁移前副本。发布 ZIP 不包含验收运行数据或开发机配置、授权。

主要风险是移动后仍引用原包、两副本共享锁/库、迁移运行中 H2 文件、输出混入验收数据。通过双副本不同配置/数据库标记及重启、不同 cwd、相对路径资源实读、停机迁移说明、ZIP 目录检查和原有保护 smoke 验证。两包可各自启动并使用不同后端端口；生产硬件连接仍按原设备规则，验收关闭硬件自动连接。

## 后续明确：重打包保留与本机授权

本节更新上节首次方案：授权不再随 userData 隔离；默认重新打包可携带原发行目录真实持久数据。旧节点验收记录作为历史保留，以最新需求为准。

打包入口先确认目标包和 Java 后端未运行，再将旧 `data`、媒体及控制器目录快照到独立 `.build` 目录，保留可追踪恢复记录。使用独立暂存输出构建，持久 `data/database`、`data/settings`、`data/branding` 通过打包配置进入新包，媒体和控制器来自旧目录完整快照（包括空目录），没有旧来源时沿用开发种子及默认来源。ZIP 排除授权、日志与会话缓存；原目录这些非分发文件保留。发布前复核进程及快照内容，防止构建期间用户重新启动或修改后被旧快照覆盖。保留原数据、暂存产物和失败信息，不再将 builder 输出直接指向有运行数据的目录。

正常启动使用 `app.getPath('appData')/led-game/activation` 固定授权根，不依赖 EXE 路径、cwd 或后置 app.setName。当前用户多个包共用签名授权，每次进程启动仍校验同一真实机器身份。显式 `LED_USER_DATA_DIR` 保留隔离语义，授权仅在指定隔离根，不触碰正式授权。后端通过受控环境值获得旧候选目录，依次核验包内旧授权及历史默认目录，只有可信、本机、同产品授权才原子保存到固定目录；有效固定授权优先。迁移保存失败不报已激活，原旧文件保留。这里共享的是本机授权，游戏库与配置仍各包独立。

验证包含临时密钥依赖隔离的后端迁移/异机/损坏/保存失败测试，以及使用现有本机真实有效授权的发行包验收。真实授权只留在本机固定目录和原有恢复备份，不写入 Git、ZIP 或测试输出。重打包前后对真实发行持久数据生成摘要核对，并再次执行完整性保护验收。

## 游戏首页重复导航

分类详情是 GameListView 内部的 selectedCategory，父页面 section 仍为 home，重复设置相同 prop 不会触发旧监听；KeepAlive 进一步保留了该选择。增加顶层显式导航请求序号，成功通过既有编辑离开保护后更新，GameListView 同时监听 section 和请求序号，清除分类、分类选择器和拖动状态。分类卡片点击只更新内部分类，不再重复向父级发送首页导航。正常编辑返回不发新请求，因此保留分类上下文；取消离开不更新序号。

通过真实 App 组件菜单点击复现和回归：分类→游戏/首页、重复进入不同分类、仅展开/关闭菜单、切换其它Tab返回首页及普通返回保留上下文。使用内存 API，不写客户数据库。

## 游戏布线的控制器通道数

普通和排行编辑器共用布线面板，随该游戏的 `wiringData` 保存可选数字 `controlChannel`。导入或导出保留该字段、线路顺序和空端口。运行时缺省值使用当前包配置。编辑器预选相应路数，保存时写入具体数值。

运行时从包内配置加载网卡、监听端口和线序，按当前游戏的显式通道数选择 HC01、HC02、HC04 或 HC08。搜索、发帧和踩踏映射都使用相同的型号和布线快照。调试入口按选中游戏搜索，在游戏结束或启动失败后按既有生命周期恢复包内配置。用旧版协议格式校验 1/2 路，并用隔离的发行包验证编辑保存和数据保留。
