# Design

## Context

现有 charge/bind 已支持未绑定卡，但 charge 自动按分钟记收入，bind 将待领取额度直接并入可分配余额而未生成会员入账记录。会员管理端的旧手环页已隐藏。参见 proposal.md。

## Goals / Non-Goals

复用手环、原充值记录、会员充值记录及当前 SQLite 事务和操作员权限；不增加权益账户框架、后台批量作业、次数消费或 TXT 文件入口。

## Decisions

- 原 wristband_charge_records 新增预置状态、请求号、修改版本；member_recharge_records 增加唯一来源记录 ID，不新建表。旧记录保留，老 charge 接口仍可激活。
- 新预充值 API 创建时金额为 0 的内部占位且明确不属于销售；查询和业务导出不将未领取/取消额度作为充值交易。领取时创建一条有来源 ID 的会员充值记录，再从账户全额分配本次时间，同一事务内完成；旧收费记录转为会员入账时保持原金额和日期，避免历史收入改变或重复。
- 新建请求号幂等；待领取修改/取消携带版本；柜台发卡识别预置卡后固定本次分钟数，携带来源和版本防止确认旧额度。已领取不可修改或取消。自助 bind 不改变请求格式。
- 独立精简页面默认待激活，先设置分钟数再连续刷卡，逐卡反馈且失败后可继续。数字+Enter 仅在等待刷卡时捕获，接口提交期间禁止关闭；失败重试保留请求身份。取消预置使用 DOM 确认弹窗，不卡住输入焦点。
- 新接口采用已有 WRISTBAND_MANAGE，取消采用已有清余额权限（当前三角色均具备）；不扩展业务导出权限。修改、取消及准备记录具体操作员。

## Risks / Trade-offs

- 重试/并发重复领取 → SQLite 写事务、唯一来源 ID、卡及会员占用校验，事务失败全部回滚。
- 卡重复发放后误取消 → 按预充值记录 ID 和版本校验，不能只按卡号清除。
- 预置误记收入/重复展示 → 未领取不作为交易，领取后由会员入账记录唯一展示；旧金额迁接保持收入总额。
- 老卡缺少操作员快照 → 保留历史未知标记，不伪造真实操作员。

## Migration Plan

schema 8 只增列和索引，不重写既有会员余额或绑定。隔离库验证迁移可重复执行及原数据保留；正式库只在应用启动时正常升级。回退须使用升级前备份。交付不修改本机人工库。
