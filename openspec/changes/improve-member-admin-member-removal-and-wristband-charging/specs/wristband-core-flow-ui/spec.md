## MODIFIED Requirements

### Requirement: 管理端手环工作台采用紧凑响应式布局
会员管理端 SHALL 使用响应式 Grid 组织手环状态流程、充值、清除余额、绑定说明和回收操作，使常用操作在桌面宽度下并排展示，在窄屏下自动回落为单列，并保持手环真实状态列表为独立的全宽区域。

#### Scenario: 桌面宽度查看手环管理
- **WHEN** 店员在常规桌面窗口打开手环管理页
- **THEN** 系统以紧凑 Grid 展示操作卡片，充值入口与其他操作无需纵向经过多个大块卡片才能访问
- **AND** 手环状态列表保持完整宽度并继续展示真实后端数据

#### Scenario: 窄屏查看手环管理
- **WHEN** 可用宽度不足以并排展示操作卡片
- **THEN** Grid 自动折叠为单列，且所有按钮、提示和弹层入口仍可访问

### Requirement: 管理端手环充时
会员管理端 SHALL 通过显式按钮启动手环充时会话，先在等待提示中捕获键盘式读卡器输入的数字 UID 和回车；确认该 UID 可以充时后，系统 SHALL 展示分钟数输入框、快捷分钟选项、确认充时和取消操作，并且只有确认充时才写入数据库。

#### Scenario: 开始等待刷手环
- **WHEN** 店员点击“手环充值”按钮
- **THEN** 系统弹出“请刷手环”提示并进入等待状态
- **AND** 页面在进入等待前不展示可编辑的手环 UID 输入框

#### Scenario: 读卡器完成有效扫描
- **WHEN** 等待状态收到有效数字 UID 和回车，且该 UID 是未知新手环或状态为 `IN_STOCK`
- **THEN** 系统结束刷环等待并展示扫描到的 UID
- **AND** 系统展示购买分钟数输入框以及 30、45、60、90、120 分钟快捷选项
- **AND** 此时数据库中尚未创建或充时该手环

#### Scenario: 覆盖仍在使用的手环
- **WHEN** 等待状态扫描到 `CHARGED`、`READY`、`ACTIVE` 或 `EXPIRED` 手环
- **THEN** 系统停留在可重试的刷环提示中并说明当前状态不能重复充时
- **AND** 系统不改变手环状态或分钟数

#### Scenario: 给待充时手环充时
- **WHEN** 店员在成功扫描后输入 1 到 1440 的整数分钟数并点击确认充时
- **THEN** 系统把该手环变为 `CHARGED`
- **AND** 系统展示“已充时待激活”和本次分钟数，并刷新后端手环列表

#### Scenario: 取消刷环等待
- **WHEN** 店员在“请刷手环”阶段点击取消
- **THEN** 系统关闭提示并清理本次 UID 缓冲
- **AND** 系统不创建手环且不写入任何分钟数

#### Scenario: 取消分钟输入
- **WHEN** 店员成功扫描手环后在分钟输入阶段点击取消
- **THEN** 系统关闭充时弹层并清理已扫描 UID 和未提交分钟数
- **AND** 手环数据库状态保持不变

#### Scenario: 充值请求失败
- **WHEN** 店员确认充时但服务端拒绝请求或本机服务不可用
- **THEN** 系统保留当前 UID 和分钟数并展示可重试错误
- **AND** 系统不得把失败请求显示为充值成功
