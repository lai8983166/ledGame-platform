## Context

当前 `ledGame` 的 `simple / normal / diffcult` 共用 `SimpleGameEditorView`，后端 `GameEditorDocument.CommonConfig` 已包含 `PixelLightWiring`，并通过 `/game-editor/{id}` 完成完整编辑文档的读取和保存。旧实现使用不同的 `/game/{id}` 模型，并把 `commonConfig` 当作 JSON 字符串处理，不能直接迁移。当前布局配置还没有接入实际运行时灯光输出，因此本设计只处理编辑、预览和持久化。

## Goals / Non-Goals

**Goals:**

- 在一个共享编辑器中为三种默认玩法提供独立布局弹窗。
- 以本地草稿方式完成布局编辑和预览。
- 复用现有编辑器保存链路，避免覆盖未保存的矩阵/关卡内容。
- 对 0/1 基础值转换、端口冲突、对齐坐标和墙面行重建进行稳定校验。
- 保持旧游戏配置可读、可保存，并让布局关闭成为运行时无副作用的兼容设置。

**Non-Goals:**

- 本 Change 不修改游戏运行时报文，不驱动符号灯或圆灯硬件。
- 不新增数据库表、独立布局接口或 Electron IPC。
- 不改变现有地砖矩阵编辑、关卡编辑、游戏启动和结算逻辑。

## Decisions

### 使用独立布局弹窗和纯状态模块

新增独立的布局弹窗组件，并将归一化、行重建、校验和预览几何计算放入纯函数模块。这样可以避免继续膨胀已有全局配置弹窗，也便于单元测试。

备选方案是把布局字段直接追加到现有全局配置弹窗中，但会混合不同保存语义和大量 UI 状态，增加回归风险，因此不采用。

### 复用现有编辑器文档保存 helper

布局保存使用现有的编辑器文档读取、合并和保存流程，只提交：

```js
{ commonConfig: { pixelLightWiring: normalizedDraft } }
```

该方式不会让布局弹窗重新提交当前内存中的完整矩阵，从而保护未保存的编辑内容。保存成功后再把同一 patch 合并回当前文档状态。

备选方案是新增 `/pixel-light-layout` 接口或直接在前端手动拼接 JSON 字符串；前者会重复现有文档接口，后者容易破坏 `commonConfig` 其他字段，均不采用。

### 关闭只改变 open，不清理布局

关闭布局时保留墙面数量、行、起点和对齐信息，只将 `open` 改为关闭值。重新启用时可以恢复上次配置，也避免旧实现清空数据导致不可逆丢失。

### 使用稳定行身份重建 rows

墙面行以 `wall|idx` 作为身份。墙面数量变化只新增或删除受影响的行，并保留仍存在行的 `align`。预览和保存都使用归一化后的行集合，避免数组下标变化造成错配。

### 前端先校验，后端保持兼容

第一阶段在前端完成用户即时反馈和严格校验；后端继续使用已有宽松 DTO 以兼容历史配置。若后续增加后端校验，应只在布局字段存在且启用时检查端口冲突、范围和坐标格式，不能因为旧配置缺少字段而拒绝整个游戏文档。

## Risks / Trade-offs

- [布局配置已保存但运行时暂不生效] → 在界面文案和 Change 范围中明确“本 Change 只保存布局”；实际硬件驱动放到独立运行时 Change。
- [立即保存与外层保存并存] → 复用现有 helper，并在保存后同步当前文档的 `commonConfig`，避免后续外层保存回写旧布局。
- [历史配置默认值不一致] → 只对缺失字段补默认值，不覆盖已有显式值；关闭布局也不清理历史数据。
- [多控制器数量变化] → 控制器选项从现有 wiring 配置派生，不在布局弹窗中硬编码为两个。
- [行数量大导致预览重绘成本上升] → 预览只在草稿变化或点击绘制时更新，并限制单面数量为非负整数。
