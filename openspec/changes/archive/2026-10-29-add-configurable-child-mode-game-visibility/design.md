## Context

现有儿童模式总开关已经由会员管理端持久化，并通过已有房间长连接同步到游戏端；游戏端目前用固定内部名称 `simple-demo` 过滤和拦截。此次只替换游戏级判定方式，保留已有总开关、连接和重连机制。

## Goals / Non-Goals

**Goals:**

- 在现有游戏配置模型中增加可持久化的儿童模式可见性字段。
- 让游戏编辑界面、游戏目录过滤和启动校验使用同一份配置。
- 保证旧游戏配置缺少字段时默认可见。
- 复用现有会员管理端儿童模式同步协议，不引入第二套开关或新的长连接。

**Non-Goals:**

- 本次不设计年龄分级、用户角色分级或多级内容审核。
- 本次不改变会员管理端儿童模式总开关的权限、存储和同步方式。
- 本次不删除或迁移现有游戏名称字段。

## Decisions

### 1. 使用游戏配置字段而不是名称黑名单

在现有游戏元数据/配置中增加布尔字段 `childModeVisible`，默认值为 `true`。游戏端编辑器负责读写，后端目录和启动校验读取同一字段。选择字段而不是名称黑名单，是为了支持改名并允许未来扩展更多游戏；保留名称黑名单会继续产生改名绕过问题。

### 2. 保持旧配置向后兼容

读取配置时缺少 `childModeVisible` 按 `true` 处理，保存时才写入显式值。这样已有门店游戏不会因为升级而突然消失，也不需要一次性迁移全部配置文件。

### 3. 过滤和启动使用同一判定函数

游戏目录生成和启动入口共享“儿童模式是否允许该游戏”的判定，避免只隐藏前端列表但仍可通过接口启动。儿童模式关闭时跳过游戏级限制，保留原有启动校验。

### 4. 复用现有跨端同步

会员管理端继续只发送全局 `childMode` 状态；游戏端收到状态变化后重新计算可见列表。游戏级字段随游戏配置/目录数据传递，不在会员管理端重复维护一份。

### 5. 测试覆盖三端契约与兼容性

增加配置默认值、保存读取、跨端状态切换、列表过滤、直接启动拒绝和旧配置兼容测试；保留现有儿童模式总开关测试，确保协议改动不会影响重连和离线默认行为。

## Risks / Trade-offs

- [旧配置字段缺失] → 读取时默认可见，并覆盖旧配置测试。
- [编辑器与后端使用不同字段名] → 在共享契约/目录测试中固定字段名称和序列化形状。
- [列表已加载时状态变化] → 收到儿童模式变更后重新生成列表，并清理当前未启动的不可见选择。
- [部分旧游戏运行中切换为不可见] → 只阻止新的游戏启动，不中断已经运行的游戏。

## Migration Plan

1. 先发布支持缺省字段读取的游戏端和后端。
2. 再启用游戏编辑器开关，用户保存后逐步写入显式字段。
3. 出现问题时可暂时关闭会员管理端儿童模式总开关；旧配置仍按可见处理，不需要回滚数据文件。
